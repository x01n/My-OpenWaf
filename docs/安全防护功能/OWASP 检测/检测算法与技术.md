## 简介
本文件系统性梳理 OWASP 检测算法与技术在代码库中的实现，重点覆盖：
- 字符串归一化处理（URL 解码、HTML 实体解码、JavaScript 转义序列解码、UTF-7 解码、SQL 注释剥离、空白折叠）
- 正则表达式匹配策略与恶意模式识别
- 多层检测架构（快速路径过滤、深度解码扫描、上下文感知分析）
- 检测精度优化（误报抑制、上下文分析、阈值控制）
- 性能优化（目标长度限制、内存管理、正则缓存）
- 检测结果评分与威胁等级评估

- OWASP 检测入口：`CheckOWASP` / `CheckOWASPWithThresholdsAndMode` / `FirstAcceptedOWASPHitWithThresholdsAndMode`，包含归一化、快速路径过滤、深度解码扫描、协议级检查与路径危险模式识别。

## 架构总览
WAF 引擎按阶段顺序装配：`ip_reputation` → `anti_replay` → `acl` → Lua 前置策略 → `owasp_default` → `cve_detection` → `bot_detection` → `browser_sign` → `rate_limit` → `signature` → `custom`。缺少对应管理器或关闭配置时跳过相关阶段。每个阶段返回动作结果，`drop` 严重度最高（90）优先短路，终止动作终止链，`observe`（10）只收集日志；质询类动作（60）在链尾按严重度竞争。

## 详细组件分析

### 字符串归一化与预处理
`normalizeTarget(s, queryPlusAsSpace)` 按固定顺序执行 17 个可跳过的前置判定，顺序本身就是正确性的一部分：UTF-7 必须在 URL 解码之前解一次，否则 `+ADw-` 里的 `+` 会先被当成空格破坏掉。

| 序 | 阶段 | 条件门 | 关键符号 |
|:--:|------|--------|----------|
| 1 | UTF-7 预解码 | 含 `+A` 且解码产物含 `<>"&;!/[]` 之一 | `decodeUTF7Sequences` |
| 2 | U+2215 归一 | 含 `∕` | 直接替换为 `/` |
| 3 | overlong UTF-8 还原 | 含 `%` 且 `containsOverlongUTF8Escape` | `reOverlongLT`/`reOverlongGT` 等 |
| 4 | 多轮 URL 解码 | 最多 3 轮，首轮 `unescapeURLComponent`，后续 `url.PathUnescape` | `unescapeURLComponent` |
| 5 | 解码产物二次 overlong | 同第 3 步条件 | `reOverlongDotCompact` 等 |
| 6 | HTML 实体解码 | `shouldDecodeHTMLEntities` 为真，最多 2 轮 | `html.UnescapeString` |
| 7 | JS 转义解码 | 含 `\` | `decodeJSEscapesPooled` |
| 8 | JS 转义后再 URL 解码 | 含 `%`，最多 3 轮 | `url.PathUnescape` |
| 9 | UTF-7 二次解码 | 含 `+A` | `decodeUTF7Sequences` |
| 10 | URL scheme 控制字符归一 | 无条件 | `normalizeURLSchemeControls` |
| 11 | ASCII 小写化 | 无条件 | `toLowerASCII` |
| 12 | `%uXXXX` 解码 | 含 `%u` | `decodePercentU` |
| 13 | 零字节剥离 | 无条件（剥离而非替换，还原 `<scr\x00ipt>`） | `strings.ReplaceAll` |
| 14 | 内嵌混淆标签剥离 | 成对短标签 `<x>`/`</x>` | `stripInlineConfusionTags` |
| 15 | SQL/C 风格注释剥离 | 无条件，空串替换使 `sel/**/ect` → `select` | `stripSQLCommentsPooled` |
| 16 | 空白折叠 | 无条件 | `collapseWhitespacePooled` |
| 17 | 长度截断（调用侧） | `len > maxTargetLen(16384)` 时保留首尾各一份 | `truncateTarget` |

### 快速路径过滤与指示器门
干净目标与可疑内容判定先于归一化，脏目标才进入归一化与正则电池：

| 判定 | 允许字符集 | 长度上限 | 额外排除 |
|------|------------|:--:|----------|
| `isCleanTarget` | 字母、数字、`-`、`_`、`.`、空格、`,`、`@` | 256 | 命中 Base64 候选或攻击关键词时不走干净短路 |
| `isCleanPathTarget` | 字母、数字、`/`、`-`、`_`、`.` | 256 | 含可疑 Base64 路径段或明文攻击关键词 |
| `isCleanPlainQueryTarget` | 字母数字与查询安全字符 | 512 | 必须含 `=` |
| `hasSuspiciousContent` | O(n) 扫描可疑字符集 | — | 未命中即跳过正则电池 |

### OWASP 阶段与体目标提取
OWASP 阶段先扫描 multipart 文件名与内容类型（文件上传检查），再按 Content-Type 抽取文本目标送检；抽取结果缓存在 `RequestCtx.BodyTargets`，供 CVE 阶段复用。

| Content-Type | 抽取函数 | 采样上限 | 说明 |
|--------------|----------|:--:|----------|
| `application/x-www-form-urlencoded` | `extractFormValues` | 全量体 | 解析键值并解码，键名与值都扫描 |
| `application/json` | `extractJSONValues` → `walkJSON` | 深度 ≤10、值 ≤100 | 超限按稳定排序保留靠前键，保证归因可复现 |
| `multipart/form-data` | `extractMultipartFieldValues` | 最多 20 段、每段 4096 字节 | 文件段扫内容开头，非文件段扫值 + 字段名 + 原始 `name=` |
| `text/*`、`application/xml`、`application/soap` | 直接取体 | 8192 字节 | 截断后单目标扫描 |
| 其他非空类型 | 可打印比例采样 | `WAFBodyScanLimit` = 48 KB | 首 512 字节可打印 ASCII 比例 ≥90% 且 `shouldScanOpaqueBodyTarget` 为真才扫描 |
| Content-Type 缺失 | 直接取体 | 48 KB | 无声明时按原文扫描 |

Content-Type 伪装防护独立于上述分支：声明类型不是 `application/json` 但 `looksLikeJSON` 为真时，额外执行一次 `extractJSONValues` 并并入目标集；声明类型解析不出任何值且未被判定为不可扫描时，回退再扫一遍原始请求体，使 Base64 包裹的载荷仍有机会被 `normalizeWithDecode` 剥层。

### 语义视图与派生缓存
检测所需的解析视图都做成按请求惰性缓存，避免同一请求内多阶段重复解析：

| 缓存 | 载体字段 | 触发者 | 失效时机 |
|------|----------|--------|----------|
| 请求体目标 | `RequestCtx.BodyTargets` / `BodyTargetsDone` | `owaspPhase` 首次抽取 | `ResetMutationCaches` |
| JSON 对象 | `matcherJSONBody` / `matcherJSONBodyDone` | `bodyJSONPath` 类规则 | `ReleaseCtx` |
| 查询值 | `matcherQueryValues` | `queryParam` 类规则 | `ReleaseCtx` |
| 派生请求头 | `matcherHeaders` | 需要 Host/TLS/头顺序别名的匹配器 | `ReleaseCtx` |
| 派生指纹串 | `derivedALPN` / `derivedHeaderOrder` / `derivedCipherSuites` | Bot 与 TLS 匹配器 | `ReleaseCtx` |

归一化侧同样使用对象池：`getNormBuf` / `putNormBuf` 复用缓冲区，`maxNormBufCap` 为 64 KB，防止偶发超大目标把池中对象永久抬到数十万字节导致峰值后 RSS 不回落；`collapseWhitespacePooled`、`stripSQLCommentsPooled`、`decodeJSEscapesPooled` 均基于该池实现。

## 性能考虑
- 目标长度限制：`maxTargetLen` = 16384，超长目标保留首尾各一份，避免正则爆炸；片段目标上限 `MaxTargetLen` = 2×16384+1 与检测层对齐。
- 快速路径：`isCleanTarget`、`hasSuspiciousContent`、`hasACIndicator`、`owaspPatternGatePass` 四级过滤在进入每条正则前生效。
- 自动机摊平：转移表一维化 + 终态位内联，使 `MatchAny` 内层循环每次转移一次内存读。
- 正则缓存：`regexCache` + `cachedCompile` 复用编译结果；内置正则在包初始化时一次性编译。
- 缓冲区池化：归一化缓冲区上限 64 KB，避免峰值后 RSS 不回落；累加器同样池化复用。
- 深度扫描门限：仅当长度 ≥30 且 `shouldScanUnicodeBase64Target` 为真时才排队深扫，绝大多数请求不进这条路径。
- 采样代替扫描：未声明或异常 Content-Type 的请求体只采样首 512 字节判断可打印比例。

## 结论
该检测体系通过「干净目标短路 + 17 步归一化 + AC 族门 + 单条规则门 + 正则电池 + 类别抑制 + 累加跨阈归因 + 覆盖过滤」的组合，覆盖 18 个类别 553 条内置规则，同时把热路径成本压到「多数请求只做字符扫描」的水平。两阶段 Bot 检测与敏感端点兜底进一步补齐了无载荷探测这一盲区。
