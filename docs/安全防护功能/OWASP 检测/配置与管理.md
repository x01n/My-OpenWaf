## 简介
本文件面向 OWASP 检测配置与管理，系统性梳理配置项、规则管理、动态重载、检测结果存储与日志、告警触发、监控指标与性能统计、最佳实践与常见问题。读者可据此完成从“敏感度与阈值”到“规则启停与自定义”的全链路配置与运维。

## 详细组件分析

### 配置系统与动态重载
配置来源全部为环境变量，未设置时取代码内默认值；`Validate` 返回「致命错误 + 非致命告警」两级结果，致命错误直接终止启动。

| 环境变量 | 字段 | 默认值 | 校验口径 |
|----------|------|--------|----------|
| `MY_OPENWAF_DB_DRIVER` | `DBDriver` | `sqlite` | 接受空值、`sqlite`、`mysql`、`postgres`、`postgresql` |
| `MY_OPENWAF_DSN` / `MY_OPENWAF_DB` | `DBDSN` | `{数据目录}/waf.db` | 非空，否则致命 |
| `MY_OPENWAF_DATA` | 数据目录 | `./data` | 用于推导两个默认 DSN |
| `MY_OPENWAF_LOG_DSN` / `MY_OPENWAF_LOG_DB` | 日志 DSN | `{数据目录}/waf_logs.db` | 日志库独立文件 |
| `MY_OPENWAF_ADMIN_BIND` | `AdminBind` | `:9443` | 必须可 `SplitHostPort`；取 `:80`/`:443` 时告警 |
| `MY_OPENWAF_REDIS_ADDR` | `RedisAddr` | 空（不启用） | 非空时必须为合法 `host:port` |
| `MY_OPENWAF_REDIS_DB` | `RedisDB` | 0 | 忽略解析错误 |
| `MY_OPENWAF_GEOIP_DB` | Bot GeoIP 路径 | 默认配置 | 非空才覆盖 |
| `MY_OPENWAF_BOT_THRESHOLD` | Bot 深评阈值 | 默认配置 | 仅接受正整数 |
| `MY_OPENWAF_DROP_BOT_THRESHOLD` | Drop 恶意阈值 | 默认配置 | 仅接受正整数 |
| `MY_OPENWAF_DROP_ENABLED` | Drop 开关 | 启用 | 显式 `false` 才关闭 |
| `MY_OPENWAF_CVE_ENABLED` | CVE 开关 | 关闭 | 仅接受 `true` |
| `MY_OPENWAF_ACCESSLOG_SAMPLING` | 访问日志采样 | 1（全量） | <1 或非法时保留默认并告警 |

重载链路由 `config_revisions` 表驱动：`currentRevision` 读取版本号，`ReloadSnapshotWithPrePublish` 在版本未变时复用缓存快照，版本变化时构建新快照并在发布前执行回调，最后原子替换。规则目录对账在 `AutoMigrate` 之后、快照首次加载之前完成，因此首轮快照就能读到最新目录。

### 敏感度档位、阈值与规则优先级
敏感度字符串先经 `normalizeSensitivityLevel` 归一化，再由 `sensitivityThresholdForNormalizedLevel` 映射为闭区间阈值；`off` 使类别整体停用。类别级与规则级档位在其之上叠加。

| 档位 | 归一化输入 | 阈值 | 说明 |
|------|------------|:--:|------|
| `off` | `off`、`none` | — | `CategoryThreshold` 返回 `enabled=false` |
| `low` | `low` | 7 | 最宽松 |
| `mid`（默认） | `mid`、`medium` | 4 | 未识别值也回落此档 |
| `high` | `high` | 3 | 由 2 上调至 3 以降低误报 |
| `very_high` | `very_high`、`very-high`、`veryhigh` | 2 | 高威胁 |
| `strict` | `strict` | 1 | 单条即命中 |

档位可三层叠加，优先级由低到高：

| 层级 | 载体 | 解析入口 | 生效点 |
|------|------|----------|--------|
| 全局默认 | `ProtectionConfig.OWASPSensitivity` | `DefaultProtectionConfig`（`mid`） | `CompileThresholds` |
| 按类别 | `category_sensitivity` / `owasp_modules` JSON | `EffectiveCategorySensitivity` | `CategoryThreshold` 的第一优先分支 |
| 按规则 | `policy_owasp_rule_configs.sensitivity` | `ParseOWASPRulesConfig` | `HitPassesOverrideSensitivity` |

自定义规则的动作与优先级来自 `store.Rule`，编译时按 `Priority` 升序、`ID` 升序稳定排序；OWASP 内置规则不参与该排序，其执行顺序由 `owaspPhase.Execute` 内固定（上传 → 方法 → 主扫描 → 端点兜底）。

### 规则启用/禁用与覆盖修改流程

| 操作 | 端点 | 落库动作 | reload |

### 站点级三态覆盖语义
站点级 OWASP 字段与全局字段同名但语义不同，「空值」在本项目中一律表示继承，绝不等于关闭。

| 字段 | 类型 | 继承态 | 覆盖启用 | 覆盖关闭 |
|------|------|:--:|:--:|:--:|
| `owasp_enabled` | `*bool` | `null` | `true` | `false` |
| `owasp_sensitivity` | `string` | 空串 | 显式档位 | 空串（仅当 `owasp_enabled` 为 `false` 时无意义） |
| `owasp_action` | `string` | 空串 | 显式动作 | 空串（同上） |
| `anti_replay_cookie_mode` | `*string` | `null` | 显式模式 | 显式模式 |
| `skip_path_by_phase` | `*string` | `null` | `"{}"` 表示覆盖为不跳过 | 非空 JSON 覆盖为该配置 |

三态在前端由 `TriState = "inherit" | "on" | "off"` 表达，提交时经 `fromTriState` 还原为 `null`/`true`/`false`。后端在 `clearInheritedProtectionOverrides` 中做从属清理：`owasp_enabled == nil` 时连带把 `owasp_sensitivity`、`owasp_action` 清空，防止把继承态存成「空档位 + 空动作」这种看似显式覆盖的配置。快照合并只在 `site.OWASPEnabled != nil` 时才读取站点档位与动作，因此「继承 + 空档位」不会覆盖全局默认值。

### 覆盖校验规则
`validateOWASPPatch` 与 `validateOWASPStoredConfig` 构成两道校验：前者校验本次提交的补丁，后者校验与库中既有值合并后的最终形态，防止部分更新留下不自洽的配置。

| 项 | 约束 | 违规响应 |
|----|------|----------|
| `action` | 必须 `IsValid`，且归一化后不得为 `allow`/`tag` | 400 `invalid action` |
| `sensitivity` | `low`/`mid`/`medium`/`high`/`very_high`/`strict`/`off` 之一或空 | 400 `invalid sensitivity` |
| `status_code` | 为 0 视为清空；否则必须落在 100–599 | 400 `status_code must be between 100 and 599` |
| `redirect_to` | `redirect` 动作且规则启用时必填 | 400 `redirect_to required` |
| `captcha_type` | 必须与 `captcha_challenge` 动作配对 | 400 `captcha_type requires captcha_challenge action` |
| `cisco_asa_mode` | `legacy`/`strict`/`scoped` 或空 | 400 `invalid cisco_asa_mode` |
| `whitelist` | ≤64 条、单条 ≤512 字节、必须 `*` 或以 `/` 开头、通配符仅末位 | 400 对应错误文案 |
| `note` | ≤4096 字节 | 400 `note exceeds 4096 bytes` |
| 批量条数 | `ids` + `rules` ≤1000 | 400 `batch exceeds 1000 rules` |
| 批量载荷 | `reset_all` 不得与 `ids`/`rules` 混用 | 400 `reset_all cannot be combined with rule updates` |

补丁的空值语义为「清除该项覆盖」：`action`/`sensitivity`/`captcha_type`/`cisco_asa_mode`/`redirect_to`/`note` 传空串、`status_code` 传 0 时，对应指针字段被置回 `nil`，而不是写入空字符串。

## 性能考虑
- 阶段预处理：`NewOWASPPhase` 在快照构建期一次性完成阈值编译、覆盖解析与 ASA 档位归一化，`Execute` 热路径不再解析 JSON。
- 覆盖表容量：`ParseOWASPRulesConfig` 对空串与 `{}` 直接返回 `nil`，无覆盖时 `FilterFirstHit` 走零分配快路径。
- 目录读取缓存：同一 `policy_id` 的目录 + 覆盖视图带快照缓存，避免每次列表都重新联表。
- 列表分页：`page_size` 默认 500、上限 500（缺省与越界都取上限），`q` 过滤限制 256 字节，避免全表模糊扫描放大。
- 规则编译：按优先级与 ID 排序，仅启用规则参与编译。
- 配置重载：基于 `config_revisions` 版本号构建快照，版本未变时复用缓存，避免频繁重建。

## 结论
OWASP 配置管理由「环境变量配置 + 全局保护配置 + 按类别档位 + 按策略规则覆盖 + 站点三态覆盖」五层组成，任一层的空值都表示继承而非关闭。控制面写入后统一走 `reload()` 触发快照重建，数据面在快照构建期完成阈值与覆盖的预处理，因此配置变更可追溯、可回滚（`reset` 即删除覆盖行），且不会把解析成本带入请求热路径。
