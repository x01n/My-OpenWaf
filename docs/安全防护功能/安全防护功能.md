## 简介
本文件是「安全防护功能」域的总览，只回答三个问题：这个域包含哪些功能子域、每个子域挂在处理阶段链的哪一步、配置从哪里来又向哪里生效。

## 核心组件
- `iprep.IPReputation`：全局黑白名单 + 违规计数自动封禁，带 5 分钟清理协程（iprep.go:249）
- `rules.aclPhase` / `signaturePhase` / `customPhase`：三段用户规则阶段，共用 `Compiled` + `Matcher`（phases.go:131-192）
- `bot.CheckBotTwoPhaseWithBehavior`：预筛 + 五模块加权评分 + 五档处置（bot.go:922）

- `pages.WriteBlockResponse`：站点 HTML → 全局 HTML → 配置化模板 → 内嵌页四级回退（block.go:20-58）
- `visitorfusion.Result`：对已放行 HTTPS 请求做事后可解释分类，不参与判定（classifier.go:166-222）

## 架构总览
一次请求先解析客户端 IP（`security.ResolveClientIP`，clientip.go:17），再由引擎按条件装配的阶段链判定，最后由数据面把 `action.Result` 落成响应、断连或放行。

| 阶段名 | 产出本域动作 | 证据 |
|---|---|---|
| `ip_reputation` | Allow / Intercept / Drop | phases.go:368-433 |
| `acl` | Allow（不短路）/ Intercept / Drop / 挑战类 | phases.go:148-150、compiler.go:32-37 |
| `owasp_default` | 配置动作（默认 intercept） | phases.go:618-685 |
| `cve_detection` | 配置动作，Critical/High 可自动升 Drop | phases.go:827-839 |
| `bot_detection` | Observe / Challenge / Intercept / Drop | phases.go:561-591 |
| `rate_limit` | 配置动作（默认 rate_limit，429） | phases.go:316-340 |

动作档位的严重度只有一处定义：`TerminalPriority` 为 drop 90、intercept 80、rate_limit 70、四类挑战同 60、redirect 50、observe 10（action.go:88-115）。同档取先出现者。

## 详细组件分析

### 切面一：访问控制与信誉
本域有三条互不替代的准入路径，容易混淆，此处一次划清：

| 路径 | 数据源 | 匹配对象 | 命中动作 | 证据 |
|---|---|---|---|---|
| 全局黑白名单 | `ip_list_entries` 且 `site_id IS NULL` | `net.IP`（单 IP / CIDR） | 白 Allow（短路）/ 黑 Intercept 或 Drop | server.go:1331-1352、phases.go:404-432 |
| 站点黑白名单 | `ip_list_entries` 且 `site_id = 站点` | 同上 | 白 Allow（**不短路**）/ 黑 Intercept 或 Drop | build.go:1596-1644、phases.go:374-402 |
| 自动封禁 | 内存 `violations`（`sync.Map`） | IP 字符串键 | Intercept 或 Drop（按 `auto_ban_action`） | iprep.go:144-167、phases.go:421-432 |
| ACL 规则 | `rules` 表 `phase=acl` | `MatchCtx` 全字段 | 规则动作，Allow 不短路 | compiler.go:40-78、phases.go:148-150 |

关键语义差异：站点白名单命中返回 `stop=false`，后续阶段照常执行；全局白名单命中返回 `stop=true`，直接结束阶段链。二者都放行，但作用域完全不同（phases.go:376-384 与 411-419）。名单细节见 [IP 信誉系统](IP 信誉系统.md)，规则 DSL 与匹配器细节见 [ACL 规则引擎](ACL 规则引擎.md)。名单细节见 [IP 信誉系统](IP 信誉系统.md)，规则 DSL 与匹配器细节见 [ACL 规则引擎](ACL 规则引擎.md)。

`bot_detection` 是唯一「先评分、后分档」的阶段：五模块原始分按固定权重折算总分，再由 `ClassifyScore` 从阈值派生五档，危险标记走独立通道保证终止。

### 切面三：攻击特征检测
OWASP 与 CVE 都是「命中即产规则级动作」的检测阶段，二者内部实现庞大，本文不复制其类别表与检测器表：

- OWASP：`owasp_default` 阶段在 `prot.OWASPEnabled` 为真时入链（engine.go:496-498），执行入口 phases.go:618-685，动作取 `OWASPAction` 并可被规则级覆盖改写（phases.go:687-700）

- 两个阶段的启用位都是站点级三态字段（`owasp_enabled` / `cve_enabled`），nil 表示继承全局

规则内容、检测器与阈值表分别见 [OWASP 检测](OWASP 检测/OWASP 检测.md) 与 [CVE 漏洞检测](CVE 漏洞检测/CVE 漏洞检测.md)，本页不复制。

### 切面四：流量约束

## 性能考虑
- 阶段链按条件入链，未启用的检测不产生任何开销；阶段链本身以 11 为容量预分配（engine.go:467）
- Bot 的预筛把五模块加权评分限制在可疑流量上，干净流量只走 `PreScreen`（bot.go:359-376）
- `Details` 在干净流量下不分配 map，首个 detail 才惰性创建（bot.go:702-705、813-818）
- IP 名单是线性匹配，名单越长越应依赖自动封禁与站点级短名单；封禁记录由清理器每 5 分钟回收（iprep.go:249-271）
- Drop 零响应路径省掉 HTTP 响应生成，是四种终端动作里代价最低的一种（drop.go:47-72）
- `BotScoreLog` 只对非 human/good 的判定写库，良性流量不落库（phases.go:536-539）
- 观测通道全部异步：Drop/事件走统一写入器批量提交，热路径不等待磁盘（handler_support.go:334-348）

## 故障排查指南

| 症状 | 首查位置 | 判据 |
|---|---|---|
| 名单加了不生效 | 条目 `site_id` 作用域 | 全局条目进 `IPReputation`，站点条目只进阶段（server.go:1331、build.go:1596） |
| 白名单加了仍被拦 | 命中的是站点还是全局白 | 站点白 Allow 不短路，后续阶段仍可拦（phases.go:376-384） |
| Bot 判定全部放行 | `bot_detection_enabled` 与 GeoIP 库 | 阶段未入链或阈值 80 未达（engine.go:503、phases.go:470-473） |
| TLS 一致性判定不触发 | `RequestCtx.TLS` 是否有结构数据 | 无扩展/ALPN/SNI 时判据整体跳过（dynamic_tls.go:35-38） |
| Drop 后客户端收到 403 | 是否走了降级分支 | 响应头含 `X-OWAF-Drop-Degraded`（handler.go:839） |
| 拦截页显示默认样式 | 站点/全局 HTML 是否为空 | 四级回退顺序（block.go:29-57） |
| 页面里看不到规则 ID | 属预期脱敏 | 模板只注入 RequestID 与状态码（block.go:196-217） |
| 改了站点开关无效 | 从属字段是否被清空 | nil 继承时从属字段被清（admin/site/site.go:490-508） |

排查通则：先用 `X-Request-ID` 关联访问日志与安全事件，再按 `BotScoreLog` 的模块分与 `Details` 定位触发证据；协议级 Drop 只影响该连接，不影响同连接其他流以外的判定统计。

## 结论
本域以「阶段链 + 统一动作语义」为骨架，各功能子域只负责一个判定切面，判定与执行彻底分离：阶段产出 `action.Result`，数据面决定断连、渲染还是放行。配置只有一处真值（`SystemSettings.protection` 与 `ip_list_entries`），站点级用三态指针表达继承，避免了「空值被误存为关闭」这一类常见错误。跨子域最容易混淆的三点已在正文订正：站点白名单不短路、Bot 阶段的 TLS 判据走危险通道而非权重通道、Drop 在拿不到可关闭连接时会降级为 403。下一步的改进方向是把 `drop.DropStats` 的四个分桶字面值改成阶段名常量，使其与 `drop_events.source` 同源，省掉运维侧两套口径的对账成本。
