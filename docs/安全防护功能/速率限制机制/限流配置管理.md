## 简介
本文件面向限流配置管理系统，聚焦请求频率、错误频率与自动封禁三组配置项的模型、写入口与生效路径。系统提供两类可互换的限流后端：
- 本地限流器 `RateLimiter`：进程内固定窗口计数，`sync.Mutex` 保护窗口表、`atomic.Int64` 做窗口内自增 [ratelimit.go:20-34](file://internal/waf/ratelimit/ratelimit.go#L20-L34)。
- Redis 分布式限流器 `RedisRateLimiter`：基于 Sorted Set 的滑动窗口，三段 Lua 脚本保证原子性，单命令 50ms 超时、出错一律放行（fail-open）[redis.go:77-139](file://internal/waf/ratelimit/redis.go#L77-L139)。

两者都实现同一个 `RateLimiterBackend` 接口，由 `DynamicRateLimiter` 包装成进程级单例，Redis 可用性变化时在运行时 `Swap` 后端而不重建引擎 [ratelimit.go:9-17](file://internal/waf/ratelimit/ratelimit.go#L9-L17)、[dynamic.go:7-32](file://internal/waf/ratelimit/dynamic.go#L7-L32)。

配置只有一份真相：`ProtectionConfig` JSON 落在 `system_settings` 的 `protection` 行，唯一写入口是 `POST /api/v1/protection-settings`；进程级覆盖注册表 `internal/core/configoverride` 中没有 `request_ratelimit_*` 系列键，因此不存在第二配置源 [protection.go:12-25](file://internal/store/protection.go#L12-L25)、[router.go:287](file://internal/admin/router.go#L287)。

## 核心组件

### 本地限流器（RateLimiter）
- 固定窗口算法：键首次访问或 `expiry <= now` 时重建窗口，随后 `count.Add(1)` 与 `maxReqs` 比较 [ratelimit.go:96-118](file://internal/waf/ratelimit/ratelimit.go#L96-L118)。
- 双锁分工：`configMu sync.RWMutex` 保护窗口/配额/开关三元组的读写，`mu sync.Mutex` 只保护窗口表 [ratelimit.go:20-29](file://internal/waf/ratelimit/ratelimit.go#L20-L29)。
- 参数无效即视为未启用：`NewRateLimiter` 与 `Reconfigure` 在 `windowSec <= 0 || maxReqs <= 0` 时强制 `enabled = false`，避免零配额把首个请求判成超限 [ratelimit.go:36-51](file://internal/waf/ratelimit/ratelimit.go#L36-L51)、[ratelimit.go:80-94](file://internal/waf/ratelimit/ratelimit.go#L80-L94)。
- 后台回收：`cleaner` 协程每 30 秒删除过期窗口，表空时整体替换为新 map [ratelimit.go:175-196](file://internal/waf/ratelimit/ratelimit.go#L175-L196)。
- 全部方法 nil 安全，`Close` 用 `sync.Once` 关闭 `stopCh` [ratelimit.go:164-173](file://internal/waf/ratelimit/ratelimit.go#L164-L173)。

### Redis 分布式限流器
- 滑动窗口：三段 Lua 脚本先在 Sorted Set 上 `ZREMRANGEBYSCORE` 清出窗口外成员，再按 `ZCARD < limit` 决定是否 `ZADD`，并把键 TTL 设为 `window + 1` 秒 [redis.go:77-113](file://internal/waf/ratelimit/redis.go#L77-L113)。
- 客户端类型是 `rueidis.Client`（非 go-redis），键前缀由装配处传入 `openwaf:request` / `openwaf:error`，实际键形如 `openwaf:request:rl:<计数键>` [redis.go:13-37](file://internal/waf/ratelimit/redis.go#L13-L37)、[server.go:383-384](file://internal/app/server.go#L383-L384)。
- 时间基准是毫秒：`now = UnixMilli()`、`windowMs = windowS * 1000`，与本地实现按秒取整不同 [redis.go:130-133](file://internal/waf/ratelimit/redis.go#L130-L133)。
- 降级：`client == nil` 时构造函数返回 `nil`，装配处回退本地限流器；Redis 调用错误（含 50ms 超时）时 `Allow` 返回 true、`Increment` 返回 0、`IsOverLimit` 返回 false，即 fail-open [redis.go:22-37](file://internal/waf/ratelimit/redis.go#L22-L37)、[redis.go:115-192](file://internal/waf/ratelimit/redis.go#L115-L192)。
- `Close()` 是空实现，连接生命周期由上层 Redis 客户端统一管理 [redis.go:194](file://internal/waf/ratelimit/redis.go#L194)。

### 配置模型（ProtectionConfig）

## 性能考虑
本地限流器
- 窗口对象是 `{count atomic.Int64; expiry int64}`，自增走原子操作，但**取窗口仍要过 `rl.mu` 互斥锁**，高基数键（大量不同客户端 IP）会在锁上排队 [ratelimit.go:31-34](file://internal/waf/ratelimit/ratelimit.go#L31-L34)、[ratelimit.go:108-118](file://internal/waf/ratelimit/ratelimit.go#L108-L118)。
- 回收周期固定 30 秒，`map` 无容量上限；键基数由「bind × 站点 × Host × 客户端 IP」笛卡尔积决定，扫描式清理没有 LRU 兜底 [ratelimit.go:175-196](file://internal/waf/ratelimit/ratelimit.go#L175-L196)。

Redis 限流器
- 每次判定一次 `Eval`，脚本内 `ZREMRANGEBYSCORE + ZCARD (+ ZADD)` 保证原子，单次调用上限 50ms；错误即放行，不会把 Redis 故障放大成 5xx [redis.go:77-139](file://internal/waf/ratelimit/redis.go#L77-L139)。
- 键 TTL 为 `window + 1` 秒，空闲键自然过期，无需清理协程 [redis.go:88](file://internal/waf/ratelimit/redis.go#L88)。

调优建议
- 窗口分档：突发抑制取 10-60 秒，均值抑制取 60-300 秒（默认请求 60/300、错误 300/30），长周期统计不建议用限流器承载。
- 多节点部署必须开 Redis，否则同一客户端在 N 个节点上的实际配额约为配置值的 N 倍。
- bot 行为分与请求限流共用窗口长度，调 `request_ratelimit_max` 会同步改变行为分基准，需一并回归 [engine.go:509](file://internal/core/engine/engine.go#L509)。

## 结论
限流配置管理保持了单一配置源：字段定义与默认值在 `store.ProtectionConfig`，唯一写入口是 `POST /api/v1/protection-settings`，生效路径统一经 `reloadRuntime(true)` → 快照重建 → `applyProtectionRuntimeConfig` → Redis 广播。两套后端通过 `RateLimiterBackend` 与 `DynamicRateLimiter` 实现可替换，Redis 不可用时自动回落本地且不放大故障。

需要注意两处边界：窗口与配额的实际执行值是进程级单例上的全局值，站点覆盖只作用于开关、动作与 bot 阈值；本地后端没有键基数上限。建议生产多节点部署启用 Redis 后端，并把配额回归与 bot 行为分一并验证。

### 运维清单
- 变更前记录当前 `protection` 行 JSON，便于回滚。
