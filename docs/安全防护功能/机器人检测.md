## 简介
机器人检测是 `bot_detection` 阶段的判定能力，用来在爬虫、自动化工具、扫描器与真实浏览器之间做区分，并把区分结果折算成五档处置（放行 / 记录 / 挑战 / 拦截 / 断连）。

本模块的设计核心是**两条正交通道**：
- **加权总分**只回答「这请求有多可疑」，决定档位；单一弱信号叠加再多也不会直接致死
- **危险标记**只回答「能不能放过去」，任何一条确定性证据成立即保证档位不低于挑战

因此阈值调优只影响可疑度排序，不影响确定性终止；反过来加一条危险判据也不会把低分流量抬到拦截。该设计写于包内注释并落在 `applyDangerFloor`（bot.go:944-961）。

阶段名实为 `bot_detection`，不是 `bot`（phases.go:488）。TLS 指纹与 GeoIP 已从主包切分为独立子包，本文一并覆盖它们的采集与消费边界。

## 详细组件分析

### 两阶段判定流水线
`PreScreen` 是四条件闸门，任一成立即进入加权评分；全部不成立时直接返回 `human`，不产生任何评分开销（bot.go:359-376）：

| 预筛条件 | 判据 | 证据 |
|---|---|---|
| 恶意工具 UA | `matchMaliciousToolUA` 命中 20 条模式之一 | bot.go:262-283、378-394 |
| 名单拒绝 | `IPReputation.Check` 命中且不允许 | bot.go:364-369 |
| 地理高风险 | `MaxMindResolver.IsHighRisk` | bot.go:370-374、geoip.go:123-152 |
| 动态 TLS 矛盾 | `dynamicPrescreenHit`（任一条一致性矛盾） | bot.go:375、dynamic.go:190-192 |

`CheckBotTwoPhaseWithBehavior` 在评分完成后还会做一次良性爬虫复核：`matchGoodBotUA` 要求「UA 自称 × 反向 DNS 指向官方域」两条同时成立，UA 模式 0/1/2/5（Google、Bing、Yandex、Apple）之外的自称爬虫一律不按良性处理（bot.go:294-349、922-942、963-974）。

### 模块权重与档位划分
五个模块的权重合计 100，原始分各自钳制到 0–100，总分按 `Σ(模块分 × 权重)/100` 四舍五入（bot.go:671-690、794-803）。

| 模块 | 权重 | 主要判据 | 满分场景 | 证据 |
|---|:--:|---|---|---|
| UA | 40 | 工具字面 / 空 UA / 短 UA / 伪造 Mozilla | 空 UA = 100 | bot.go:604-635 |
| 请求指纹 | 25 | Accept 三件套缺失、`Connection: close`、扫描路径、头序、TLS 一致性 | 多项叠加 | bot.go:822-871、dynamic.go:118-179 |
| 行为 | 15 | 窗口请求数相对限流阈值的倍数 | ≥3 倍 = 100 | bot.go:649-663 |
| GeoIP | 5 | 机房 ASN +25、VPN ASN +15、高风险国家 +20 | 三项叠加 60 | geoip.go:153-180 |
| IP 声誉 | 15 | 黑名单 60、自动封禁 50、其它拒绝 30 | 黑名单 60 | bot.go:750-767 |

`IsHighRisk` 的判据是「总分 ≥ 80 或 地理原始分 ≥ 40 或 声誉原始分 ≥ 25」，与处置档位无关（bot.go:802）。

### TLS 一致性判据
`evaluateDynamicTLS` 只在 ClientHello 带有结构数据时才运行，判据分两类（dynamic.go:118-179、dynamic_tls.go:35-38）。

| 编号 | 原因码 | 类型 | 分值 | 判据 |
|:--:|---|---|:--:|---|
| D1 | `tls_fake_browser_claim` | 危险 | 30 | 自称 Chromium，但 ALPS、GREASE、h2/h3 三项同时缺失 |
| D2 | `tls_browser_stack_without_ua` | 危险 | 30 | 空 UA 却携带浏览器级 ClientHello |
| D3 | `tls_automation_browser_ua` | 危险 | 40 | UA 自称受控浏览器（HeadlessChrome/Puppeteer 等）且实况为浏览器栈 |
| W1 | `tls_alpn_ua_mismatch` | 观测 | 18 | 自称浏览器但未声明 h2/h3 |
| W2 | `tls_no_sni_for_dns_host` | 观测 | 10 | 域名为 Host 却未发 SNI |
| W3 | `tls_sni_for_ip_host` | 观测 | 8 | Host 为 IP 字面量却发了 SNI |
| W4 | `tls_browser_stack_foreign_ua` | 观测 | 25 | 浏览器级 ClientHello 搭配非浏览器 UA |

结构标记的实测分布决定了 D1 的可靠性：Chrome 桌面同时有 ALPS 与 GREASE，Edge/Safari/iOS WebKit 至少有 GREASE，Firefox 与 Go 两者皆无但声明 h2，因此任一真实栈都不会同时满足 D1 的三个否定条件（dynamic_tls.go:128-153）。SNI 存在性优先读 JA4 的指示位而非 SNI 字段，避免把「未采集」当成「未发送」（sni_presence.go:46-70）。

请求指纹模块的分数由三部分相加：`fingerprintScore`（头缺失与 TLS/UA 矛盾）、`headerOrderScore`（字母序头序 +8、UA 早于 Host +6）、`evaluateDynamicTLS` 的分数（bot.go:736-741、822-871、1016-1035）。

## 性能考虑
- 预筛是主要成本闸门：干净流量只走四个 O(1)~O(n) 判据即返回，不分配 `BotScore`（bot.go:888-889）
- `Details` 采用惰性分配，`setDetail` 首次写入才建 map（bot.go:702-705、813-818）
- 良性爬虫反向 DNS 结果缓存 1 小时，避免同一 IP 反复查询（bot.go:285-347）
- ClientHello 解析走 4096 槽直址缓存，命中时不重新计算 JA3/JA4（cache.go:9-40）
- 良性流量不写 `bot_score_logs`，省下按请求线性增长的库写入（phases.go:536-539）
- 行为分使用独立后缀键，不会让限流阈值被双重计数减半（phases.go:490-512）
- 恶意工具 UA 匹配先用 ASCII 大小写折叠的字面扫描做前置过滤，未命中直接跳过正则遍历（bot.go:378-404）

## 故障排查指南
| 症状 | 定位路径 | 处置 |
|---|---|---|
| 正常浏览器被判 `intercept` | `BotScoreLog.details` 的 `fingerprint` 与 `header_order` | 多为中间设备重写 ALPN 触发 W1，可放宽阈值或按路径跳过该阶段 |
| curl/wget 被直接打死 | 检查 UA 严重度是否被登记为 ≥ 80 | 常规工具应为 15–25，只叠加不终止（bot.go:579-585） |
| 空 UA 只记不拦 | 空 UA 权重后恰为 40 分，落在记录档 | 属设计值，需要更强处置时结合指纹叠加 |
| Googlebot 被拦 | 来源 IP 未通过反向 DNS | 只有模式 0/1/2/5 可校验，其余自称爬虫按可疑处理 |
| 行为分恒为 0 | `RateLimiterBackend.Enabled()` 与 `rateMax` | 请求限流未开启时行为分必为 0（phases.go:501-505） |
| GeoIP 分恒为 0 | 库路径与启动日志告警 | 库缺失时 `IsHighRisk`/`ScoreIP` 直接返回 0（geoip.go:123-180） |
| 站点关掉 Bot 无效 | `bot_protection_enabled` 是否为 nil | nil 表示继承全局，需在站点详情页显式覆盖 |
| 指纹页没有数据 | `RequestCtx.TLS` 是否为空 | 明文 HTTP 或关闭 ClientHello 窃读时属预期 |

排查顺序建议：先看 `action` 与 `total_score` 判断档位来源，再看五个模块分定位具体模块，最后用 `details` 里的原因码回到代码分支。

## 结论
机器人检测用「五模块加权 + 五档处置 + 独立危险通道」替代了旧版「恶意 UA 直接判死 + 三分类」的做法：可伪造的弱信号进权重，确定性强的证据进危险标记，两者互不换算，档位因此既可解释又不会被单一信号误抬到断连。TLS 与 GeoIP 已按职责切分成子包，主包只消费结构字段与解析结果，代码中不存在任何内置 JA3/JA4 指纹库表。

需要提醒的两点：`GET /fingerprints` 的数据源是访问日志聚合而非独立指纹库；前端 Bot 配置的归属页是 `captcha/`，不存在独立的 bot 页面。下一步建议把 `Details` 的原因码收敛成枚举并对齐前端 i18n，减少运维侧的字符串猜测。
