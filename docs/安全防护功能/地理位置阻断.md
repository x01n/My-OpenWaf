## 简介
My-OpenWaf 的地理位置阻断有**两条互不相干的通路**，这是本文最重要的划分：

| 通路 | 判定物 | 数据来源 | 产出 | 归属阶段 |
|---|---|---|---|---|
| 规则匹配通路 | 国家码 | **上游 CDN 注入的请求头** | 命中即返回规则动作 | `acl` / `signature` / `custom` |
| 评分加权通路 | ASN + 国家码 | **本地 MaxMind 库** | 地理模块原始分（权重 5%） | `bot_detection` |

前者由 `geoBlockMatcher` 实现，它只读 `x-geo-country` 与 `cf-ipcountry` 两个请求头，**完全不查本地库**（matcher.go:652-668）；后者由 `MaxMindResolver` 实现，只给 Bot 评分供能，本身不产生阻断动作。把两者混为一谈是旧文档的主要错误。

库文件本身的来源与拉取由 `bot/geoip` 子包负责（`GeoIPBootstrap`），环境变量为 `MY_OPENWAF_GEOIP_DB`。城市级查询能力存在但没有城市级阻断入口，阻断粒度止于国家。

## 详细组件分析

### 规则通路：国家码阻断匹配器
`geo_block` 是注册在 `knownPrefixes` 里的合法 kind（compiler.go:121），arg 为逗号分隔国家码，编译期归一为大写并去空（matcher.go:1757-1767）。校验侧要求 arg 非空（validate.go:133-139）。

| 判据 | 取值 | 说明 |
|---|---|---|
| 首选头 | `x-geo-country` | 命中且在国家集合内即返回 true，不再看第二头 |
| 兜底头 | `cf-ipcountry` | Cloudflare 注入，取值同样大写去空白后比对 |
| 反向语义 | 复合 `{"op":"not","children":[{"kind":"geo_block","arg":"CN"}]}` | 前端 `not_in_geo` 用 `wrapNot` 生成 |
| 动作 | 由规则自身决定 | `allow_ip` 语义不适用于地理，只有 `block` 类动作 |

两个关键限制必须写清：其一是**该通路的国家码来自请求头，不由本引擎推导**，因此只有当上游 CDN/代理确实注入该头时才有判定依据，直连场景永远不命中；其二是**头值不可信时必须由上游保证**，若客户端可自行伪造该头，规则会被绕过。前端条件构建器把 `src_ip` 目标的 `in_geo` / `not_in_geo` 映射到这一 kind，并要求值为 ISO 3166-1 alpha-2（rule-pattern-mapper.ts:174-186）。

### 评分通路：MaxMind 解析与打分
`ScoreIP` 的三项加分是固定值，互不遮蔽、可直接叠加（geoip.go:153-180）：

| 风险类型 | 加分 | 判定依据 | 证据 |
|---|:--:|---|---|
| 数据中心 ASN | +25 | ASN ∈ `dcASNs` | geoip.go:160-169 |
| VPN/代理 ASN | +15 | ASN ∈ `vpnASNs` | geoip.go:166-168 |
| 高风险国家 | +20 | ISO 码 ∈ `hrCountries` | geoip.go:171-178 |

`IsHighRisk` 是同一批集合的布尔版本，供预筛使用；两库都没有时直接返回 false，不做任何猜测（geoip.go:123-152）。`Lookup` 同时读 City 与 ASN 两个库，任一为空则该维度留零值（geoip.go:101-122）。

地理分进入 Bot 总分时被权重 5% 折算，即原始 60 分只贡献 3 分总分。设计意图写在权重注释里：机房与高风险国家只是环境概率，不能单独定性，`IsHighRisk` 判定则用「地理原始分 ≥ 40」这一绝对值口径（bot.go:60-85、802）。

### 库文件来源与自举
`GeoIPBootstrap(explicitPath, dataDir)` 的规则只有一条：显式路径存在即完全接管，否则在 `dataDir/geoip` 下自举（fetch.go:69-88）。

| 候选文件 | 功能面 | 校验 | 说明 |
|---|---|---|---|
| `GeoLite2-City.mmdb` | city | 无锚定值 | 城市面 |
| `GeoLite2-Country.mmdb` | country | sha256 + 字节数 | 城市面兜底 |
| `dbip-asn-lite.mmdb` | asn | sha256 + 字节数 | ASN 面 |
| `dbip-country-lite.mmdb` | country | sha256 + 字节数 | ASN 面兜底 |

启动流程如下：

| 步 | 动作 | 结论值 | 证据 |
|:--:|---|---|---|
| 1 | 显式路径存在且是普通文件 | 直接以同一文件满足两面，不做任何下载 | fetch.go:78-84 |
| 2 | 目录分诊 | `Kept` / `Tainted`（NotRegular、Oversize、ShaAnchored、SizeAnchored、OpenFailed） | fetch.go:186-238 |
| 3 | 逐候选下载 | `Fetched` / `Failed` / `Skipped`，单文件上限 16 MiB | fetch.go:98、319-383 |
| 4 | 汇总上报 | 一条 `slog.Warn` 汇总各候选处置 | fetch.go:109-124 |

自举失败不致命：路径为空时 `botCfg.Enabled` 仍会建 resolver，只是查询返回零值，地理维度静默退化为不参与打分（server.go:461-472、geoip.go:50-79）。

### 配置与热更新
配置有三个来源，收敛顺序固定。

| 配置 | 默认值 | 载体 | 证据 |
|---|---|---|---|
| `geoip_db_path` | 空 | 环境变量 `MY_OPENWAF_GEOIP_DB` / `bot_settings` / 覆盖表 | config.go:15、registry.go:372-376 |
| `high_risk_countries` | 空（必须由管理员配） | `bot_settings` | config.go:16、28-29 |
| `datacenter_asns` | 内置 13 项（AWS/GCP/Azure/DO/Vultr/Linode/OVH/Hetzner/Yandex/腾讯/阿里） | `bot_settings` 可覆盖 | config.go:30-43 |
| `vpn_proxy_asns` | 内置 8 项 | `bot_settings` 可覆盖 | config.go:44-54 |
| `score_threshold` | `core.BotConfig` 默认 80；`bot_settings` 投影缺省 60，被 `drop_policy.bot_score_threshold`（默认 80）覆盖 | `bot_settings` 与 `drop_policy` 双写同步 | config.go:27、admin/protect/bot/bot.go:44-74 |
| `bot_enabled` | `true`（决定是否创建解析器） | 逐键覆盖表，无环境变量载体 | config.go:25、config_override.go:41-44、registry.go:409-414 |

取值收敛顺序是：`DefaultBotConfig` → `MY_OPENWAF_GEOIP_DB` / `MY_OPENWAF_BOT_THRESHOLD` 环境变量 → 逐键覆盖表（`applyBotOverrides`）→ 管理界面的 `bot_settings`（`loadBotGeoConfig`），后者优先级最高（config.go:386-392、config_override.go:41-44、server.go:1354-1405）。

热更新在 reload 回调里完成，遵循两条节流原则：**路径不变就不重新开库**（避免无谓的 mmap 重开），**清单变化只更新集合**（`UpdateConfig` 取写锁替换三张表）（server.go:663-673、geoip.go:81-88）。`loadBotGeoConfig` 只覆盖请求里出现过的字段：nil 切片表示没配过、保留默认，空切片是用户主动清空、如实生效（server.go:1362-1404）。

前端入口是 `captcha/` 页的 Bot 设置块（GeoIP 库路径、高风险国家、机房 ASN、VPN ASN 四个输入项）与其下方的 detection 域覆盖卡（`geoip_db_path`、`bot_threshold`）。写接口为 `POST /bot-settings/update`，站点级开关为 `site.bot_protection_enabled`（三态，nil = 继承全局）（router.go:315、api.ts、site.go:60）。**仓库中不存在 `protection/` 页面**。

## 性能考虑
- 风险集合是 `map[uint]struct{}` 与 `map[string]struct{}`，命中判定 O(1)（geoip.go:198-211）
- 读路径全程只持读锁，热更新只发生在 reload，不在请求路径（geoip.go:101-180、82-88）
- `IsHighRisk` 在预筛阶段先跑，只有命中者才继续 `ScoreIP`，避免对干净流量做两次库查询（bot.go:370-374、723-734）
- 显式路径把城市面与 ASN 面指向同一文件，省一次打开开销，但也意味着单库必须具备两种记录类型（fetch.go:78-81）
- 自举下载有 16 MiB 上限，异常源不会把内存拖爆（fetch.go:97-98）
- 库文件由 `maxminddb` 以 mmap 方式读取，`Reload` 时才关闭旧句柄（geoip.go:50-79）

## 故障排查指南
| 症状 | 判据 | 处置 |
|---|---|---|
| `geo_block` 规则永不命中 | 请求里是否有 `x-geo-country` 或 `cf-ipcountry` | 直连场景没有该头，需由 CDN 注入 |
| 国家码大小写不生效 | arg 与头值都会大写去空白 | 若上游发小写也能动，问题多半在集合内容 |
| 地理分恒 0 | 库路径是否存在、启动日志是否告警 | 打开失败只告警并降级（geoip.go:50-79） |
| 高风险国家配了没用 | `hrCountries` 是否为空 | 默认为空是刻意设计，需管理员显式配置（config.go:28-29） |
| 机房 IP 没被加分 | ASN 是否在内置清单 | 内置 13 项之外需自行补录（config.go:30-43） |
| 界面保存后不生效 | reload 是否触发 `UpdateConfig` | 路径不变只更新集合（server.go:663-673） |
| Bot 阶段完全跳过地理 | `bot_settings.enabled` 与 resolver 是否为 nil | resolver 仅在 Bot 开启时创建（server.go:466） |
| 想按 IP 直接封国家 | 用站点级 IP 名单，不用 `geo_block` | 名单是库无关的确定性阻断（build.go:1596-1644） |

## 结论
地理位置阻断的正确答案取决于问的是哪条通路：要「按国家立刻拒绝」，就在规则里用 `geo_block` 并依赖 CDN 头；要「按网络环境抬升可疑度」，就配好 MaxMind 库让 Bot 阶段做地理加权。前者的强度是布尔的、后者的强度只有 5% 权重，两者不能互相替代，也不能互相印证。

本轮已订正：地理加权与 TLS 指纹分别住在 `bot/geoip` 与 `bot/tlsfp` 子包；`ScoreIP` 的分值是 25/15/20 而非旧文档写的「+0-25 区间」；不存在城市级阻断入口与 `protection/` 页面。下一步可评估的是把 `geo_block` 的头驱动模式扩展为可选的服务端解析模式，让直连部署也能用同一份规则语义。
