## 简介
本文件聚焦于数据平面（Data Plane）的处理流程与实现细节，涵盖请求从接收、WAF 处理、上游转发（含 HTTP、WebSocket、Server-Sent Events）、TLS 终止、连接池与传输层优化、以及可观测性与性能调优等主题。目标是帮助读者在不深入源码的前提下，理解系统如何高效、安全地处理流量。

数据平面以「每个站点绑定地址一个独立 Hertz 监听器」的方式运行，请求进入后依次完成四个阶段：

1. **协议层处理**：TLS 终止（证书选择、SNI 匹配、ALPN）→ HTTP/WebSocket/SSE/h2 扩展 CONNECT 协议识别；
2. **请求处理**：站点匹配（绑定地址 + Host）→ WAF 引擎多阶段规则执行 → 拦截/质询/维护/放行决策；
3. **上游转发**：轮询起点 + 健康择优选择上游地址 → 通过 `internal/proxy/transport` 的连接池复用连接 → 剥离 Hop-by-Hop 头部并回写响应；
4. **可观测性**：异步批量写入安全事件与访问日志、实时 QPS 与状态码统计、控制面 `/metrics` 文本指标导出。

整个链路以对象池（`RequestCtx`）、连接池（`http.Transport` / `http3.Transport`）与 HTTP/2 复用为核心优化手段，兼顾高并发与低延迟。

## 核心组件
- 数据平面处理器：负责静态资源、访问日志、WAF 执行、上游转发（HTTP/WebSocket/SSE）、错误率限流与状态统计。
- WAF 引擎与流水线：按阶段顺序执行规则链，支持观察命中与拦截动作。
- 上游代理与传输层：连接池按上游 scheme 分组缓存在 `internal/proxy/transport/transport.go`，支持 HTTP/2、HTTP/3、h2c 与 mTLS。

- 快照与站点运行时：提供站点匹配、上游地址、转发参数与证书等运行时信息。
- 阻断/维护页面：根据策略渲染阻断或维护页面，支持模板与内嵌资源回退。

## 架构总览

## 详细组件分析

### 请求处理主流程（从接收至响应）
- 内部端点优先：WASM 质询资产、ACME 质询、质询验证、动态保护密钥、访问控制端点与 `/__owaf` 静态资源依次短路。
- 请求上下文构建：使用对象池申请 RequestCtx，填充方法、路径、查询串、头部与 Body，Body 送检上限 48 KB。
- WAF 执行：按站点匹配与保护策略执行多阶段规则链，收集观察命中并决定是否拦截。
- 上游转发决策：按扩展 CONNECT、Upgrade、Accept、缓存命中与规则顺序选择转发分支。
- 错误率限流：基于响应状态码对 4xx/5xx 进行计数，按 bind + 站点 + 客户端 IP + Host 维度聚合。
- 访问日志与指标：记录请求 ID、方法、路径、主机、状态码与 WAF 动作。

## 性能考虑
- 对象池与内存：`RequestCtx` 池化并带容量上限（头 map 128、键切片 64、观察缓冲 32），送检体上限 48 KB，避免峰值后 RSS 不回落。
- 连接复用：共享上游 transport（256/32/30 秒）与 TLS 会话缓存（LRU 32）共同决定回源开销；h2c 与探活各有独立池。
- 反射与热路径：`stream` 子包按监听器是否注册 h2 协议栈决定是否绑定 CloseNotify，并用 `sync.Map` 缓存方法索引，避免每请求递归反射扫描。
- 请求 ID：`reqid` 用进程前缀 + 原子计数器生成 23 字节 ID，单请求一次堆分配，不消耗 `crypto/rand` 系统调用。
- 日志与指标：`logredact` 在入队前完成脱敏与截断；`unified_writer` 非阻塞入队，队列满时按 `SlowLogGrace`（默认 30 秒）决定是否等待。

## 故障排查指南
- 502 上游错误：先确认 `Pool.Pick` 返回的 base 是否来自健康集合，再检查 transport 池参数与 TLS SNI 配置；上游错误按 `shouldLogUpstreamErrorCount` 限流打印。
- 无站点匹配：当前实现写欢迎页并记 `routing_error`（状态 200），不是 404；核对快照键 `bind + NUL + 小写 host` 与 catch-all `*` 条目。
- 503 配置快照未加载 / 引擎不可用：分别对应 `handler.go:124` 与 `handler.go:165`，确认初始化顺序与 reload 结果。
- 431 头字段超限：由 `sn.HTTP2Config.MaxHeaderFields` 触发，调整 HTTP/2 配置而非放宽 WAF。
- WebSocket 握手失败：`readHTTPResponseHead` 要求状态必须是 101，且响应必须同时含 `Upgrade: websocket` 与 `Connection: Upgrade`，否则直接报错断开。
- SSE 无输出：检查 `Accept` 是否精确含 `text/event-stream`，以及 hijack writer 是否已被占用。
- 阻断页缺失：`WriteBlockResponse` 依次尝试站点 `BlockHTML` → 快照配置的阻断页 → 内嵌页面回退。

## 结论
数据平面以「监听器装配 → 端点短路 → 快照匹配 → 引擎判决 → 协议分支转发 → 异步观测」为主线，把职责切到 `internal/dataplane` 的根文件与六个子包，连接池与择优分别收敛在 `internal/proxy/transport` 与 `internal/upstream`。三类 transport 池的取值差异（256/32/30 秒、512/128/90 秒、128/32/90 秒）是回源容量的真实边界，调参时必须按池分别处理。
