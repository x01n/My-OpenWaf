## 简介

本篇只讲**可核对的监控暴露面**。My-OpenWaf 不推指标、不写日志到远端、不发告警，它只提供一个**拉取式文本端点**和三个 JSON 探针，外加一个可选 pprof。任何「已集成 Prometheus Remote Write / Grafana Agent / Datadog / NewRelic / OpenTelemetry Collector」的描述都不成立：`go.mod` 既没有 `prometheus/client_golang`，也没有 OTel/Jaeger/Zipkin 依赖（`go.mod:5-38`），`/metrics` 的文本是自己 `fmt.Sprintf` 拼出来的（`internal/observability/metrics.go:253`、`:771`）。

真实暴露面清单：

| 暴露面 | 路径 | 端口 | 鉴权 | 格式 | 装配位置 |
|---|---|---|:----:|---|---|
| 指标 | `GET /metrics` | 管理端口（默认 `:9443`） | **无** | `text/plain; version=0.0.4; charset=utf-8` | `internal/app/server.go:1056` |
| 存活 | `GET /healthz` | 管理端口 | **无** | JSON | `server.go:1053` |
| 就绪 | `GET /readyz` | 管理端口 | **无** | JSON | `server.go:1054` |
| 运行时状态 | `GET /status` | 管理端口 | **无** | JSON | `server.go:1055` |
| 管理台实时推送 | `GET /api/v1/realtime/ws` | 管理端口 | 一次性票据 | WebSocket | `router.go:424` |
| 性能剖析 | `/debug/pprof/*` | `MY_OPENWAF_PPROF_BIND`（默认不监听） | **无** | pprof | `cmd/main.go:29-41` |
| 业务聚合查询 | `GET /api/v1/dashboard/summary` 等 | 管理端口 | JWT/API Key | JSON | `router.go:203` |

抓取前提（缺一条就会看到「指标缺项」而非报错）：

| 前提 | 判据 | 未满足时的表现 |
|---|---|---|
| 网络可达管理端口 | `:9443` 未绑公网或已被防火墙收敛 | 抓取超时；同时 `/healthz` 也不可达 |
| 无鉴权即公开 | 四个探针与 `/metrics` 注册在 `api` 组之外（`router.go:110` 只对 `/api/v1` 挂鉴权） | 任何能连上端口的进程都能读拓扑与计数 |
| provider 已挂载 | 9 个 `Set*Provider` 在 `server.go:481-593` 装配 | 对应指标族整体缺席 |
| HTTPTrace 显式开启 | `MY_OPENWAF_TRACE_ENABLED=true`（`server.go:482`） | `openwaf_httptrace_*` 完全不存在 |
| Lua 脚本在跑 | `SetLuaScriptStatsProvider` 返回空切片时不渲染 | `openwaf_lua_script_*` 缺席 |
| 存在上游探活目标 | `SetUpstreamMetricsProvider` 读 `Pool.Snapshot`（`server.go:508`） | `openwaf_upstream_*` 全 0 |

**两套计数体系必须分开理解**，这是本主题最容易写错的地方：

| 体系 | 载体 | 出口 | 典型名 |
|---|---|---|---|
| 数据面原子计数 | `dataplane/metrics` 结构体字段 | 经 `SetDataPlaneMetricsProvider` 桥接后输出 `openwaf_dataplane_*` | `openwaf_dataplane_requests_total` |
| 观测性进程指标 | `observability.Metrics` 只持 `Uptime` | `PrometheusBody` 直接渲染 | `openwaf_uptime_seconds` |

`observability` 包里曾经存在的 `openwaf_requests_total`、`openwaf_blocks_total`、`openwaf_observes_total`、`openwaf_upstream_errors_total` **已连同字段与 Record 方法一并移除**（原因写在 `metrics.go:265-273` 的注释里：同一语义两条路径各持一份计数，会制造第二真相）。凡照旧名抓取的仪表盘都会拿到空序列。

## 详细组件分析

### 指标渲染与抓取时序

`PrometheusHandler` 没有缓冲、没有缓存：每次抓取都重新求值全部 provider，因此 gauge 反映的是抓取瞬间的值（`internal/observability/metrics.go:242-250`）。响应体以固定 5 条进程指标开头，再按 provider 挂载顺序拼接（`:273-345`）。

抓取链路的流程步骤表：

| 步 | 动作 | 执行位置 | 输入 | 输出 | 失败分支 | 可观测点 |
|:--:|---|---|---|---|---|---|
| 1 | 抓取请求进入管理端口 | `internal/app/server.go:1056` | GET `/metrics` | 处理器调用 | 端口不通则超时 | 抓取端 target state |
| 2 |  读运行时内存统计 | `internal/observability/metrics.go:258` | `runtime.MemStats` | alloc/sys/pause | 无 | `openwaf_memory_*` |
| 3 | 计算 uptime | `metrics.go:261` | `Metrics.Uptime` | 秒 | 无 | `openwaf_uptime_seconds` |
| 4 | 逐个 `atomic.Value.Load` | `metrics.go:299-344` | provider | 片段字符串 | provider 未挂载 → 跳过 | 对应族整体缺席 |
| 5 | label 值转义 | `metrics.go:568` | 名称含 `\`、`"`、换行 | 合法文本 | 不转义会破坏解析 | 抓取报 parse error |
| 6 | 设置内容类型并返回 | `metrics.go:246-248` | 文本 | 200 | 无 | `Content-Type: text/plain; version=0.0.4` |

### 数据面计数与 QPS 环

`dataplane.Metrics` 用 7 个 `atomic.Int64` + 10 槽环形桶（每槽 1 秒）实现近似 QPS：写入时若当前秒槽位不匹配就前进一格并重置为 1，读窗口时把 `now-ts < windowSec` 的槽求和除以窗口（`internal/dataplane/metrics/metrics.go:48-62`、`:112-125`）。唯一 IP 与攻击 IP 用互斥锁保护的 `map[string]struct{}` 去重，**作用域是进程生命周期**，进程重启即归零（`:80-109`，注释见 `:10`）。

## 性能考虑

- 抓取路径零缓存零分配复用：`PrometheusBody` 每次用 `fmt.Sprintf` 生成片段（`internal/observability/metrics.go:273`），代价是分配，换来的是永远没有陈旧值；对高频抓取（<5s）建议放长 `scrape_interval`。
- `runtime.ReadMemStats` 每次抓取只调用一次，但会产生一次短暂停顿（`metrics.go:258-259`），因此不要把 `/metrics` 当作高频健康检查端点使用。
- 数据面计数全原子，`Summary()` 一次读 12 个值，无锁；唯一例外是 IP 去重表的互斥锁（`internal/dataplane/metrics/metrics.go:80-109`），高基数流量下该锁是热点，`unique_ips_total` 因此是进程级近似值。
- 写入器批量 256 / 3s 与 `DoMulti` 合并（`internal/observability/unified_writer.go:1154`）使 DB 与 Redis 各只承担一次往返；宽限 30s 把「DB 落后」转化为「请求变慢」而不是「日志丢失」。
- 实时推送在无订阅者时不采集，节流成本随视图打开数增长（`internal/admin/system/realtime/realtime.go:456-467`）。

## 结论

本篇把监控暴露面收敛到可验证的一页：**一个无鉴权的 `/metrics`（自实现文本格式，18 个真实指标族）+ 三个 JSON 探针 + 一条 WebSocket 推送通道 + 可选 pprof**。相比旧版，本轮做了三类硬订正——把 `openwaf_requests_total` 等已删除指标与据此编写的告警表达式全部替换为 `openwaf_dataplane_*` 真值；把「未使用标签」改为按族列出真实标签（`window/class/action/type/cache/script/stage/proto/phase/name`）；把 OpenTelemetry、Datadog、NewRelic 从「集成」降级为「可作为 Prometheus 抓取端使用」，并删除了不存在的 drop/CVE/bot 指标与 `PUT/DELETE` 端点写法。

下一步建议：给归档器补一组专属指标（对应 I-02），把 `stats_retention_days` 接上或删除（I-03），以及在部署文档中强制要求 `/metrics` 所在端口不得暴露公网（I-01）。
