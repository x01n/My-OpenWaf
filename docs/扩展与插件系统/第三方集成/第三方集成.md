## 简介

本篇是「第三方集成」主题目录的总览，回答三个问题：My-OpenWaf 实际对外连接了哪些系统、每条连接的确切代码位置与失败行为、以及**哪些常被写进 WAF 文档但本项目根本没有实现的集成**。

结论必须先讲清楚：本项目的对外集成面是**收敛的**。`go.mod` 的 require 段实测只有 rueidis、ristretto、gorm（sqlite/mysql/postgres 三驱动）、quic-go、gopher-lua、quickjs-go、gmsm、maxminddb-golang、webp、freetype、go-captcha、utls、go-ja4、gorilla/websocket、hertz 等（`go.mod:5-38`），**没有任何消息队列客户端、没有 Elasticsearch/Loki 写入器、没有对象存储 SDK、没有 OpenTelemetry/Jaeger SDK、没有 SMTP 或 IM 机器人 SDK、也没有 prometheus/client_golang**——`/metrics` 的文本格式是自己渲染的（`internal/observability/metrics.go:253`）。凡把 Kafka、RabbitMQ、ES 远程写入、S3 归档、告警机器人写成本项目能力的描述，都是虚构，本文按下表口径逐条证伪。

## 核心组件

四条集成主线共享同一套约定：**每条出向连接自带超时与体积上限，每个后台循环失败只降级不致命，所有可选依赖以 nil 客户端起步**。

- `acme.Manager`：持有 `*acme.Client` 与进程内生成的 P-256 账户密钥（`internal/acme/acme.go:73`），密钥**不落盘**，因此进程重启后由 `Register` 重新注册（409 视为已注册，`acme.go:387-396`）。
- `threatintel.Manager`：一个 goroutine 轮询到期订阅源，30s 超时、10MiB 响应上限、gzip/deflate/zlib 自适应解压、逐行 `net.ParseIP`/`ParseCIDR` 校验（`internal/waf/threatintel/manager.go:25-32`、`:269-324`、`:346-390`）。
- `cve.CVEFeedManager`：同一条 `doSync` 依次拉 NVD 与 GitHub Advisory，两者错误合并后写内存 `SyncStatus`（`internal/waf/cve/feed.go:152-190`）。
- `coreredis.ConfigSync`：JSON 载荷带 `source_id` 做回环抑制（`internal/core/redis/pubsub.go:19-22`、`:113-116`），订阅循环不重连。
- `accessgate.OAuthFlow` + `RedisSessionStore`：数据面认证出向统一走带 10s 超时的专用客户端（`internal/waf/accessgate/oauth.go:26-32`），会话与 state 键前缀 `owaf:access:*`、单命令 100ms 超时（`internal/waf/accessgate/store_redis.go:15-21`）。

## 性能考虑

出向连接全部在后台 goroutine，不进请求热路径；唯一进入热路径的是访问控制 IdP 换取令牌（每个新会话一次），已用 10s 超时 + 1MiB 响应上限封顶（`internal/waf/accessgate/oauth.go:26-32`、`:225`）。Redis 事件扇出在 flush 阶段用 `DoMulti` 批处理（`internal/observability/unified_writer.go:1154`），失败不阻塞写库路径。指标侧的抓取成本可忽略：`/metrics` 每次请求只做一次 `runtime.ReadMemStats` 加 9 个 provider 快照（`internal/observability/metrics.go:253-345`）。

## 结论

本轮成果是把「第三方集成」从泛泛而谈改成可核对的事实集：一条集成清单表覆盖 23 项外部系统，逐项给到接入位置、配置项、状态与失败行为；把 Redis、ACME、GeoIP、威胁情报、CVE、IdP、上游、监控、实时推送九条主线分别落到流程步骤表或代码上下文表；并订正了三类长期错误——把 OAuth 说成未实现（实际已完整实现授权码 + PKCE + OIDC 发现）、把 gRPC 说成协议级支持（实际只有 scheme 别名与透传）、把未接线的 GeoIP 下载器与 CVE 同步历史表描述成在用能力。

遗留风险按优先级：ACME 出向没有显式超时（依赖调用方 ctx）、`ConfigSync` 无重连、`/metrics` 与探针无鉴权、`CVESyncLog` 与 `GeoIPBootstrap` 两处「已写未接」。下一步建议先接 `GeoIPBootstrap`（改动面最小、收益直接），再给 `doSync` 补 CVE 同步历史落库。
