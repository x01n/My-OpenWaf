## 简介

本文是**扩展与替换视角**的数据库适配器文档：回答「要接入第四种 SQL 方言要改哪几处」「要替换某个方言的取连接方式要动哪个函数」，而不是重述表结构与模型。仓库中数据库适配只有一条接缝——`database.Options` 加 `database.Open`，没有驱动注册表，也没有 `OpenLogDB` 这类第二入口，日志库走的是同一函数的 `LogDB` 字段分支。

**边界**：写现状的模型清单、字段明细、方言取值分布属于 [数据存储层/多数据库支持](../../数据存储层/多数据库支持.md) 与 [数据存储层/GORM 配置与使用](../../数据存储层/GORM%20配置与使用.md)，本文不复制其表格；扩展点全景与接口化替换见 [存储后端扩展](存储后端扩展.md)；池参数真值见 [连接池管理](连接池管理.md)；迁移版本与备份恢复见 [存储迁移机制](存储迁移机制.md)。

判定「这里是不是扩展点」的三条依据中，本适配层只满足两条：存在多个实现（三种方言打开路径）、上层只依赖 `*gorm.DB`；**不存在按名称解析的注册表**，分发靠 `switch` 硬编码。因此接入新方言必然是修改型扩展，而非插拔式扩展，这一点决定了后文流程表的形态。

## 详细组件分析

### Open 工厂与 Options 契约

`Options` 定义在适配包内而不是 `core.Config` 上，注释写明原因是避免与 `core` 形成导入环（`gorm.go:21`）。这一决定直接约束扩展方式：**新增方言不得给 `Options` 加字段**，只能扩 `Driver` 的取值集合，否则 `core` 侧要跟着改结构体，接缝变宽。

`Open` 的四段职责互相独立：装载 `gcfg`、按驱动分发、非 SQLite 池调优、返回句柄。分发段是唯一必须修改的位置。

| 符号 | 位置 | 职责 | 上游调用者 | 下游依赖 | 副作用 | 影响面 |
|------|------|------|------------|----------|--------|--------|
| `Options` | `gorm.go:22-27` | 方言标记与连接参数载体 | `runtime.go:63`、`runtime.go:88`、`dialect_test.go` 全部用例 | 无 | 无 | 高：所有取句柄路径的契约 |
| `Open` | `gorm.go:30-71` | 唯一分发点，产 `*gorm.DB` | `runtime.go:63-67`（主库）、`runtime.go:88-93`（日志库）、`dialect_migration_test.go:44` | `gorm.Open`、`sql.DB` 池 setter | 建立物理连接、创建 SQLite 目录 | 高：启动失败即整体不可用 |
| `openSQLite` | `gorm.go:73-109` | 拼 PRAGMA、建目录、设 8 连接 | `Open`（`gorm.go:47`） | `glebarez/sqlite`、`os.MkdirAll` | 磁盘写入 | 中：仅 SQLite 路径 |

### DSN 约定与凭据脱敏

三条 DSN 约定来自 README 与代码注释，互为印证；表中凭据一律 `{占位}`。

| 驱动 | DSN 形态 | 必带参数 | 出处 | 违反后果 |
|------|----------|----------|------|----------|
| sqlite | 文件路径，或 `:memory:` | 无（PRAGMA 由代码拼接） | `gorm.go:89`、`gorm_test.go:21` | 目录不存在会被 `MkdirAll` 补齐 |
| mysql | `{user}:{pass}@tcp({host}:{port})/{db}?charset=utf8mb4&parseTime=True&loc=Local` | `parseTime=True` | `gorm.go:118`、`gorm.go:123-125`、README.md:318 | 启动期直接拒绝，不放行到首次查询 |
| postgres | `postgres://{user}:{pass}@{host}:{port}/{db}?sslmode=disable` | 经 PgBouncer 事务池时加 `pgbouncer=true` | `gorm.go:137`、`gorm.go:157-159`、README.md:318 | 缺 `pgbouncer=true` 时报 prepared statement 不存在 |

脱敏是三形态合一：`url.Parse` 覆盖 `postgres://` 形态，`mysqldriver.ParseDSN` 覆盖 `user:pass@tcp(...)` 形态，两者都失败时落到 `maskDSNKeywordValues` 处理 `host=... password=...` 形态（`gorm.go:162-199`）。关键字判定集合固定为 `password` / `passwd` / `pwd` / `sslpassword`，大小写不敏感（`gorm.go:212-222`）；引号未闭合的畸形值整体替换为 `[redacted]`（`gorm.go:251-253`）。

新增方言时**唯一强制项**是把建连错误过一遍 `maskDatabaseOpenError`（`gorm.go:201-210`）：它先把错误串里出现的原始 DSN 换成遮蔽形态，再整体过一次 `maskDSN`。绕过它等于把凭据写进启动日志。

### 主库与日志库双句柄

不存在 `OpenLogDB`。日志库与主库共用 `Open`，差别只在 `Options.LogDB` 这一个布尔位（`runtime.go:88-93`），`openSQLite` 内部据此切换 PRAGMA 组合（`gorm.go:90-95`）。这是「一套工厂两种画像」的最小实现，替换日志库后端时**不需要**新函数，只需要给 `Options` 之外的 `LogDBDSN` 换值（`config.go:347-353`）。

| PRAGMA | 主库取值 | 日志库取值 | 差异动机 | 位置 |
|--------|----------|------------|----------|------|
| `journal_mode` | `WAL` | `WAL` | 读写并发 | `gorm.go:89`、`gorm.go:94` |
| `busy_timeout` | `10000` | `10000` | 锁等待上限 10 秒 | 同上 |
| `synchronous` | `NORMAL` | `NORMAL` | WAL 下的持久性折中 | 同上 |

```go
// 位置：internal/core/database/gorm.go，紧随 openPostgres（:134-149）之后
// 形状与 openPostgres 同构：DSN 必填校验 + gorm.Open + 错误脱敏
func openNewDialect(opt Options, gcfg *gorm.Config) (*gorm.DB, error) {
    dsn := strings.TrimSpace(opt.DSN)
    if dsn == "" {
        return nil, fmt.Errorf("{新方言} requires MY_OPENWAF_DSN (e.g. {user}:{pass}@{host}:{port}/{db})")
    }
    db, err := gorm.Open(newdialect.New(newdialect.Config{
        DSN: dsn,
    }), gcfg)
    if err != nil {
        // 必须复用：把错误串里出现的原始 DSN 先换成遮蔽形态
        return nil, maskDatabaseOpenError(err, dsn)
    }
    return db, nil
}

// 位置：Open 的 switch 分支（gorm.go:45-54）
//   case "{新方言}":
//       db, err = openNewDialect(opt, gcfg)
// 位置：core.Config.Validate 的白名单（config_validate.go:15-20）同步加同一字符串
```

## 性能考虑

适配层可调项极少，这是刻意结果：绝大多数性能旋钮在池层与迁移层。

| 场景 | 问题 | 优化 | 效果 |
|------|------|------|------|
| 单条 INSERT | GORM 默认包事务，写放大 | `SkipDefaultTransaction: true`（`gorm.go:38`） | 省掉每写一次两轮 BEGIN/COMMIT |
| 重复查询 | 每次重新解析与预编译 | `PrepareStmt: true`（`gorm.go:39`） | 语句缓存复用；PG 走 PgBouncer 时必须关简单协议 |
| 慢查询噪音 | 全量 SQL 日志拖吞吐 | `LogLevel: logger.Error` + `SlowThreshold: 200ms`（`gorm.go:33-34`） | 只留错误与超过 200ms 的语句 |

| SQLite 并发 | 单连接把读写串行化 | 8 连接 + WAL（`gorm.go:103-105`、`:89`） | 读并发可用，写仍受单写者约束 |

## 结论

适配层的可扩展性来自一处分发、一份契约、一个脱敏函数：`Open` 的 `switch` 是新增方言的唯一必改点，`Options` 的四字段承载全部参数，`maskDatabaseOpenError` 兜住全部凭据出口。**优势**：接缝窄（新增方言改动集中在 2 个文件）、失败早（DSN 与白名单在启动阶段判定）、行为可测（`dialect_test.go` 与 `gorm_test.go` 把别名、PRAGMA、脱敏边界都锁成断言）。**代价**：没有注册表，白名单在两处重复，靠测试而非抽象维持一致。**建议**：新增方言时把「白名单同步 + 脱敏 + 外部方言实测」三步当成不可拆分的提交单元；其余性能旋钮一律放到池层与迁移层处理，不要塞进适配函数。
