## 简介
本文件从**扩展开发视角**阐述 My-OpenWaf 的执行阶段系统，回答三个问题：阶段链由什么构成、要新增一个阶段该改哪些文件、新增一个阶段开关要走哪条配置链路。

- 阶段划分：引擎实测组装 **11 个阶段**，顺序为 `ip_reputation → anti_replay → acl → lua_pre → owasp_default → cve_detection → bot_detection → browser_sign → rate_limit → signature → custom`，注册点在 `internal/core/engine/engine.go:479-529`，链容量预分配 11（engine.go:467）。历史文档常写成「9 阶段」，缺 `lua_pre`（492-494）与 `browser_sign`（513-515）两段，本文件一律以 11 阶段为准。
- 上下文传递：`pipeline.RequestCtx` 是阶段间唯一上下文载体（pipeline.go:15-100），阶段通过它读写派生缓存、观察命中与请求改写意图。
- 配置与调度：阶段按「依赖非空」或「防护配置为真」两类条件入链；终态判定由 `action.TerminalPriority` 决定，drop 90 / intercept 80 / rate_limit 70 / 四类挑战同 60 / redirect 50，同档取先出现者（action.go:88-119、pipeline.go:517-560）。
- 扩展红线：阶段名同时受**三处**约束——`Phase.Name()` 返回值、`store.skipPathPhaseKeys` 跳过白名单、`admin/shared.ValidateSkipPathByPhase` 入参校验。漏登记第三处会让新阶段的跳过配置在保存期直接报 400。
- 边界：引擎侧实现现状由 [处理阶段详解](../../WAF%20引擎系统/处理阶段详解/处理阶段详解.md)、[管道执行机制](../../WAF%20引擎系统/引擎核心架构/管道执行机制.md)、[规则编译器](../../WAF%20引擎系统/规则编译器.md) 承载，本文件不复制其表格，只写扩展动作与需改动文件。

## 架构总览
执行阶段系统采用「按站点动态组装的阶段链」模式：`Engine.processResolved` 先取维护模式闸门，再取预编译规则与生效防护配置，调用 `getOrBuildPhases` 得到 `[]pipeline.Phase`，交给 `pipeline.Run` 顺序执行，最后在链外补一次后置 Lua 判定（engine.go:331-378）。

### 终态判定与短路语义
`pipeline.Run` 不是「遇到任何终止动作立即返回」的朴素循环，而是三档处理：

1. `stop == true` 且非挑战类：立刻返回该结果（phases.go 各阶段把 `IsTerminal()` 作为 stop 传回）。
2. `IsDrop()`：无条件立刻返回，TCP 关闭且不发送 HTTP 响应。
3. 挑战类（`challenge` / `captcha_challenge` / `shield_challenge` / `chain_challenge`）：**记为 pendingChallenge 继续跑完链**，若后续出现更高 `TerminalPriority` 则覆盖，否则末尾返回它（pipeline.go:529-558）。

| 动作 `Type` | `TerminalPriority` | 是否终态 | 默认状态码 | 短路表现 |
|---|:--:|:--:|:--:|---|
| `drop` | 90 | 是 | 0（不发响应） | 立即返回并关闭 TCP |
| `intercept` | 80 | 是 | 403 | 立即返回 |
| `rate_limit` | 70 | 是 | 429 | 立即返回 |
| `challenge` | 60 | 是 | 403 | 记 pending，继续跑链 |
| `captcha_challenge` | 60 | 是 | 403 | 同上；同档取先出现者 |
| `shield_challenge` | 60 | 是 | 403 | 同上 |
| `chain_challenge` | 60 | 是 | 403 | 同上 |
| `redirect` | 50 | 是 | 302 | 立即返回 |
| `observe` | 10 | 否 | 0 | 记入 `ObserveHits`，继续 |
| `allow` | 0 | 否 | 0 | 继续（不短路） |
| `tag` | 0 | 否 | 0 | 非终止打标 |

同档（四个挑战类型同为 60）**取链上先出现者**，因为覆盖条件是严格 `>`（pipeline.go:533、545）。

### 上下文传递、请求改写与对象池
- `RequestCtx` 是阶段间唯一上下文（pipeline.go:15-100）：请求标识、`Bind`、客户端 IP、方法、`Path` 与不可变的 `OriginalPath`、原始查询串、Host、头、体、TLS 指纹、站点 ID。
- 派生缓存三族：`BodyTargets`（OWASP/CVE 共用体抽取结果）、`matcherJSONBody`/`matcherQueryValues`/`matcherHeaders`（匹配器懒解析）、`derivedALPN`/`derivedHeaderOrder`/`derivedCipherSuites`（指纹拼接串）。每请求至多算一次，跨阶段复用。
- 阶段内观察命中：某阶段先产生 observe 命中、随后返回更强终止动作时，用 `AppendPhaseObserveHits` 暂存，由 `Run` 每轮 `DrainPhaseObserveHits` 收走（pipeline.go:214-230）。
- 请求改写出口 `RequestMutator`：`Method`/`Path`/`RawQuery`/`Body` 用指针区分「不改」与「显式置空」，头变更用 `SetHeaders`/`DeleteHeaders` 两张表（pipeline.go:290-297）。`ApplyRequestMutation` **先整体校验再整体应用**，任一非法即整份失败（pipeline.go:319-388）。保留头 `host`、`content-length`、`transfer-encoding`、`connection`、`keep-alive`、`te`、`trailer`、`upgrade`、`proxy-*` 一律拒绝（pipeline.go:398-410）。
- 响应改写出口 `ResponseMutator` 只服务链外 Lua post，由数据面转交 proxy 的响应变换链（pipeline.go:463-491）。
- 对象池：`AcquireCtx`/`ReleaseCtx` 复用 `RequestCtx`，池容量上限 `maxPooledHeaderMapLen 128`、`maxPooledHeaderKeysCap 64`、`maxPooledObserveHitsCap 32`（pool.go:12-17）。**新增上下文字段必须在 `ReleaseCtx` 补清理**，否则跨请求脏读。

```go
package rules

import (
	"My-OpenWaf/internal/core/action"
	"My-OpenWaf/internal/core/pipeline"
)

// contentFilterPhase 是新增阶段的样板：无外部状态，依赖由构造函数注入。
type contentFilterPhase struct {
	enabled   bool
	threshold int
}

// NewContentFilterPhase 返回阶段实例。依赖缺失时不要返回 nil 阶段，
// 而是在引擎注册点用条件判断决定是否入链。
func NewContentFilterPhase(enabled bool, threshold int) pipeline.Phase {
	return &contentFilterPhase{enabled: enabled, threshold: threshold}
}

// Name 必须与 store.skipPathPhaseKeys 中登记的键逐字符一致。
func (p *contentFilterPhase) Name() string { return "content_filter" }

// Execute 返回 (action.Result, stop)。stop 用 result.IsTerminal() 推导，
// 不要自己造第二套短路判据，否则与 pipeline.Run 的挑战延迟语义冲突。
func (p *contentFilterPhase) Execute(ctx *pipeline.RequestCtx) (action.Result, bool) {
	if !p.enabled || ctx == nil {
		return action.Pass(), false
	}
	body := ctx.Body
	if len(body) == 0 {
		return action.Pass(), false
	}

	// 只读上下文字段；跨阶段数据请写回 ctx 导出字段并同步 ReleaseCtx 清理。
	if len(body) > p.threshold {
		r := action.Result{
			Type:     action.Observe,
			Matched:  true,
			Phase:    p.Name(),
			Category: "content_filter",
			MatchDesc: "body exceeds threshold",
		}
		return r, r.IsTerminal()
	}
	return action.Pass(), false
}
```

| 步 | 动作 | 文件:行 | 关键点 |

### 阶段跳过装饰器与第三处白名单
`addPhase` 闭包（engine.go:472-477）在 `prot.GetSkipPathByPhase()` 非空时给每个阶段包一层 `skipByPathPhase`：命中跳过列表返回 `(action.Pass(), false)`，`Pass()` 的 `Matched` 为零值 false，因此既不记 observe 也不短路——是「跳过这一个检测」而非「放行整个请求」；`Name()` 透传 inner（phase_skip.go:38）；判定同时要求 `OriginalPath` 与当前 `Path` 都命中（phase_skip.go:41-48），防止 Lua pre 改写路径后绕过。

## 性能考虑
- 对象池：`RequestCtx` 经 `sync.Pool` 复用，容量上限见 pool.go:12-17；新阶段不要长期持有 `ctx` 指针或转存 `Body`，否则跨请求泄漏。
- 短路收益：`drop`/`intercept` 立即返回；四类挑战故意**不**立即返回而是继续跑链，代价是多跑若干阶段，收益是避免低优先级挑战压制高优先级判定。扩展阶段应尽量排在其应让位的检测之前。
- `needsDerivedHeaders` 按需计算：只有规则出现 `tls_alpn`/`tls_cipher_suite(s)`/`header_order_contains`/`header_order_regex`（或复合条件含它们）时才拼接派生串（phases.go:228-247）。新阶段要同类派生值请复用 `ctx.DerivedALPN`/`DerivedCipherSuites`/`DerivedHeaderOrder` 闭包缓存，不要算第二遍。
- 阶段链缓存：链按 `{policyID, siteID, antiReplayEnabled}` 缓存，热路径只付一次 `atomic.Pointer.Load`；`addPhase` 包装装饰器只在 `skipMap` 非空时引入一层调用（engine.go:472-477），未配置跳过时零开销。
- 计数键统一：限流、bot 行为分、规则 `cc_rate` 三类窗口共用 `RateLimitKey`（phases.go:63-70），键含 `bind` 与归一化 Host。新阶段若要建自己的窗口，请复用该函数而不是只按 Host 建键。
- 建议：新阶段 `Execute` 内避免分配；暂存命中走 `AppendPhaseObserveHits`；能力缺失时返回 `action.Pass(), false` 而非错误动作。

## 结论
执行阶段系统对扩展者只暴露三个真正的接入点：`pipeline.Phase` 接口、`engine.getOrBuildPhases` 的注册块、`store.skipPathPhaseKeys` 的阶段名白名单。三者都足够小，新增一个阶段不需要改动短路与审计逻辑。

本次迭代成果：阶段链从错误的「9 阶段」订正为实测 11 阶段；澄清 allow 不短路；补齐终态优先级与「同档取先出现者」语义；散点要点转为模块清单表、代码上下文表、阶段属性表、依赖矩阵表、两张流程步骤表与排查表；补齐两篇硬要求流程节。

KISS/YAGNI/DRY/SOLID 落点：
- KISS：阶段只由 `Name()` + `Execute()` 两个方法构成，注册是一行 `addPhase`。
- YAGNI：不为「未来可能的阶段元数据注册中心」造表，注册点保持直读直写。
- DRY：规则类阶段共用 `executeCompiledPhase`，窗口共用 `RateLimitKey`，派生值共用 `Derived*` 闭包缓存。
- SOLID：`LuaPluginEvaluator` 是包内定义的最小接口，阶段依赖抽象；新增阶段是「扩展」而非修改既有阶段（OCP）。

已知问题：`allowShortCircuit` 形参在 `executeCompiledPhase` 中未被使用，属代码事实而非文档笔误，本文件按现状描述。下一步若要「allow 即放行整链」，应新增显式动作判定而不是复用该形参。
