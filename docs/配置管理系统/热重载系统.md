## 简介

本文件专述 My-OpenWaf 的**热重载链**本身：配置变更如何被检测、如何一路走到不可变快照重建、如何原子替换、以及一次重载到底会带动哪些运行期副作用。

覆盖范围：

- 变更检测：`config_revisions` 修订号自增、Redis Pub/Sub 事件、（不存在的）文件监控。
- 重建与发布：`Runtime.ReloadSnapshotWithPrePublish` 的代次 CAS 二次核对。
- 副作用面：监听器协调、限流器重配置、Lua/JS 脚本热替换、IP 名单重载、上游连接池回收。
- 分布式：跨节点**只传事件不传快照**的语义与回环抑制。
- 生命周期：启动顺序、优雅关闭、热移除窗口。

## 核心组件

- 唯一重载闭包：`reloadRuntime(propagate bool)`。`propagate=true` 表示本节点是变更源，先 `store.BumpRevision` 再重建；`propagate=false` 表示由 Redis 订阅回调触发，修订号已由变更节点自增，本节点只重建。
- 代次 CAS 发布：`ReloadSnapshotWithPrePublish` 在 `reloadMu` 互斥下循环，每次构建前后各读一次修订号，任一次不一致就 `continue` 重来，最终由 `Holder.StoreIfNewer` 做第二次单调性保护。
- 快照前钩子：`prePublish` 回调在快照对请求处理器可见之前执行，当前唯一使用者是 JS 插件引擎预热（`server.go:870-877`）；钩子返回错误时**当前已发布快照保持不变**。
- 副作用编排：`applySnapshotReload` 按固定顺序做「响应缓存清理 → 运行期参数重设 → Lua 热替换 → IP 名单重载 → 监听器协调 → 上游连接池回收」。
- 监听器协调：`reconcileListeners` 用 `siteListenerFingerprint` 生成的 SHA-256 标签比对，标签变化才 `Remove` + `StartOne`，只影响受影响 bind。
- 跨节点通知：`redis.ConfigSync` 只广播 `{source_id, action:"reload"}`，不携带快照内容。

### 重载触发矩阵

### 配置变更检测机制

- 数据库修订号：变更信号唯一来源是 `config_revisions` 表的单行（`ID=1`）。`BumpRevision` 先以 `ON CONFLICT DO NOTHING` 播种，再 `UPDATE revision = revision + 1`，并要求 `RowsAffected == 1`，否则报错（`migrate.go:141-160`）。读取用 `FirstOrCreate`，缺行时以 `revision=0` 播种（`runtime.go:283-289`）。
- Redis 事件：发布端 `PublishReload` 发送 JSON `{source_id, action}`，订阅端 `Subscribe` 解析后按 `source_id` 抑制回环（`pubsub.go:114-116`）。
- 文件监控：**当前实现不存在任何文件系统监控**。配置的唯一真相是数据库；`MY_OPENWAF_*` 环境变量只在进程引导期读取一次，改环境变量必须重启。
- 轮询兜底：**没有修订号轮询协程**。若 Redis 未启用，跨节点一致性只能靠各节点自身的 Admin 写请求或手动 `POST /api/v1/reload`。

### 代次 CAS 与并发保护

`ReloadSnapshotWithPrePublish` 的设计目标是：**任何被发布的快照，都必须与发布瞬间数据库里的修订号一致**。为此在单次循环里做了三次修订号读取（`runtime.go:219/224/236/250/262`），构成两道核对：

1. 构建（或缓存取值）后核对一次，不一致则丢弃重来；
2. `prePublish` 回调之后再核对一次，防止钩子执行期间发生新的变更；
3. 最后由 `Holder.StoreIfNewer` 做「代次不小于当前」的 CAS，`current.Revision >= s.Revision` 时直接返回 `false` 而不发布。

前置条件：动态防护密钥基必须已配置为 32 字节，否则整个方法立即返回错误（`runtime.go:215-217`）。启动链在 `server.go:289` 由 `deriveDynamicProtectionKeyBase(jwtSecret)`（`server.go:1490`）注入，因此**手动构造 Runtime 而未设置密钥基时重载必然失败**。

### 监听器协调与指纹

`reconcileListeners`（`server.go:722-825`）分四轮扫描：

### 回滚机制与失败面

- **没有自动回滚到上一快照的逻辑**。重载一旦失败，`Holder` 里仍是上一个成功发布的快照，数据面继续按旧配置服务；本次失败的构建产物被直接丢弃，不回写缓存（`runtime.go:246-249` 在 `Build` 报错时立刻返回）。
- 失败传播路径统一为 500，文案 `config applied but reload failed: ...`（如 `protection.go:297-301`、`acme.go:521-526`、`rule.go:181-184`）。**这是非 fail-closed 的写法**：配置已经落库，只是没有生效，重启后同样会重载失败。
- 构建期的错误分流由 `Build` 决定：致命错误使整次重载失败（例如默认策略缺失，`build.go:71-73`）；可跳过的无效项写入 `ConfigDiagnostics` 随快照发布（`build.go:39-40`、`509-524`）。
- 单脚本编译失败不阻断整体：Lua/JS 的错误分别落到 `LuaPluginErrors`/`JSPluginErrors`（`snapshot.go:238-248`）。
- 手动干预手段：修复数据库中的非法值后 `POST /api/v1/reload`；或在无法修复时清空本地缓存并回退到上一份数据（备份恢复路径 `router.go:382-388`）。

## 性能考虑

- 读路径零锁：数据面通过 `Holder.Load()` 取快照，重载只做指针级 CAS（O(1)），不会阻塞正在处理的请求。
- 重建成本随配置规模增长：`Build` 一次性读取站点、监听器、证书、规则、策略、访问控制、插件与全部系统设置，站点数与规则数是主要变量；这部分口径见 [配置快照机制](配置快照机制.md)。
- 缓存命中价值：同修订号复用已构建快照，避免重复 `Build`；但缓存 MaxCost 很小，长期只保留最近的代次。
- 监听器粒度：按 bind 重启而非全进程重启，指纹不匹配只影响该端口的在途连接。
- Redis 通知不放大延迟：发布走 2s 超时且失败只告警，重载链不会因通知而变慢。
- 建议：批量变更（规则导入、备份恢复）尽量走单端点，减少 `BumpRevision` 次数；每次重载会带一次全量 `Build` 与一次 IP 名单重载。

| 其他节点不跟随 | 未启用 Redis | `received config sync reload` 是否打印 | 在各节点分别调用重载端点 |
| 限流不生效但窗口已改 | 站点覆盖不入全局窗口 | `server.go:638-639` 只取全局 `Protection` | 站点级 window/max 仅影响入链判定 |
| 频繁整表重启 | 全局 TLS/HTTP2 默认值反复变 | 指纹含全局默认值（`server.go:2050` 起） | 把站点级字段显式固定 |
| Redis 改配置后限流异常 | `ReloadRedis` 不重建窗口 | `server.go:926-979` | 手动 `POST /api/v1/reload` |

## 结论

热重载链的实质是「**一个修订号 + 一次全量重建 + 一次原子替换 + 一串固定副作用**」。三条设计取舍值得强调：

1. 用代次 CAS 而非全局锁来保证快照一致性，代价是重载可能被高并发改写打断并重来，收益是读路径完全无锁。
2. 跨节点只传事件不传快照，代价是每个节点都要能访问自己的配置真相，收益是无需快照序列化协议、无版本兼容负担。
3. 重载失败不回滚，代价是存在「已落库未生效」的中间态，收益是不会在故障时反复改动运行中配置。

建议：把 `POST /api/v1/reload` 纳入发布后检查项，以日志关键字 `hot-started site listener`、`reconciled idle upstream transports after snapshot reload`、`received config sync reload` 作为三段式验收信号。

### 重载兼容性矩阵

「兼容」在这里指：某类配置载体能否在不重启进程的前提下被重载链接管。

| 配置载体 | 写入口 | 是否被 `Build` 读取 | 是否需重启 | 兼容说明 |
|----------|--------|:---:|:---:|----------|

| `runtime_config_overrides` 设置键 | `POST /api/v1/runtime-config/env-overrides` | 是（`build.go:1260-1283`） | 部分键需重启（`RestartRequired`） | 布尔类键逐键指针式覆盖 |
| `protection` 设置键 | `POST /api/v1/protection-settings` | 是（`build.go:1285-1301`） | 否 | 全量 JSON 覆盖 |

| `lua_plugins` / `js_plugins` | 插件端点 | 是 | 否 | 单脚本失败不阻断 |
