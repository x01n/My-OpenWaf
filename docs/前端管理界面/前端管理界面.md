> **模块概述**
> 前端管理界面位于 `frontend/`，基于 **Next.js 16.2.6 + React 19.2 + Tailwind CSS v4 + shadcn/ui（`radix-luma` 风格）** 构建，采用分层结构：视图层（App Router 页面与 69 个组件文件）、交互层（表单/对话框/确认弹窗）、服务层（`lib/api.ts` 统一封装 + SWR 快照缓存）、样式层（`app/globals.css` 的 oklch 变量与 next-themes 主题）。
> 关键前提（来自 `frontend/AGENTS.md`）：本仓库的 Next.js 版本「不是你所熟知的 Next.js」，涉及路由、渲染、缓存、metadata、字体、构建配置的表述均以 `frontend/node_modules/next/dist/docs/` 与实测配置文件为准，不采用训练记忆中的通用说法。最直接的体现是 `next.config.ts:4` 的 `output: "export"` —— 全站为静态导出，不支持 `redirects`/`rewrites`/`cookies()`/Server Actions/ISR，因此根路径跳转用 `<meta httpEquiv="refresh">`（`app/page.tsx:4`）实现，凭据用 `localStorage`（`lib/api.ts:137`、`:191`）承载。

## 简介
本文件面向 My-OpenWaf 前端管理界面的开发者，系统化梳理基于 Next.js 16.2.6 + React 19.2 的前端架构与组件组织，重点覆盖以下方面：
- 基于 shadcn/ui 的组件库使用方式与自定义主题系统
- 状态管理策略（本地状态、对话框与确认弹窗、SWR 快照）
- API 集成模式（统一请求封装、鉴权与错误处理）
- 用户交互设计原则（导航、表单、表格、提示）、组件开发约定与性能优化建议

阅读顺序建议：先读本篇的「页面目录索引」建立整体地图，再按「Next.js 架构设计」→「组件设计模式」→ 其余四篇二级文档逐层深入。

## 结论
该前端管理界面以 Next.js 16.2.6 + React 19.2 为基础，结合 shadcn/ui（`radix-luma`）与 Tailwind CSS v4 实现了统一主题与组件风格；通过 `lib/api.ts` 与 `hooks/use-api.ts` 的两段式封装保障了鉴权、错误处理与缓存一致性；导航、面包屑与多标签工作区由 `lib/route-titles.ts` 单一数据源驱动，避免多处配置漂移。CRUD 采用「复用件 + 页面级表单载体」的组合模式而非巨型通用组件，符合 KISS 与 YAGNI。

优势：
- 69 个组件文件按「原子 → 业务 → 页面」分层，边界清晰
- 路由元数据、写操作失效前缀、错误处理三处均有单一真源
- 静态导出与浏览器存储配合，摆脱服务端依赖

已知不一致（如实记录，未擅自改代码）：
- `next.config.ts:12` 的 `optimizePackageImports` 仍含未声明的 `lucide-react`
- `sidebar-nav.tsx:377` 页脚硬编码 `v1.0.0`，与 `package.json:3` 的 `0.0.1` 不符
- `lib/route-titles.ts` 缺 `/tls-fingerprints` 条目，导致该页标题回落
- `hooks/use-api.ts` 的 `useIsAuthenticated`、`components/tab-workspace.tsx` 的 `useTabWorkspace` 未见调用方

### 组件开发约定
- 新增保护配置字段时同步 store 模型、Admin handler、前端类型、页面表单与验证命令，不制造第二配置源。
- 组件一律用 `cn()` 合并类名，并以 `data-slot`/`data-variant`/`data-size` 暴露状态钩子。
- 写操作后必须调用对应的 `invalidate*` 前缀重验，不手动拼 `mutate()`。
- 图标统一从 `@tabler/icons-react` 引入 `Icon*`，不引入 `lucide-react`。
- 涉及浏览器 API 的初值不得写在 `useState` 初值里，改用 `useEffect` 或 `useSyncExternalStore`。
- 文案必须走 i18n key，同时补齐 `lib/i18n/locales/zh.json` 与 `en.json`（各 2540 行）。
