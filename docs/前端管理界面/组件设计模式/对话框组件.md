## 简介
本文件系统梳理 My-OpenWaf 的对话框组件体系，涵盖模态对话框的设计模式与生命周期管理、打开/关闭状态控制、背景遮罩处理；对话框通用结构（标题、内容区、操作按钮、关闭机制）；表单校验在对话框中的实现方式；尺寸控制与响应式策略；以及组件复用模式与参数传递。

需要先纠正旧文档的两处失真：

1. 不存在名为 `AddSiteDialog` 或 `ProtectionModeDialog` 的组件。站点表单弹窗的真名是 **`SiteFormDialog`**（`sites/components/site-form-dialog.tsx:137`）；「防护模式」不是一个独立对话框，而是站点详情页 `protection-tab.tsx` 内联的表单区，模式选择通过 `RadioGroup` 与徽章呈现。
2. 遮罩不是「透明黑」而是 `bg-black/30` 且在支持时叠加 `backdrop-blur-sm`，并可通过 `disableBackdropBlur` 关闭（`dialog.tsx:45-46`）。

体系分三层：UI 原语（`Dialog`、`AlertDialog`、`Sheet`）→ 通用封装（`ConfirmDialog`）→ 业务对话框（12 个具名导出 + 6 个页面内联）。

## 核心组件
三个原语的语义分工是明确的，混用会导致交互契约不一致：

| 组件 | 适用场景 | 关闭语义 | 焦点契约 | 典型调用方 |
|------|----------|----------|----------|------------|
| `Dialog` | 表单编辑、详情浏览 | 遮罩点击 / `IconX` / `ESC` / `DialogClose` 均可 | 可逃逸，允许外部按钮接管 | `SiteFormDialog`、`RuleFormDialog` |
| `AlertDialog` | 危险动作二次确认 | 必须显式选 `Action` 或 `Cancel` | 拦截逃逸，不点不关 | `ConfirmDialog`、`rules/owasp/page.tsx` |
| `Sheet` | 移动端抽屉、贴边面板 | `side` 决定动画方向，默认 `right` | 复用 `Dialog` 的焦点陷阱 | 仅 `ui/sidebar.tsx` |

`ConfirmDialog` 的完整属性表：

| prop | 类型 | 默认值 | 说明 | 位置 |
|------|------|--------|------|------|
| `open` | `boolean` | 必填 | 受控开关，父组件持有 | `confirm-dialog.tsx:16` |
| `onOpenChange` | `(open: boolean) => void` | 必填 | Radix 回调，遮罩/`ESC` 也走它 | `:17` |
| `title` | `string?` | `t("common.confirmTitle")` | 缺省时回落 i18n | `:18`、`:38` |
| `description` | `string?` | `t("common.confirmDescription")` | 同上 | `:19`、`:39` |
| `confirmText` | `string?` | `t("common.confirm")` | 按钮文案 | `:20`、`:40` |

## 架构总览
对话框的行为内核全部来自 Radix；本仓库这一层只做三件事：加 `data-slot` 标记、加样式与动画、加两个自定义 prop。

```mermaid
stateDiagram-v2
  state "未挂载（Radix 惰性）" as UNMOUNTED
  state "进场动画 data-open" as ENTERING
  state "已打开 open" as OPEN
  state "退场动画 data-closed" as EXITING
  state "提交中 isSubmitting" as SUBMITTING
  UNMOUNTED --> ENTERING: 父级 setOpen(true)
  ENTERING --> OPEN: fade-in-0 / zoom-in-95 完成（duration-100）
  OPEN --> OPEN: 字段变更 / 遮罩不消费
  OPEN --> SUBMITTING: handleSubmit 通过校验
  SUBMITTING --> EXITING: 写成功 → invalidate → onOpenChange(false)
  SUBMITTING --> OPEN: 写失败 → toast.error，停留并保留输入
  OPEN --> EXITING: IconX / DialogClose / ESC / 遮罩点击
  EXITING --> UNMOUNTED: fade-out-0 / zoom-out-95 完成
  note right of SUBMITTING
    ConfirmDialog 用 loading 禁用双按钮；
    业务表单用 isSubmitting
  end note
```

### 尺寸与响应式兼容矩阵
| 断点 | `Dialog` 默认（`dialog.tsx:70`） | `AlertDialog`（`alert-dialog.tsx:61`） | `Sheet`（`sheet.tsx:64`） |
|------|--------------------------------|--------------------------------------|--------------------------|
| `< 640px` | `w-[calc(100%-2rem)]`、`max-w-md`、`max-h-[calc(100dvh-1rem)]` | `w-full`、`max-w-xs`、同上限 | 按 `side` 贴边，`bg-popover` |
| `≥ 640px`（`sm:`） | `sm:max-h-[calc(100dvh-2rem)]` | `data-[size=default]:sm:max-w-md` | 同左 |
| `size="sm"` | — | `max-w-xs`（不放大） | — |
| 高度溢出 | `overflow-y-auto` + `overflow-x-hidden` | 同左 | `flex flex-col` |
| 圆角 | `rounded-4xl` | `rounded-4xl` | 由 `data-side` 决定 |
| 遮罩模糊 | 可关（`disableBackdropBlur`） | 固定 `backdrop-blur-sm` | 固定 |

业务侧覆写宽度的实测取值分布（18 个 `DialogContent`/`AlertDialogContent` 实例、19 个宽度声明，`certificates` 的一个实例同时写了 `max-w-3xl` 与 `sm:max-w-2xl`）：`max-w-md` 4 处、`max-w-lg` 2 处、`max-w-xl` 2 处、`max-w-2xl` 3 处、`max-w-3xl` 3 处、`max-w-4xl` 2 处、`max-w-5xl` 3 处。其中 `max-w-5xl` 全部来自两个详情对话框的报文全屏视图与 JS 插件编辑器（`sm:max-w-5xl`）。

值得注意的反例：`site-form-dialog.tsx:251` 用的是 `max-h-[85vh]` 而非原语默认的 `calc(100dvh-…)` 表达，`listeners-tab.tsx:101` 用 `max-h-[90vh]`，两个插件编辑器用 `max-h-[90dvh]`。三种写法语义接近但基准不同（`vh` 含移动端地址栏，`dvh` 随视口动态变化），在移动端浏览器上会出现高度抖动。

### 表单校验在对话框中的实现
以 `SiteFormDialog` 为范式，五步固定流程：

1. **schema 定义在组件外**：`siteFormSchema`（`site-form-dialog.tsx:64-108`），错误消息写 i18n key（如 `sites.form.portRange`），不写死中文。
2. **哨兵值处理「无选择」**：Radix `Select` 拒收空串 value，故定义 `CERT_NONE = "none"` 与 `POLICY_INHERIT = "inherit-default"`（`:48-49`），提交前转回 `undefined`/`null`（`:211`）。
3. **打开时才拉引用数据**：`useCertificates(open)`、`usePolicies(open)`（`:145-146`），低频数据不常驻请求。
4. **以 open 驱动 reset，而非受控 value**：`useEffect` 仅在 `open` 为真时把 `site` 映射进表单或回落 `EMPTY_VALUES`（`:171-195`）。
5. **提交后先失效再关闭**：`await invalidateSiteCaches(savedSiteId)` 然后 `onOpenChange(false)`（`:238-239`），保证关闭瞬间列表已是新值。

跨字段校验也有实例：任一监听启用 TLS 则必须绑定证书，用 `z.refine` 挂在 `cert_id` 路径上（`:105-108`），与后端 `shared.ValidateSiteTLSCertificate` 对齐。

另一种做法是**不用 effect**：`lua-plugins/components/plugin-editor-dialog.tsx:133-138` 的注释说明表单态只在挂载时由 `editing` 初始化，父级每次打开换 `key` 强制重挂载，从而避开在 effect 里 `setState` 触发级联渲染。

## 性能考虑
- 动画时长统一 `duration-100`（`dialog.tsx:45`、`:70`，`alert-dialog.tsx:39`、`:61`），遮罩与面板同拍，避免两层过渡叠加导致的视觉拖影。
- 惰性挂载：Radix 在 `open` 为假时不渲染 Portal 内容，`animate-out` 结束后卸载，关闭即释放 DOM。
- 滚动隔离：内容区 `overflow-x-hidden overflow-y-auto` 并限定 `max-h`（`dialog.tsx:70`），长表单不会撑破视口，也避免 body 滚动联动。
- 大对话框拆格：`PluginEditorDialog` 用 `grid grid-rows-[auto_minmax(0,1fr)_auto] gap-0 p-0` + `max-h-[90dvh]`（`plugin-editor-dialog.tsx`），把滚动限制在中间行，头尾固定。
- 按需取数：低频引用数据只在 `open` 为真时请求（`site-form-dialog.tsx:145-146`），避免每个列表页常驻两份额外请求。

## 结论
本项目的对话框体系以「Radix 行为 + 极薄封装 + 明确契约」为骨架：

- **单一职责**：原语只管容器与无障碍，不管业务；`ConfirmDialog` 只管确认，不管写；业务对话框只管自己的表单与提交。
- **开闭原则**：新增对话框只需组合 `Dialog` + `DialogHeader/Title/Description/Footer`，或包一层 `ConfirmDialog`；需要新尺寸时改 `className` 的 `max-w-*`，实测 7 档宽度就是这样演化的。
- **杜绝重复**：`open`/`onOpenChange` 双 prop 契约在 12 个业务对话框中完全一致；写后失效统一走 `invalidate*` 函数族而非各页自拼 `mutate`。
- **简洁优先**：Portal 与 Overlay 被内联进 `DialogContent`，业务代码不必记忆 Radix 的组合顺序。

已知偏差：`AlertDialog` 的 `Media` 槽位（`alert-dialog.tsx:102-116`）在本仓库尚无使用者，`ConfirmDialog` 未开放该槽位，属于预留而非在用能力。
