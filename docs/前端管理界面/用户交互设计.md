## 简介
本文件聚焦 My-OpenWaf 管理面板的用户交互设计，系统梳理前端在表单验证、错误处理、加载与空状态、成功反馈、认证会话生命周期、无障碍支持等方面的实现。分析基于站点管理页、登录页、通用交互组件与 API 客户端封装的真实代码，为开发者与产品人员理解现有交互体系、并在后续迭代中保持一致性提供参考。

交互能力遵循四条主线：客户端以 `react-hook-form` + `zod` 做即时校验，服务端错误由统一的 `ApiError` 承载并转成通知提示，加载与空态由 `DataTable` / `EmptyState` 统一呈现，会话状态由 `useAuth` 控制器与 `AuthGate` 路由闸门协同维护。

## 项目结构
前端采用 Next.js App Router 结构，且以静态导出（`output: "export"`）方式嵌入后端二进制。根布局 `app/layout.tsx` 不做字体注入，仅按 `ThemeProvider → I18nProvider → AuthProvider → TooltipProvider` 顺序包裹子树，并在末尾挂载 `Toaster`（位置 `top-center`）。业务页面位于 `app/(dashboard)` 下，通用交互组件位于 `components`，原子 UI 组件位于 `components/ui`，认证与请求逻辑封装在 `hooks` 与 `lib`。

## 详细组件分析

### 表单验证与实时反馈
- 客户端校验：站点表单以 `useForm({ resolver: zodResolver(siteFormSchema) })` 驱动。`siteFormSchema` 用 `zod` 声明必填与格式：域名解析后非空、端口必须是 1–65535 的数字串、上游列表至少一项且 scheme 必须命中允许集合，并用跨字段 `refine` 表达“启用 TLS 的监听必须绑定证书”。校验失败信息以 i18n 文案键（如 `sites.form.hostRequired`、`sites.form.portRange`）呈现，绑定到对应字段实现内联提示。
- 登录校验：登录页在提交前对用户名/密码做非空判断，任一为空即 `toast.error` 提示并 `return`，不发起请求。
- 提交态：`formState.isSubmitting` / `loading` 期间禁用提交按钮并切换文案，防止重复提交。
- 成功反馈：创建/更新成功后调用 `toast.success`，随后 `invalidateSiteCaches(savedSiteId)` 并 `onOpenChange(false)` 关闭对话框。

流程步骤如下表：

| 步序 | 交互动作 | 触发实现 | 反馈 |
|:----:|----------|----------|------|
| 1 | 打开表单对话框 | `setShowForm(true)`，`useCertificates(open)` 懒加载引用 | 对话框弹出 |
| 2 | 填写并失焦校验 | `react-hook-form` `register` + `zod` | 字段级内联错误 |
| 3 | 提交前拦截 | `handleSubmit(onSubmit)` | 校验不过则不发起请求 |
| 4 | 发起写请求 | `siteApi.create` / `.update`（POST） | 按钮禁用 + `isSubmitting` |
| 5 | 成功回流 | `toast.success` → `invalidateSiteCaches` → 关闭 | 列表缓存失效自动刷新 |
| 6 | 失败回流 | `catch` 中 `toast.error(err.message)` | 保留输入便于重试 |

### 错误处理策略
`lib/api.ts` 的 `apiRequest` 是唯一错误出口：当 `!response.ok` 时抛出 `ApiError(status, data?.error ?? "请求失败: {status}", data)`。需要订正的是——它并未对 403/429/4xx 做前端硬编码分类映射，而是统一透传后端 `error` 文案，由调用方（`toast.error(err.message)`）呈现；唯一被特殊处理的是 401（见下节刷新流程）。空态兜底同样在组件层落实：`DataTable` 在 `data` 为空时回落 `EmptyState`，避免“空列表即崩溃”。破坏性操作通过 `ConfirmDialog` 二次确认，其“确认”按钮采用 `bg-destructive` 警示配色，`loading` 时同时禁用取消与确认并显示“处理中”。

### 认证会话与令牌刷新
会话生命周期由 `useAuthController` 管理：access token 存于 `localStorage`（键 `token` / `token_expires_at`），refresh token 为 HttpOnly Cookie（请求带 `credentials: "include"`）。控制器在到期前 60 秒（`REFRESH_LEAD_MS`）预约刷新，失败原因区分 `unauthorized`（清令牌、置空用户）与 `unavailable`（网络/5xx，保留令牌并 30 秒后重试），避免把一次故障误判为登出。`apiRequest` 在 401 时先比对跨标签页是否已轮换令牌再决定是否刷新；仅当刷新明确 `unauthorized` 才 `clearToken()` 并 `window.location.href = "/login"`。`AuthGate` 在确认前不挂载业务子树，渲染 `role="status" aria-live="polite"` 的加载态。

### 加载与空状态体验
`DataTable` 将“加载中/空/有数据”收敛为单一组件三态：加载时保留真实表头并以 6 行 `Skeleton`（宽度循环 `w-4/5/w-3/5/...`）占位，避免数据到达时的列宽抖动；空数据回落 `EmptyState`（默认 `IconInbox` 图标），并允许调用方传入自定义 `emptyContent`。站点列表页额外用 `useSites` 的 `isLoading` / `error` 驱动骨架与 `Alert` 错误条，`MetricTile` 承载统计指标；视图偏好（表格/网格）通过 `useSyncExternalStore` + `localStorage` 键 `owaf.sites.view` 持久化，以规避静态导出的水合不一致。

## 性能考虑
- 懒加载引用数据：证书/策略下拉仅在对话框 `open` 时请求，减少页面初始网络量。
- 缓存失效优于整表重拉：写操作后按 `invalidateSiteCaches` 精确失效相关 SWR 键。
- 认证请求去重：同一 access token 的 `/auth/me` 只保留一个在途 Promise，多页面共享。
- 骨架代替空白：`DataTable` 加载态保留真实表头，降低布局抖动与感知延迟。

## 结论
该交互体系以 `react-hook-form` + `zod` 的客户端校验、`api.ts` 的统一 `ApiError` 模型、`DataTable`/`EmptyState`/`ConfirmDialog` 的组合式反馈，以及 `useAuth`/`AuthGate` 的会话生命周期协同为核心，覆盖了验证、错误、加载、空态、成功提示与无障碍等关键面。相比引入通用 CRUD 巨石抽象，本仓库坚持“按场景组合原子组件”的路线，更易维护也更贴合静态导出约束。后续可在全局批量选择与拖拽排序上增强，同时保持既有的键盘可达性不回退。
