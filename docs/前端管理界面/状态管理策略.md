## 简介

本篇描述管理前端的**状态分层、缓存键空间与失效机制**，以及六个 `hooks/` 模块各自承载的
职责。页面渲染策略与服务端契约分别见
[Next.js 架构设计](Next.js%20架构设计/Next.js%20架构设计.md) 与
[API 集成](API%20集成.md)，组件如何消费这些状态见
[组件设计模式](组件设计模式/组件设计模式.md)，本篇不重复其结构。

四条基本结论先行：

- **没有全局状态库**。未引入 Redux / Zustand / MobX / Recoil / Context 大杂烩；跨页面共享的
  只有认证会话与多标签工作区两个 React Context
- **服务端状态与客户端状态严格分离**。所有远端数据经 SWR 缓存在 `hooks/use-api.ts` 一处管理，
  组件不自行 `fetch`
- **失效靠具名函数 + 键前缀匹配**，不是「调用 `load()` 重新拉取」。实测 5 个具名失效函数
  （`invalidateAllAPICaches`、`invalidateIPListCaches`、`invalidateSiteCaches`、
  `invalidateCVERuleCaches`、`invalidateOWASPRuleCaches`）加上 `useMutation` 的
  `invalidateKeys` 声明式参数
- **持久化只有浏览器存储与 HttpOnly Cookie 两类**，前端不落 IndexedDB，也没有离线队列

## 详细组件分析

### SWR 键空间与失效函数

键一律写成数组形式 `[前缀, ...作用域]`，前缀决定归属哪一类失效。实测 `use-api.ts` 内出现
**74 个不同字符串键前缀**（读侧与失效侧并集），另有 `use-env-overrides.ts` 的 `env-overrides`。
前缀匹配由 `matchesPrefix` 完成：字符串键等值，或数组键首元素等值
（[use-api.ts:173-178](file://frontend/hooks/use-api.ts#L173-L178)）；
`revalidatePrefixes` 对每个前缀并行发起一次 `mutate(..., { revalidate: true })`
（[:180-188](file://frontend/hooks/use-api.ts#L180-L188)）。

### 服务端缓存与状态一致性

前端缓存不是唯一一层。后端另有两处，语义不同，排查时必须分开：

| 层 | 位置:行 | 键 | 淘汰 | 与前端的关系 |
|------|------|------|------|------|
| 响应缓存 | [response_cache.go:13-35](file://internal/cache/response_cache.go#L13-L35) | 条目含 `StatusCode`/`ContentType`/`Body`/`TTL`/`SiteID` | TTL + 分片互斥（64 分片，[:48-56](file://internal/cache/response_cache.go#L48-L56)） | 数据面缓存上游 GET 响应，与管理端 API 无交集 |
| 快照缓存层 | [layer.go:19-35](file://internal/cache/layer.go#L19-L35) | `snapshot:{revision}`（[:41-56](file://internal/cache/layer.go#L41-L56)） | ristretto，`MaxCost 1<<20`；跨节点走 Redis pub/sub 重载 | 决定 `/runtime-config` 读到的生效值 |
| SWR 内存缓存 | [use-api.ts:156](file://frontend/hooks/use-api.ts#L156) | 数组键 | 显式失效 + 轮询 | 前端唯一远端态 |
| 管理端 `no-store` | [middleware.go:180-186](file://internal/admin/middleware.go#L180-L186) | - | - | 禁止浏览器/代理缓存 `/api/v1/` |

一致性链路：管理员保存 → POST 成功 → 后端触发 reload → 前端 `revalidatePrefixes` 重取
→ 新快照经 `["runtime-config"]` 等键回流。备份导入是例外，走
`invalidateAllAPICaches()` 全量清空（[backup/page.tsx:123](file://frontend/app/(dashboard)/backup/page.tsx#L123)）。
环境变量覆盖写入后，除了回写自身键，还会显式重验 `runtime-config`
（[use-env-overrides.ts:102-104](file://frontend/hooks/use-env-overrides.ts#L102-L104)）。

环境变量覆盖视图是唯一的「写后不回读」例外：`useEnvOverrides` 用后端返回的完整快照直接
灌入 SWR 缓存（`revalidate: false`），因为该响应本身就是写后回读结果（[use-env-overrides.ts:96-114](file://frontend/hooks/use-env-overrides.ts#L96-L114)）。
前端的键注册表 `ENV_OVERRIDE_KEYS` 是 9 个域共 45 键的镜像
（[env-override.ts:22-45](file://frontend/lib/env-override.ts#L22-L45)），仅决定「哪个键渲染在哪张卡」，
每个键的生效值、来源（`env` / `db` / `default`）与只读性一律取自后端 items
（[use-env-overrides.ts:16-47](file://frontend/hooks/use-env-overrides.ts#L16-L47)），因此不构成第二配置源。

## 结论

本次迭代成果：把状态管理篇从「主题 + 缓存的泛谈」重构为可核对的分层契约，交付状态分层表、
SWR 键与失效函数表、具名失效函数差异表、hooks 清单表、查询选项档位表、轮询表、浏览器存储键清单、
服务端缓存对照表、依赖约束表、故障排查表与反模式清单，共 11 张。

订正清单：

- 访问令牌「存储于模块闭包」→ 实为 `localStorage` 的 `token` 与 `token_expires_at`，
  刷新令牌为 HttpOnly Cookie `my_openwaf_rt`
- 「列表刷新调用 `load()`」→ 实为 5 个具名失效函数 + `useMutation` 的 `invalidateKeys`
- 仪表板「`setInterval` 15 秒」→ 实为 SWR `refreshInterval`（10/15/20/30 秒分档）
- CRUD 模板 / `ConsoleShell` / `CrudPage` 等不存在的组件叙述 → 改为 `PageHeader` + `DataTable`
  + `TablePagination` + `ConfirmDialog` 的组合式，见
  [组件设计模式/CRUD 页面组件](组件设计模式/CRUD%20页面组件.md)
- 认证「密钥轮换」等旧路径已对齐到 `internal/admin/middleware.go` 与
  `internal/admin/auth/jwt.go` 的现行实现
- 新增 `use-env-overrides.ts` 的 `env-overrides` 键与写后直读快照模式，旧稿完全缺失
- 如实登记 `useIsAuthenticated`、`useTabWorkspace` 无调用方与 `routeTitleKeyMap` 缺
  `/tls-fingerprints` 三处不一致

设计原则落点：SRP——六个 hooks 各管一类状态，互不重叠；OCP——新增远端数据只需在 `use-api.ts`
加键与失效前缀，不改组件；I——页面依赖 `useXxx` 抽象而非 `lib/api.ts` 具体函数；
KISS——不引入状态库，Context 只留两个真正全局的；YAGNI——不做乐观更新、不做离线队列、
不做 IndexedDB。

下一步：把 SWR 键与失效前缀的对应关系做成静态校验脚本（类似
`check:api-route-contract`），在 CI 中捕获「新增了键但没有失效入口」的漂移。

## 附录

### 新增一份远端数据的标准流程

1. 在 `lib/api.ts` 对应命名空间补请求方法（读 `get<T>`、写 `post<T>`）。
2. 在 `lib/types.ts` 补 snake_case 类型，可空字段用 `| null`。
3. 在 `hooks/use-api.ts` 加 `useXxx`，键写成 `[前缀, 作用域...]`；作用域 ID 必须过 `cacheId` 归一。
4. 选定查询选项：低频选择器用 `REFERENCE_QUERY_OPTIONS`，可写列表用 `RULE_QUERY_OPTIONS`，
   无作用域标识用 `STRICT_RULE_QUERY_OPTIONS`。
5. 加写侧 `useMutation`，在 `invalidateKeys` 里列出全部受影响前缀；若需要跨作用域连带，
   复用既有 5 个具名失效函数而不是新造。
6. 页面只消费 `{ data, isLoading, error }`，不自行 `fetch`，也不在 `useEffect` 里 setState 同步。
7. 需要持久化 UI 偏好时，用 `useSyncExternalStore` 三件套，参照 `owaf.sites.view` 的实现。
