## 核心组件

主题系统由四个可独立替换的部件构成，各自职责不重叠：

| 组件 | 类型 | 输入 | 输出 | 失败语义 |
|------|------|------|------|----------|
| `ThemeProvider` | next-themes 包装 | `ComponentProps` | `<html>` 上的 `dark` class | 未挂载则 `.dark` 变量永不生效 |
| `ThemeHotkey` | 副作用组件（返回 `null`） | `keydown` 事件 | `setTheme(light\|dark)` | 输入态直接忽略 |
| `ThemeToggle` | 受控按钮 | `resolvedTheme` | 图标 + `setTheme` | 挂载前不渲染图标 |
| `AccentToggle` | 受控按钮 | `localStorage["owaf.accent"]` | `documentElement.dataset.accent` | 写失败静默忽略 |
| `globals.css` | 令牌源 | CSS 自定义属性 | `--color-*` → 工具类 | 变量缺失回落默认色 |
| `cn()` | 类名合并 | `ClassValue[]` | 去冲突字符串 | 不校验类名合法性 |
| `actionBadgeClass()` | 语义映射 | 后端动作串 | Tailwind 类串 | 未知动作归 `unknown` |

`ThemeHotkey` 挂在 Provider 内部、`children` 之前（[theme-provider.tsx:18-19](file://frontend/components/theme-provider.tsx#L18-L19)），
因此它自身不渲染任何 DOM，只是快捷键的宿主。

## 架构总览

令牌到像素只有一跳半：CSS 自定义属性 → `@theme inline` 映射 → Tailwind 生成工具类 → 组件类串。
`inline` 关键字是关键：它让 `--color-primary` 直接**引用** `var(--primary)`，而不是在构建期把值
固化下来，因此运行时改 `--primary` 即可级联生效。

```mermaid
flowchart TD
  A[":root / .dark / [data-accent=blue]<br/>定义 --primary 等原始变量"] --> B["@theme inline<br/>--color-primary: var(--primary)"]
  B --> C["Tailwind v4 生成工具类<br/>bg-primary · text-primary-foreground · border-border"]
  A --> B2["@theme inline<br/>--radius-sm … --radius-4xl"]
  B2 --> C2["rounded-4xl · rounded-3xl"]
  A --> B3["@theme inline<br/>--font-sans / --font-mono / --font-heading"]
```

### 暗色模式与强调色的落地位置

暗色的开关是 `<html>` 上的 `class`：Provider 显式设 `attribute="class"`、`defaultTheme="system"`、
`enableSystem`、`disableTransitionOnChange`（[theme-provider.tsx:11-16](file://frontend/components/theme-provider.tsx#L11-L16)）；
Tailwind 侧用 `@custom-variant dark (&:is(.dark *))` 把 `dark:` 前缀绑定到同一个 class
（[globals.css:5](file://frontend/app/globals.css#L5)）。两者必须一致，否则 `dark:` 类与 `.dark` 变量块
会各自失效。

强调色是**与明暗正交的第二轴**，不走 next-themes，而走 `documentElement.dataset.accent`：


## 性能考虑

- **无字体下载**：三档字体全为系统栈（[globals.css:8-10](file://frontend/app/globals.css#L8-L10)），
  因此没有 FOUT/FOIT，也不产生额外请求。代价是跨平台字形不完全一致。
- **切主题不补间**：`disableTransitionOnChange`（[theme-provider.tsx:15](file://frontend/components/theme-provider.tsx#L15)）
  避免整屏颜色过渡触发的重排与合成层放大。
- **变量级联替代类名切换**：强调色只改一个 `data-accent` 属性

  自定义属性，无需遍历组件树。
- **动画类按需**：只有开合类元素引入 `tw-animate-css`（[dialog.tsx:45](file://frontend/components/ui/dialog.tsx#L45)），
  列表与表格不参与入场动画。
- **静态导出没有运行时样式注入**：`output: "export"` 意味着首屏 CSS 即最终 CSS
  （[next.config.ts:4](file://frontend/next.config.ts#L4)），没有 Server Components 的样式流。
- **`cn()` 的成本**：`twMerge(clsx(...))` 每次渲染都会解析类串（[utils.ts:4-6](file://frontend/lib/utils.ts#L4-L6)），
  因此类串应尽量留在 `cva` 常量里，而不是在渲染函数中临时拼接。
- **图标体积**：`optimizePackageImports` 列了 `lucide-react`，但项目实际只用
  `@tabler/icons-react`（[next.config.ts:11-13](file://frontend/next.config.ts#L11-L13)、
  [package.json:27](file://frontend/package.json#L27)）；该冗余项已登记，不影响样式，但会误导摇树配置。

## 结论

本次迭代成果：

- 主题篇从 2 类图补到 3 类（`graph` + `flowchart` + `sequenceDiagram`），并交付任务要求的三张
  必备表：逐变量**设计令牌表**（26 行，含亮/暗取值与消费行号）、17 行**组件样式约定表**、
  以及**断点/暗色/浏览器兼容矩阵**（12 项断点与开关 + 6 项现代 CSS 特性依赖）；全篇共 11 张表
- 订正旧稿的三处硬错：其一「通过 `next/font/google` 注入 Geist Sans / Geist Mono」——实测根布局
  **不导入 `next/font`、也没有 `metadata` 导出**，字体是 `@theme inline` 里的系统栈；
  其二把主题切换描述成 `class` 上的单一开关——实际是**明暗轴（`.dark`）与强调色轴
  （`data-accent`）两轴正交**；其三旧稿引用了不存在的 `tailwind.config`——Tailwind v4 无此文件
- 补齐旧稿完全缺失的三块：`@theme inline` 的 `inline` 语义（运行时引用而非构建期固化）、
  `--radius` 乘算阶梯、以及 `lib/action-style.ts` 这层「业务语义样式」
- 与已完成文档划清边界：技术栈矩阵、配置矩阵、样式装配链路、主题解析状态机、四态兼容矩阵、
  图表令牌常量表、Button 变体表均改为链接引用，不再复制

设计原则落点：**DRY**——颜色只存于 `globals.css`，动作色只存于 `action-style.ts`，标题文本只存于
`route-titles.ts`；**KISS**——不引入 CSS-in-JS、不引入主题对象运行时，靠 CSS 自定义属性一层解决；
**SRP**——`theme-provider` 只管解析与快捷键、`appearance-toggle` 只管控件、`chart-theme` 只管 recharts
边界；**OCP**——新增强调色只需追加一对选择器块，不动任何组件。

遇到的问题与解决方式：`appearance-toggle.tsx` 的强调色应用时机与静态导出水合规则相互制约——若在
初值读取 `localStorage` 会水合不一致，若在 effect 里 `setState` 会级联渲染。核对代码后确认现方案
（初值固定 `teal` + 挂载后读并直接写 DOM dataset）是有意为之，本篇按现状记录并注明动机，
不做「改进」建议。另发现 `optimizePackageImports` 中 `lucide-react` 未声明却残留，已如实登记。

下一步：把设计令牌表纳入 `check:*` 脚本的比对范围，确保新增 `--*` 变量在 `.dark` 与
`[data-accent="blue"]` 两处的覆盖完整性可自动校验。

   （[:7-49](file://frontend/app/globals.css#L7-L49)）；只给图表用时**不要**加工具类，直接 `var(--x)`。
