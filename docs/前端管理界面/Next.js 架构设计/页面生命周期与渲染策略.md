## 简介

本文件说明 My-OpenWaf 前端页面从被请求到完成渲染的实际生命周期。因为 `next.config.ts` 设定 `output: "export"`，本项目不存在服务端渲染与流式组件，"渲染策略"这个词在本仓库里的真实含义是：**静态 HTML 何时产生、客户端何时接管、状态何时确定**。

三条与直觉相反的实测结论必须先讲清楚：

1. **首页不做登录判断**。`frontend/app/page.tsx` 只输出一条 `<meta httpEquiv="refresh" content="0; url=/dashboard/">` 与一个降级链接，无条件跳转；是否未登录由 `AuthGate` 在 `/dashboard/` 一侧决定。
2. **站点详情不是动态段路由**。实际路径是 `/sites/detail/?id=<站点ID>&tab=<页签>`，`id` 与 `tab` 都由 `useSearchParams()` 读取，并带白名单校验。不存在 `sites/[id]/client.tsx`。
3. **仪表板不用 `setInterval`**。数据刷新由 SWR 的 `refreshInterval` 驱动（摘要 10 秒、统计 30 秒），页面里的 `useEffect` 只负责把新到的数据追加进 QPS 环形缓冲。

### 错误边界体系

三层边界按覆盖范围递进，实测存在：

| 边界 | 文件 | 覆盖范围 | 是否自带布局 | 生产日志 |
|------|------|----------|:------------:|:--------:|
| `GlobalError` | `frontend/app/global-error.tsx` | 根布局自身抛错 | 是，重渲 `<html>` 与 `<body>` | `console.error("[GlobalError]")` |
| `Error` | `frontend/app/error.tsx` | 根布局以下任意子树 | 否，沿用现有布局 | `console.error("[Error Boundary]")` |

### 渲染策略兼容矩阵

`output: "export"` 直接决定哪些 Next 能力可用：

| 能力 | 本项目 | 替代做法 | 备注 |
|------|:------:|----------|------|
| Server Component 取数 | ✗ | 客户端 SWR | 无服务端运行时 |
| `generateStaticParams` | ✗ | 查询参数路由 | 详情数据在运行时才知 |
| 动态段 `[id]` | ✗ | `?id=` 读取 | 静态产物无法为未知 ID 生成页面 |
| `middleware.ts` 重写 | ✗ | 服务端 Go 侧解析候选 | 无 Node 运行时 |
| `next/image` 优化服务 | 部分 | 产物为原始资源 | 无 image loader 服务 |
| `route handlers` | ✗ | Go `admin` 各域 handler | API 全部由后端提供 |
| `cookies()` 服务端读取 | ✗ | 客户端 `localStorage`/`sessionStorage` | 刷新令牌 Cookie 前端不可读 |
| `Suspense` 流式 | 部分 | 仅用于 `useSearchParams` 的客户端边界 | 见下节 |

`部分` 项的含义：`next/image` 与 `Suspense` 语法可用，但语义受限——前者没有优化服务后端，后者不会跨网络流式推送，只是客户端的等待边界。

### Suspense 边界的两处必要用法

仪表板布局把 `TabWorkspaceProvider` 包在 `<Suspense fallback={null}>` 内，站点详情页把主体包在 `<Suspense fallback={<SiteDetailSkeleton />}>` 内。两处原因相同：组件树调用了 `useSearchParams()`。

| 位置 | 包裹对象 | fallback | 触发原因 |
|------|----------|----------|----------|
| `app/(dashboard)/layout.tsx:25-32` | `TabWorkspaceProvider` | `null` | 内部使用 `usePathname` + `useSearchParams` |
| `app/(dashboard)/sites/detail/page.tsx:314-316` | 详情主体 | 骨架屏 | 内部使用 `useSearchParams` 读取 `id` 与 `tab` |

`fallback={null}` 的选择是有意的：标签条出现与否不该影响首屏可读性，用 `null` 可避免布局跳动。

### 参数化详情路由的处理流程

| 序 | 步骤 | 实现 | 校验 |
|:--:|------|------|------|
| 1 | 读取查询串 | `useSearchParams()` | 缺失时 `siteId` 为空串 |
| 2 | 取站点标识 | `searchParams.get("id")` | 空则不发起请求 |
| 3 | 取页签 | `searchParams.get("tab")` | 必须在 `ALLOWED_TABS` 白名单内 |
| 4 | 回退页签 | 白名单不命中取默认值 | 避免任意字符串渲染未知页签 |
| 5 | 写回 URL | `router.replace(pathname?params)` | 用 `replace` 不污染历史栈 |
| 6 | 数据请求 | `useSite(id)`，缓存键 `["site", id]` | `cacheId()` 归一化空值与空白 |

### 仪表板的数据刷新与 QPS 环形缓冲

仪表板的刷新全部由 SWR 声明式驱动：

| Hook | 缓存键 | `refreshInterval` | 其他选项 |
|------|--------|:-----------------:|----------|
| `useDashboard` | `["dashboard"]` | `10000` | 摘要与 QPS |
| `useDashboardStats` | `["dashboard-stats", {hours}]` | `30000` | 统计聚合 |
| `useSecurityEventTimeline` | `["security-event-timeline", {hours}]` | 无 | 随 `hours` 变化重验 |

组件内的 `useEffect` 只做一件事：`data` 更新时向 `qpsHistoryRef` 追加一个采样点，超过 `MAX_QPS_POINTS`（60）从头部截断，再 `setQpsHistory([...history])` 触发渲染。参考时间是 `HH:mm:ss` 本地串，不做时区换算。

### 认证与会话的生命周期事件

控制器在挂载时注册三类浏览器事件，卸载时全部注销，并清理续期定时器：

| 事件 | 回调 | 节流 | 处理 |
|------|------|:----:|------|
| `window` `focus` | `onResume` | 30 秒（`RESUME_CHECK_INTERVAL_MS`） | `loadSession(true)` |
| `document` `visibilitychange` | `onResume` | 同上 | 隐藏态直接返回 |
| `window` `storage` | `onStorage` | 无 | 令牌键变化立即重载；到期键变化忽略 |
| 定时器 | `scheduleRefresh` | 到期前 60 秒 | 失败按 30 秒重试 |

跨标签页时不信任 `StorageEvent.newValue`：事件可能滞后于共享存储的真实状态，因此一律重新 `getAccessToken()`；令牌与到期时间是两次独立写入，所以从令牌自身解析 `exp`。

### 实时订阅的生命周期

`use-realtime.ts` 的两个 hook 结构对称，都遵循同一套建连—换票—退避循环：

| 阶段 | 条件 | 参数 | 退出判据 |
|------|------|------|----------|
| 建连前置 | 无 `window` 直接返回 | — | 静态预渲染阶段跳过 |
| 令牌检查 | 无访问令牌则放弃 | — | 避免向控制面刷无效 ticket |
| 取票 | `GET /realtime/ticket` | — | 失败进入退避 |
| 建连 | `WebSocket` 带 `ticket` 与 `topics` | `audit,heartbeat` 或 `upstreams` | — |
| 换票 | 55 秒主动关闭重连 | `REALTIME_TICKET_TTL_MS = 55000` | 服务端票期 60 秒 |
| 退避 | 异常断开后 3 秒重连 | `REALTIME_RECONNECT_DELAY_MS = 3000` | — |
| 卸载 | `closedRef` 置真并清定时器 | — | 抑制后续重连 |

订阅侧还有一层渲染抑制：`useRealtimeEvents` 用条目 ID 拼接的 `sign`（截断到 2000 字符）与上一次比较，相同则不 `setState`，因此"条目数不变"的重量快照不打断页面。

### 标签工作区的持久化周期

## 结论

本项目的页面生命周期可以压缩成一句：**构建期定形态，水合期定语言，闸门期定可见性，缓存期定新鲜度**。四层各自独立，没有跨层耦合，这使每一层都可单独测试与替换。

与常见 Next.js 实践的主要差异来自静态导出约束：不要为首页补客户端跳转逻辑（`AuthGate` 已覆盖），不要引入 `[id]` 动态段（详情用查询参数），不要用 `setInterval` 自建轮询（交给 SWR 声明）。
