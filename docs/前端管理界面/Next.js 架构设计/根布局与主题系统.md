## 简介

本文件说明 My-OpenWaf 前端根布局与主题系统的真实实现。主题系统由两条**互相正交**的轴组成：

- **明暗轴**：由 `next-themes` 承载，写入 `<html>` 的 `class`（`light` / `dark`），来源可以是用户选择、系统偏好或默认值。
- **强调色轴**：由 `frontend/components/appearance-toggle.tsx` 的 `AccentToggle` 承载，写入 `<html>` 的 `data-accent`（缺省即青绿，`blue` 即蓝色），持久化在 `localStorage` 的 `owaf.accent`。

两轴在 CSS 中组合成四种取值空间，因此样式表用 `.dark[data-accent="blue"]` 这类复合选择器表达第四态，而不是把蓝色写死在 `.dark` 里。

需要澄清的两处常见误解（旧文档遗留）：

1. 根布局**没有** `metadata` 导出，也**没有**通过 `next/font` 加载任何 Web 字体。字体完全来自 CSS 中的系统字体栈。
2. 图标库是 `@tabler/icons-react`，`package.json` 中不存在 `lucide-react` 依赖。

### 图表令牌与对比度约束

图表色是主题系统最容易出错的地方，因为 recharts 需要**可直接解析的 CSS 值**。

| 导出常量 | 取值 | 约束来源 |
|----------|------|----------|
| `CHART_ACCENT` | `var(--chart-accent)` | 深色下 `--primary` 对卡面仅 2.64:1，不足 3:1 |
| `CHART_PRIMARY` | 同 `CHART_ACCENT` | 标记 `@deprecated`，仅为兼容旧引用 |
| `CHART_DANGER` | `var(--chart-danger)` | 固定红，语义恒定 |
| `CHART_DANGER_FILL` | `rgba(239, 68, 68, 0.12)` | 渐变不可用时的纯色兜底 |
| `CHART_GRID_STROKE` | `var(--border)` | 实心发丝线；虚线网格会被读作阈值线 |
| `CHART_AXIS_TICK` | `fill: var(--muted-foreground)`，`fontSize: 10` | 类型必须是 recharts `TextProps` |
| `chartTooltipStyle` | 背景 `var(--popover)`、边框 `var(--border)` | 跟随明暗与强调色 |

## 性能考虑

- **无字体下载**：三套字体栈全部为系统字体，首屏零字体请求，也不存在 FOIT/FOUT 窗口。
- **主题切换零过渡**：`disableTransitionOnChange` 避免全站同时过渡造成的长帧。
- **热键成本**：`ThemeHotkey` 只在 `window` 上挂一个 `keydown` 监听，并在回调最前判断 `defaultPrevented` 与 `repeat`，长按不会连续切换。
- **水合差异局部化**：`suppressHydrationWarning` 只加在 `<html>`，差异面限定在 next-themes 写入的 class。
- **强调色写入次数**：`AccentToggle` 在挂载 effect 中一次性读取并应用，切换时同步写 `dataset` 与 `localStorage`，无重复渲染。
- **变量而非计算色**：`@theme inline` 直接指向运行时变量，Tailwind 不需要为每个色值生成静态规则。

## 故障排查指南

### 主题不生效

1. 确认 `<html>` 上是否出现 `dark` 或 `light` class；若两者都没有，说明 `ThemeProvider` 未挂载或被 `I18nProvider` 的 `null` 分支挡住。
2. 确认 `documentElement` 上 `data-accent` 的值；`AccentToggle` 在 `mounted` 之前不写入，SSR 产物没有该属性属正常。
3. 确认 `globals.css` 已被 `app/layout.tsx` 导入，且 `postcss.config.mjs` 仍只启用 `@tailwindcss/postcss`。

| 症状 | 根因 | 处置 |
|------|------|------|
| 图表颜色回落默认色 | 写成 `hsl(var(--primary))` | 改为直接 `var(--primary)` 或 `var(--chart-accent)` |
| 深色模式折线过暗 | 复用了 `--primary` | 使用 `--chart-accent` |
| 主题切换整页闪烁 | 过渡动画未禁用 | 保留 `disableTransitionOnChange` |
| 首屏文案显示为 i18n key | 客户端初始化延迟 | 属预期，水合后恢复 |
| 强调色刷新后丢失 | `localStorage` 不可用（隐私模式） | 写入异常被吞，无法持久化 |
| 按 `d` 无反应 | 焦点在输入区或带组合键 | 由 `isTypingTarget` 过滤，属预期 |

## 结论

主题系统的实现规模很小但边界清晰：明暗交给 `next-themes`，强调色交给一个写 `dataset` 的按钮组件，颜色定义集中在单个 `globals.css`，图表色由单独模块收敛。三者之间没有交叉依赖，符合单一职责与开放封闭——新增强调色只需追加一组 `[data-accent=...]` 变量块，不必改动任何组件。

需要长期保持的三条纪律：不要用 `hsl(var(--x))` 包裹 oklch 变量；不要在 `package.json` 之外引入图标库；新增组件颜色一律取语义变量，不写死色值。
