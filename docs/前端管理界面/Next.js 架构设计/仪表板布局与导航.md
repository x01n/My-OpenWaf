## 简介

本文件描述仪表板壳层与导航系统的实现。壳层指 `frontend/app/(dashboard)/layout.tsx`，它在 URL 上不产生分段（路由组 `(dashboard)` 仅用于布局复用），负责把认证闸门、侧边栏、顶部栏、标签工作区与面包屑组合成一个稳定容器。

必须先纠正四处容易踩坑的事实：

1. **导航配置的单一来源是 `frontend/lib/route-titles.ts`**，不存在 `frontend/lib/console.ts`，也没有 `getNavMeta()` 这样的聚合查询函数。该文件导出三样东西：`routeTitleKeyMap`、`segmentKeyMap`、`getPageTitleKey()`。
2. **面包屑不在顶部栏里渲染**。`TopBar` 只渲染当前页标题；`BreadcrumbNav` 是独立组件，被布局放在 `<main>` 内、页面内容之上。
3. **图标库是 `@tabler/icons-react`**，不是 Lucide。
4. **侧边栏的折叠状态持久化在 Cookie**（`sidebar_state`，有效期 7 天），而标签工作区持久化在 `sessionStorage`，两者机制不同，排查时不要混。

### 活动态判定算法

高亮由两个纯函数决定，都以前缀匹配为基础：

| 步骤 | 函数 | 逻辑 | 目的 |
|:--:|------|------|------|
| 1 | `isChildActive` | 等于 `href` 或以 `href + "/"` 开头，再递归子项 | 判定父组是否处于活动态 |
| 2 | `isExactOrLongestActive` | 收集全部候选（含子项）中命中前缀者，取最长 `href` | 避免父级与子级同时高亮 |
| 3 | 组内聚合 | `groupActive = children.some(isChildActive)` | 决定 `Collapsible defaultOpen` |
| 4 | 样式注入 | `isActive` 传给 `SidebarMenuButton` | 触发 `data-[active=true]` |

`ACTIVE_ITEM_CLASS` 的由来值得记录：shadcn 默认活动态是 `bg-sidebar-accent`，与 `hover:bg-sidebar-accent` 完全相同，鼠标划过便无法分辨当前页。因此本页叠加 `bg-primary/10`、`text-primary` 与左侧 `w-[3px]` 指示条；子项指示条为 `w-0.5`。

### 顶部栏的权限门控

`TopBar` 中唯一的写操作入口是"重载配置"按钮，其可用性由角色决定：

| 元素 | 数据源 | 禁用条件 | 说明 |

| 重载按钮 | `useSystemReload()` | `authLoading \|\| !canManage \|\| reload.loading` | `canManage` 为 `admin` 或 `operator` |

### 面包屑的生成规则

| 规则 | 实现 | 示例 |
|------|------|------|
| 首项固定为首页 | 指向 `/dashboard`，文案 `common.home` | 所有页面均以首页起头 |
| 片段切分 | `pathname.split("/").filter(Boolean)` | `/sites/detail/` → `sites`、`detail` |
| 片段标题 | 命中 `segmentKeyMap` 取翻译，否则 `decodeURIComponent(segment)` | 数字 ID 原样显示 |
| 末项不可点 | 渲染 `BreadcrumbPage` | 当前页 |
| 中间项可点 | `href` 为前缀累加 | `/sites` |
| 分隔符包裹 | `span.contents` 保持 DOM 扁平 | 不影响 ARIA 结构 |

由于 `trailingSlash: true`，`filter(Boolean)` 会丢弃空片段，因此尾斜杠不会生成多余一级。

### 标签工作区与详情去重

`TabWorkspaceProvider` 渲染在 `Suspense` 内，因为需要 `useSearchParams()`。标题复用 `routeTitleKeyMap`，与顶栏、面包屑同一数据源。

| 机制 | 函数 | 行为 |
|------|------|------|
| 路径归一化 | `normalizePath` | 去尾斜杠、查询串按键排序 |
| 标签标识 | `tabIdentity` | 普通路径取 pathname；`/sites/detail` 额外保留 `id` |
| 固定标签 | `PINNED_PATH = /dashboard/` | 不可关闭，缺失时插到首位 |
| 关闭回落 | `closeTab` | 关闭当前激活标签时跳相邻项 |
| 可见性保持 | `ensureActiveTabVisible` + `ResizeObserver` | 只横向滚动，不改纵向位置 |

因此"同一站点切换页签"不会新增标签，而"切换到另一站点"会新增标签——这是 `tabIdentity` 的特例分支直接决定的。

## 性能考虑

- **标题解析复杂度**：`getPageTitleKey` 对 25 项做线性前缀扫描，调用点在每次路由变化的顶栏渲染，成本可忽略；若映射表扩张到百项级别再考虑按段建索引。
- **高亮计算的重复**：每个导航项独立收集候选并取最长匹配，分组数量有限（6 组），无需缓存。
- **折叠态渲染**：折叠时标题文本不进入 DOM（`!collapsed && ...`），减少布局节点。
- **标签滚动**：用 `ResizeObserver` 而非窗口 `resize`，容器宽度变化即响应，避免整页监听。
- **Cookie 写入**：开合状态写 Cookie 是为了跨标签页与刷新保持，代价是每次切换产生一次 `document.cookie` 赋值，频率极低。

## 结论

导航系统的一致性来自一个决定：**路径到文案的映射只有一份**。顶栏、面包屑、标签条三者各自取用同一模块，因此新增页面只需两处补表即可全线同步，符合 DRY 与开放封闭。

职责划分同样清晰：`ui/sidebar.tsx` 只管容器行为（宽度、折叠、断点、快捷键），`sidebar-nav.tsx` 只管导航语义（分组、图标、匹配），业务页面不参与导航渲染。

一处应记录的冗余：`AppSidebar` 页脚写死 `v1.0.0`，与 `package.json` 的 `0.0.1` 不一致，属需要统一版本的显示项。
