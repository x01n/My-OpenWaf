## 简介
本文件系统性梳理 My-OpenWaf 的安全机制与实现，覆盖以下主题：
- 认证与令牌：JWT 签发校验、刷新令牌轮换与吊销、黑名单 fail-closed
- API 令牌管理：一次性明文生成、bcrypt 哈希存储、角色归属
- 会话与访问控制：中间件链、白名单路径、访问日志与安全头
- 请求溯源：客户端 IP 解析、可信网段前提、出站转发头重建
- 访问判定：IP 信誉黑白名单与自动封禁、站点访问控制网关、登录暴力破解锁定
- 出站安全控制：上游协议白名单、请求净化、连接池与 TLS 装配
- 审计与事件：安全事件缓冲与异步批量写入
- 响应处置：拦截页与维护页渲染、速率限制

同时明确能力边界：**入站检测**由引擎阶段链承担（见 [安全防护功能](../安全防护功能/安全防护功能.md)），本文只覆盖认证、溯源、出站治理与审计。出站方向上，内网/回环/链路本地/云元数据地址拦截、重定向逐跳复校验、DNS 解析结果比对这三项在当前代码中没有实现，逐项证据见 [出站安全控制](出站安全控制.md) 的「SSRF 防护的真实覆盖面」。

## 项目结构
安全能力按职责分层，不按技术栈堆叠：

- 管理面认证层：`internal/admin` 与 `internal/admin/auth`
- 安全工具层：`internal/security`（IP 解析、转发头重建、Host 规范化）
- 访问判定层：`internal/waf/iprep`、`internal/waf/accessgate`、`internal/waf/ratelimit`
- 出站治理层：`internal/proxy`（请求构建与净化）与 `internal/proxy/transport`（连接池）
- 处置渲染层：`internal/waf/pages`
- 审计层：`internal/observability`
- 模型层：`internal/store/auth` 与 `internal/store/repository/authn`

## 核心组件
- 令牌管理器 `TokenManager`：HS256 签发与校验、主备密钥轮换、持久化黑名单 fail-closed
- 会话管理器 `SessionManager`：内存与数据库双写，按 JTI 跟踪活跃会话
- 暴力破解检测器 `BruteForceDetector`：纯 IP 与 `IP|用户名` 双维度计数
- API 令牌仓库 `AdminAPIKeyRepo`：32 字节随机明文一次性返回、bcrypt 哈希、前缀快路径
- 客户端 IP 解析器 `ResolveClientIP`：模式与可信网段的合取前提，按头优先级取第一个有效地址
- 出站净化器与转发头重建器：`sanitizeUpstreamHeaders` + `RebuildOutboundForwardingHeaders`
- 访问判定件：`IPReputation`、`accessgate.Gate`
- 处置与审计件：`WriteBlockResponse`、`RateLimiter`、`UnifiedWriter`

## 详细组件分析

### 认证与令牌机制
- 有效期：访问令牌 15 分钟（`jwt.go:37`），刷新令牌 7 天（`jwt.go:38`），签发者与受众固定并在校验时强制（`jwt.go:191-192`）
- 签名：HS256（`jwt.go:124`），非 HMAC 算法直接拒绝（`jwt.go:186-189`）
- Claims 载荷：`username`、`role`、`ip_hash`、`device_hash`（`jwt.go:28-34`），IP 与 UA 只存短哈希（`jwt.go:117-118`）
- 轮换：主密钥变更后备用密钥参与验证（`jwt.go:88-93`、`jwt.go:138-142`）
- 吊销：JTI 命中黑名单即拒绝（`jwt.go:151-153`）；黑名单未加载成功返回 `ErrTokenBlacklistUnavailable`，认证 fail closed 并 1 秒退避重试（`jwt.go:161-182`）
- 刷新轮换：`Rotate` 在单事务内消费旧令牌并创建替代者，`RowsAffected != 1` 判不可用（`refresh_token.go:96-110`）；`RevokeFamily` 沿 `replaced_by` 链带行锁与环检测（`refresh_token.go:43-85`）
- 过期清理：`CleanExpired` 默认单批 64 条（`refresh_token.go:134-153`）

### API 令牌与角色归属
- 生成：32 字节随机值 hex 编码，明文只在创建响应中出现一次；bcrypt 默认代价因子哈希入库，前 8 字符作快路径索引（`admin_api_key.go:50-66`）
- 校验：先按前缀查候选集逐个比对，无前缀的历史令牌全表回退并在命中后补写前缀，随后更新 `last_used_at`（`admin_api_key.go:70-101`）
- 归属：令牌不携带独立权限，身份与角色一律取归属 `AdminAccount`（`middleware.go:103-120`）；账号被删除后令牌立即失效并 401（`middleware.go:111-115`）

## 性能考虑
- 连接池复用：按 TLS 语义分池并复用 `ClientSessionCache`，命中时跳过完整握手
- 头部处理：净化器就地修改头映射，不复制集合；计数走原子变量，无锁
- 异步审计：四类通道各自有界，默认队列满即丢弃并计数，热路径不被数据库拖住
- 限流与信誉：`sync.Map` 加每键互斥，配合 5 分钟周期清理，读路径无全局锁
- IP 解析：字节级扫描加零拷贝转换，无正则；可信网段逐 token 解析，条目越多开销越大
- TLS：仅 HTTPS 上游装配 TLS；出站不做透明解压

## 故障排查指南

| 症状 | 可能原因 | 排查步骤 | 处置 |
|------|----------|----------|------|
| 401 `missing Authorization header` | 未带认证头 | 确认客户端注入逻辑 | 补 `Authorization: Bearer {占位}` |
| 401 `invalid Authorization format` | 前缀不是 `Bearer ` | 检查拼写与大小写 | 修正前缀（`middleware.go:62-67`） |
| 503 `authentication service unavailable` | 黑名单未加载 | 查数据库可用性与退避 | 存储恢复后自动放行（`jwt.go:161-182`） |
| 401 `api key owner account no longer exists` | 归属账号被删除 | 核对令牌 `user_id` | 重建令牌（`middleware.go:111-115`） |
| 403 `access denied: no role` | 上下文未写角色 | 确认经过认证中间件 | 修正路由分组（`middleware.go:133-138`） |
| 429 登录被锁 | 双维度计数达阈值 | 读剩余次数与锁定剩余时长 | 等待或调整阈值（`bruteforce.go:27-33`） |
| 客户端 IP 判定错误 | 模式或可信网段不匹配 | 按解析优先级逐项核对 | 见 [客户端 IP 获取](客户端 IP 获取.md) |

| 上游请求头被删 | 头名或头值不合校验 | 读净化器四项计数 | 修正调用方头格式（`upstream_request_guard.go:44-51`） |

## 结论
本模块的安全基础设施按职责分层落地：

- 认证与授权：双轨令牌加归属账号角色，黑名单 fail-closed，密钥轮换有主备过渡
- 会话与登录：内存与数据库双写，双维度暴力破解计数
- 请求溯源：模式与可信网段的合取前提，出站身份头先删后写
- 访问判定：IP 信誉、站点访问网关、固定窗口限流三件独立可组合
- 出站治理：协议白名单在写入阶段把关，净化器在发送前复校，连接池按 TLS 语义分池
- 审计与处置：四类通道异步落库，拦截与维护页多级回退

需要正视的三点边界：
- 管理面登录锁定使用 Hertz 内置 `ClientIP()`，其默认可信范围覆盖全网，与站点可信网段无关
- 出站方向不拦截内网、回环、链路本地与云元数据地址，也不复校验重定向与 DNS 解析结果
- `HTTPSClientTLSConfig` 的下限是 TLS 1.0，与反向代理主路径的 TLS 1.2 不一致

建议：上游配置写入权限按角色收敛；生产强制 TLS 且不开启跳过校验；令牌按账号最小授权并定期轮换；把解析后的客户端 IP 作为唯一风控输入口径。

### 安全最佳实践
- 凭据管理：账号口令与 API 令牌均为 bcrypt 哈希存储，明文只在创建响应中出现一次；私钥与令牌值一律以 `{占位}` 表达，不进入日志与文档
- 权限最小化：API 令牌权限取归属账号角色，只读场景使用 `readonly`；账号删除即令牌失效
- 溯源一致性：数据面所有风控输入统一走 `ResolveClientIP`，避免自建解析分支
- 出站治理：上游列表只由管理面配置并按角色收敛写入权限，生产禁用跳过校验
- 审计完整性：关注丢弃计数与批写失败数，队列容量按峰值 QPS 预留
- 响应口径：拦截与维护页统一使用内置模板或经评审的自定义 HTML，避免泄露内部信息
