## 简介
本文件聚焦 My-OpenWaf 的 `custom` 阶段。它是全 11 阶段链的**末位第 11 位**（`... → rate_limit → signature → custom`，engine.go:465-548），用于用户自定义规则的最终匹配与处置。与 `signature` 阶段同用 `Compiled` 规则与 `Matcher` 匹配器，核心差异在于 `custom` 走 `executeCustomPhase`：命中 Observe 类动作时不立即返回，而是先累积观察命中，待遇到更强终止动作时一并上交给管道，实现"同一阶段内多条观察命中 + 一条终止"的审计场景。

## 详细组件分析

### 执行阶段与 Observe 累积
`executeCustomPhase` 的分支语义（phases.go:194-225）：规则为空返回 `Pass(), false`；命中后若 `r.ShouldLog() && !r.IsTerminal()`（即 Observe 类），累积到 `observeHits` 并继续遍历；否则把已累积命中 `AppendPhaseObserveHits` 后返回 `(r, r.IsTerminal())`；遍历结束若无命中返回 `Pass()`，若有 Observe 命中则返回首条、其余追加进上下文，`stop=false`。

| 场景 | observeHits | 更强动作 | 返回 |
|---|:--:|:--:|---|
| 仅 Observe 命中 | 多条 | 无 | `(首条, false)` + 追加其余 |
| Observe 后遇 Intercept | 已有 | 有 | 先 flush，再 `(Intercept, true)` |
| 直接终端命中 | 空 | 有 | `(r, true)` |
| 全未命中 | 空 | 无 | `(Pass(), false)` |

```mermaid

Empty --> |是| Pass["Pass(),false"]
Empty --> |否| Loop["顺序遍历"]
Loop --> M{"命中?"}
M --> |否| Loop
M --> |是| IsObs{"ShouldLog 且非终端?"}
IsObs --> |是| Acc["累积 observeHits,继续"]
Acc --> Loop
IsObs --> |否| Flush["flush 观察命中"]
Flush --> Term{"IsTerminal?"}
Term --> |是| Stop["返回 (r,true)"]
```

### 复合规则与频次匹配
`buildCompound` 递归构建逻辑树（matcher.go:1878-1928）：

| op | 结构要求 | 匹配器 | 失败回落 |
|---|---|---|---|
| `and`/`or` | `children` 非空 | `andMatcher`/`orMatcher` | 空→neverMatcher |
| `not` | `children` 恰 1 | `notMatcher` | 数量不符→neverMatcher |
| `if`/`if_else` | `if`+`then`，可选 `else` | `ifElseMatcher` | 缺 if/then→neverMatcher |
| `cc_rate` | 1 child + window>0 + threshold>0 | `ccRateMatcher` | 非法→neverMatcher |

`cc_rate` 用 `RateLimitKey` 同源键做窗口频次判定，`state.count>=threshold` 触发并按 `duration` 设阻断窗口（matcher.go:25-91、107-109），每 60 秒清扫过期状态（matcher.go:67-74）。

### 通配符匹配器与快路径
`*_wildcard` 类 kind（`path_wildcard`/`full_url_wildcard`/`host_wildcard`/`body_wildcard`/`header_wildcard`）经 `compileWildcard` 编译为 `wildcardTester`（matcher.go:1341-1377）。`parseGlob` 把通配模式翻译为锚定正则源码，`*` 有意匹配含 `/` 的任意序列（区别于 `path.Match` 的段边界），避免 `*bot*` 静默失配（matcher.go:1054-1185）。

编译后按形态选择实现，纯字面量形态退化为 `strings`/`bytes` 快路径：

| 形态 | 模式示例 | 实现 |
|---|---|---|
| wcAny | `*` | 恒真 |
| wcExact | `abc` | 相等比较 |
| wcContains | `*abc*` | 子串（可 ASCII 折叠） |
| wcPrefix | `abc*` | 前缀 |
| wcSuffix | `*abc` | 后缀 |
| wcRegex | 含 `?`/字符类/中缀 `*` | RE2 正则 |

非法通配模式（空、星号数 > 8、悬空转义）编译失败回落 `neverMatcher`，fail-closed 与全 `*_regex` 方向一致（matcher.go:1120-1122、1341-1344）。

## 性能考虑
- Observe 累积：多条观察命中在阶段内合并后一次性 flush，减少多次 `AppendPhaseObserveHits` 调用（phases.go:212-223）。
- 匹配器短路：AND 遇任一假即返回、OR 遇任即真（matcher.go:281-307），复合树避免无谓求值。
- 正则缓存：`cachedCompile` 全局缓存复用（matcher.go:1785-1808）。
- 懒解析复用：`bodyJSONPath`/`queryParam` 借 `RequestCtx` 缓存每请求至多解析一次（matcher.go:574-606）。

## 故障排查指南
- 规则无法匹配：确认启用、`Phase=="custom"`、kind 在 `knownPrefixes` 内（compiler.go:119-142）。
- 复合结构错误：`and/or` children 不能为空、`not` 恰一个子、`cc_rate` 需 window/threshold>0，否则回落永不匹配（matcher.go:1878-1928）。
- 动作漂移：`log`/`log_only` 归一化为 `observe`，非法动作归一化为 `intercept`（phases.go:1301-1310）。
- Observe 未上报：由 pipeline 统一收集，检查 `ShouldLog` 判定（action.go:260-272）。

## 结论
`custom` 阶段作为链尾最终匹配环节，通过 `executeCustomPhase` 实现"多条 Observe 命中 + 一条终止动作"的审计语义，与 `signature` 共享编译与匹配器体系。匹配器全谱与复合逻辑树覆盖 IP/路径/查询/头部/方法/内容类型/请求体/TLS 指纹/频次等维度，非法模式统一 fail-closed，保证规则错误不会放大为误封。
