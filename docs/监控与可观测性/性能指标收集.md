## 简介

本篇聚焦「指标」这一可观测支柱，覆盖两套彼此独立、口径不同的计数体系，以及它们如何汇合到单一 Prometheus 文本端点：

- **控制面 Prometheus 指标**：由 `internal/observability.Metrics` 收集，经管理端口 `GET /metrics` 暴露，进程级指标恒常输出，子系统指标由可插拔 provider 按需挂载。
- **数据面实时计数器**：由 `internal/dataplane/metrics.Metrics` 维护原子计数、QPS 环形缓冲与去重 IP 集合，主要服务实时面板（`Summary` JSON）；其中一份经 provider 桥接为 `openwaf_dataplane_*` 序列进入 Prometheus。
- **异步写入器诊断**：`UnifiedWriter` 与 `WriteQueue` 的队列深度、丢弃与 flush 结果，用于判断「数据是否被丢弃」。

关键事实：`openwaf_requests_total`、`openwaf_blocks_total`、`openwaf_observes_total`、`openwaf_upstream_errors_total` **已从代码移除**，`/metrics` 不再输出这四个名字；请求总量请读 `openwaf_dataplane_requests_total`，移除原因见 `internal/observability/metrics.go:263-273` 的结构体注释。缓存族真实名是 `owaf_cache_*`（带 `cache` 标签），而非 `openwaf_cache_*`。`/metrics` 挂在**管理端口**而非数据面端口。域级概述（含事件、归档、探针）见 [监控与可观测性](监控与可观测性.md)，本篇不重复其结论。

`/metrics` 只在管理端口注册（`adminSrv.GET("/metrics", ...)`，`server.go:1056`），且 `adminSrv` 为明文 HTTP（`server.Default(server.WithHostPorts(AdminBind))`，`server.go:1052`，默认 `:9443`）。每次抓取触发一次 `PrometheusBody`：先读 Go runtime 拼进程片段，再对每个已挂载 provider 调一次快照函数追加片段。未挂载 provider 的子系统（如未启用 HTTPTrace）不会输出对应 HELP/TYPE 头。

### 数据面计数器与 openwaf_dataplane_* 桥接（两套体系）

数据面计数器与 Prometheus 指标是**两套独立体系**，不得混为一谈：

- 第一套是 `dataplane.Metrics` 的原子字段与环形缓冲（`dataplane/metrics/metrics.go:13-31`）。它们本身不是 Prometheus 指标，没有 HELP/TYPE，只在内存里累加。`RecordRequest`（:48-62）在原子自增的同时把请求落进 10×1s 环形桶；`QPS(windowSec)`（:112-125）遍历窗口求和再除以秒数。唯一 IP 与攻击 IP 通过 `sync.Mutex` + `map` 去重（:80-109），仅首次出现时给 `uniqueIPCnt`/`attackIPCnt` 加一。
- 该结构体主要服务 `Summary`（:131-161）JSON，供管理端实时面板（`server.go:1060` 的 `NewRealtimeHub`）消费。
- 第二套是桥接后的 Prometheus 序列：`server.go:491` 用 `SetDataPlaneMetricsProvider` 注册一个闭包，把 `metrics.Summary()` 转成 `observability.DataPlaneMetricsSnapshot`，`PrometheusBody` 经 `prometheusDataPlaneMetrics`（metrics.go:402-453）渲染为 `openwaf_dataplane_*`。

差异点：原子字段是「累计值」，`openwaf_dataplane_*` 是抓取瞬时快照；QPS 是即时窗口估计而非 rate 积分；IP 集合按进程生命周期去重、重启清零。`observability.Metrics` 内不再自带 `RequestsTotal`/`BlocksTotal` 等字段，这些语义的唯一真实来源就是这条桥接链路。

| 维度 | 数据面原子计数器 | openwaf_dataplane_* 桥接序列 |
|---|---|---|
| 定义处 | `dataplane/metrics/metrics.go:13-31` | `metrics.go:402-453` |
| 形态 | `atomic.Int64` / `map` / 环形桶 | Prometheus counter/gauge 文本 |
| 消费者 | `Summary` JSON、实时面板 | Prometheus 抓取 |
| 是否带 HELP/TYPE | 否 | 是 |
| 重启后 | 全部清零 | 快照随进程清零 |

### 缓存指标族 owaf_cache_*

缓存族是少数使用 `owaf_` 前缀（而非 `openwaf_`）的指标，定义在 `metrics.go:532-550`，由 `server.go:550-561` 的 `SetCacheStatsProvider` 注入三层快照：

- `cache="query"`：`queryCache.HitStats()`。
- `cache="hot"`：`hotCache.HitStats()`，且额外携带 `ErrorCount()`——hot 层走 Redis，把「Redis 故障穿透」与「键不存在」分开计数。
- `cache="response"`：`responseCache.HitStats()`。

每个 `CacheLayerStats` 含 `Hits/Misses/Errors`（`metrics.go:72-80`）。`Errors` 增长说明请求正穿透到数据库，而非缓存策略失效。label 值经 `escapePrometheusLabelValue`（:568-587）转义反斜杠、双引号与换行，避免用户可控字符串破坏文本格式。

### 写入器与写队列诊断

`UnifiedWriter` 与 `WriteQueue` 是两个生命周期与丢失语义不同的队列，故各自有独立 provider（`metrics.go:15-28` 的接口注释）。`prometheusUnifiedWriterStats`（:771-836）渲染队列长度（`{type}` 四类）、丢弃、flush 结果与最近一次 flush 的若干 gauge；`prometheusWriteQueueStats`（:838-935）渲染深度/容量/关闭位、提交/入队/满丢弃/关闭丢弃/同步回落、执行/成功/失败/事务错误、批次与最近批次 gauge。

判断「数据是否真丢」：`openwaf_writer_dropped_total{type=...}` 增长代表入队前被丢（通道满或关停期），`openwaf_writer_failed_records_total` 增长代表已进入 flush 但数据库写失败。默认容量与阈值见 `unified_writer.go:124-129`（事件/访问日志通道 16384、丢弃/机器人通道 8192、批 256、flush 3s）与 `write_queue.go:111-115`（容量 256、批 64、ticker 50ms）。归档与保留策略见 [监控与可观测性](监控与可观测性.md)。

### 上游健康、出站净化与 Lua/HTTPTrace/图像指标

- 上游健康（`prometheusUpstreamMetrics` :455-493）：`server.go:508-537` 的闭包遍历 `upstreamPool.Snapshot()`，区分 healthy/unhealthy/known/checked 与平均/最大延迟。这是探活结果，非请求级。
- 出站净化（`prometheusUpstreamRequestGuardStats` :505-528）：四个 counter 记录「本可成 5xx 却被救回」的次数，包括 `DroppedSecurityHeaderNames`——非零意味着上游看到的身份/来源与客户端发出的不一致，是重要告警信号。
- Lua 脚本（`prometheusLuaScriptStats` :598-636）：脚本失败/超时只写日志即跳过，若无指标则策略长期失效无外部信号；`failures` 与 `timeouts` 互斥。无脚本时返回空串（不输出空 HELP/TYPE）。
- HTTPTrace（`prometheusHTTPTraceStats` :654-755）：仅在 `rt.Config.HTTPTrace.Enabled` 时挂载（`server.go:482-488`），分协议输出 `total/read_header/read_body/server_handle/write` 直方图（阶段名 `http_trace.go:16-22`）。`phase="server_handle"` **含同步等待上游**，不是纯 WAF 计算时间（`http_trace.go:85-114`）。
- 图像（`prometheusImageTransformStats` :358-400）：`openwaf_imagery_webp_dynamic_available` 是 libwebp 装载失败退回纯 Go 转译的唯一信号，恒为 0/1 gauge 而非省略。

## 性能考虑

- 进程指标每次抓取读一次 `runtime.ReadMemStats`，与抓取频率绑定、不在请求热路径上。
- provider 用 `atomic.Value` 挂载、抓取时 `Load()` 一次，未挂载即零开销；HTTPTrace provider 一旦挂上每次抓取会遍历协议与阶段表，故未启用遥测时不调用 `SetHTTPTraceStatsProvider`（`metrics.go:222-231`）。
- 数据面 QPS 用固定 10 槽环形缓冲，`QPS` 为 O(10) 扫描，窗口长度稳定；良性竞态最坏仅略微多计（`metrics.go:51-61`）。
- 直方图仅渲染有有效样本的协议（`metrics.go:713-721`），keep-alive 空闲回收不补零，避免每次抓取多出 80 行恒零样本。
- 写入器用大缓冲通道 + 单 goroutine 批量事务，把 DB 写从热路径剥离，丢弃量经 `writer_dropped_total` 可见。

## 故障排查指南

所有探针与 `/metrics` 都在管理端口（默认 `:9443`，明文 HTTP）。以下命令均可直接执行：

```bash
# 1) 抓取指标，确认数据面累计请求确实来自桥接序列（不再有 openwaf_requests_total）
curl -s http://127.0.0.1:9443/metrics | grep '^openwaf_dataplane_requests_total'
# 预期：一行 "openwaf_dataplane_requests_total <非负整数>"；若无行，说明 provider 未挂载或数据面未起

# 2) 确认已移除的旧指标名不再出现（应无输出）
curl -s http://127.0.0.1:9443/metrics | grep -E 'openwaf_(requests|blocks|observes|upstream_errors)_total'

# 3) 看是否有入队前丢弃（通道满/关停期）
curl -s http://127.0.0.1:9443/metrics | grep '^openwaf_writer_dropped_total'
# 预期：四类 type 值；非零代表可观测记录被丢，需查 DB 背压或调大批量

# 4) 缓存族真实前缀是 owaf_ 而非 openwaf_
curl -s http://127.0.0.1:9443/metrics | grep '^owaf_cache_'

# 5) 进程级健康（uptime/goroutines 恒输出，可作为 /metrics 存活判据）
curl -s http://127.0.0.1:9443/metrics | grep -E '^openwaf_(uptime_seconds|goroutines)'
```

排查要点：

- 指标全缺：先 `curl` 管理端口确认 `adminSrv` 已起；`/metrics` 路由在 `server.go:1056` 注册，与 `RegisterRoutes` 同一实例。
- `openwaf_dataplane_*` 恒 0：数据面监听器未接流量，或 provider 闭包未注册（`server.go:491`）。
- 误把 `openwaf_requests_total` 当真实指标：该名已移除，请求总量请读 `openwaf_dataplane_requests_total`。
- 缓存命中率骤降：区分 `owaf_cache_misses_total`（策略）与 `owaf_cache_errors_total{cache="hot"}`（Redis 故障穿透）。

## 结论

My-OpenWaf 用「进程级恒输出 + 9 个可插拔 provider」的方式组织控制面 Prometheus 指标，与数据面原子计数器形成两套各司其职的体系，再经 `SetDataPlaneMetricsProvider` 单向桥接为 `openwaf_dataplane_*`。指标名以 `metrics.go` 渲染函数为权威：旧的四类计数名已移除、缓存族用 `owaf_cache_*`、`/metrics` 仅在管理端口。运维建立面板与告警时应严格按真实指标名取数，避免第二真相。

### PromQL 查询与分析

- 数据面 QPS（1m 平滑）：`rate(openwaf_dataplane_requests_total[1m])`。
- 缓存命中率（response 层）：`rate(owaf_cache_hits_total{cache="response"}[5m]) / (rate(owaf_cache_hits_total{cache="response"}[5m]) + rate(owaf_cache_misses_total{cache="response"}[5m]))`。
- Redis 穿透告警：`increase(owaf_cache_errors_total{cache="hot"}[5m]) > 0`。
- 可观测记录丢弃告警：`increase(openwaf_writer_dropped_total[5m]) > 0`。
- 上游健康翻转：`openwaf_upstream_unhealthy_total > 0`。

### 可视化与告警建议

- 实时 QPS/状态分布取数据面 `Summary`（面板）与 `openwaf_dataplane_*`（Prometheus）交叉核对，二者口径见上文两套体系表。
- 分阶段耗时面板按 `proto` 拆 h1/h2/h3，h2 的 `read_body/write` 恒缺属「未采集」而非「零耗时」，不要补零解读。

- 图像退化告警：`openwaf_imagery_webp_dynamic_available == 0` 表示退回纯 Go 路径，慢数倍。
