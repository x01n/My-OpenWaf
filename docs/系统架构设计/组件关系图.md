## 简介
本文件只回答一个问题：**系统里到底有哪些节点，它们之间的边是谁指向谁**。因此本篇的产物是图本身——容器级拓扑、组件级依赖、类型关系与调用方向，节点名一律使用真实包路径与符号名。

**划界**：为什么这样分层、分层带来的取舍，见 [系统架构设计](系统架构设计.md)；请求在边上流动时数据形态如何变化，见 [数据流分析](数据流分析.md)；快照节点内部的构建细节，见 [快照机制](快照机制.md)。

## 项目结构
节点按「谁创建谁」划分为六个簇，簇间只允许单向边。

| 簇 | 节点 | 创建者 | 生命周期 |
|---|---|---|---|
| 引导簇 | `cmd/main.go` | Go runtime | 进程级 |
| 装配簇 | `app.Run`、`app.buildDataServerWithHTTP3Plans`、`app.reconcileListeners` | `main` | 进程级，函数无状态 |
| 共享视图簇 | `core.Runtime`、`snapshot.Holder`、`snapshot.Snapshot`、`cache.Layer` | `Run` | 进程级，快照按代次更替 |
| 控制簇 | `admin.RegisterRoutes`、`core/health.Checker`、`core/lifecycle.Manager`、`core/redis.ConfigSync` | `Run` | 进程级 |
| 数据簇 | `dataplane.Handler`、`core/engine.Engine`、`core/pipeline`、`core/rules`、`proxy`、`upstream.Pool` | `Run` + 调谐器 | 监听器级 |
| 观测簇 | `observability.UnifiedWriter`、`dataplane/metrics`、`observability/metrics` | `Run` | 进程级 |

### 阶段节点的组装与装饰关系
`Engine` 不直接持有阶段实例，而是每次构建一条 `[]pipeline.Phase`。阶段实现全部来自 `internal/core/rules`，构造函数统一返回接口类型（phases.go:142、469、603 等），因此阶段之间无相互依赖，只依赖 `pipeline.RequestCtx` 与 `action.Result` 两个契约。

| 阶段节点 | 构造符号 | 附加依赖 |
|---|---|---|
| `ip_reputation` | `NewIPReputationPhase` | `iprep.IPReputation` + 站点名单 |
| `anti_replay` | `NewAntiReplayPhase` | `antireplay.AntiReplayManager` |
| `acl` | `NewACLPhasePrecompiled`（phases.go:142） | 预编译规则 |
| `lua_pre` | `NewLuaPhase` | `luaplugin.Engine` |
| `owasp_default` | `NewOWASPPhase`（phases.go:603） | `ProtectionConfig` |
| `cve` | `NewCVEPhase` | `cve.CVEDetector` |
| `bot` | `NewBotPhaseWithGeoAndLimiter`（phases.go:469） | geoip + 限流后端 |
| `browser_sign` | `NewBrowserSignPhase` | `ProtectionConfig` |
| `rate_limit` | `NewReqRateLimitPhase` | 限流后端 |
| `signature` | `NewSignaturePhasePrecompiled` | 预编译规则 |
| `custom` | `NewCustomPhasePrecompiled` | 预编译规则 |

`signature` 与 `custom` 不走 `addPhase`，因此不会被 `NewSkipByPathPhase`（phase_skip.go:31）包裹——这是二者与其余阶段在依赖图上唯一的差异。

## 性能考虑
- **汇聚节点的读放大**：`Snapshot` 是最热的节点，但每次读取只有一次 `atomic.Pointer.Load()` 加至多三次 map 探底，因此边数多不等于成本高。
- **接口边界带来的构造成本**：阶段以接口入链，链本身被缓存，构建只发生在代次切换后的首个请求。
- **无锁快路径是显式设计**：`compiledPtr`/`phasesPtr` 用 `atomic.Pointer` 读、`*WriteMu` 串行化写并整体替换不可变 map（engine.go:96-103、532-545），并非 `RWMutex`。
- **对象池切断分配边**：`RequestCtx` 由 `sync.Pool` 复用，池对象超限时在 Release 侧重建（pool.go:11-28）。
- **异步边**：`Handler → UnifiedWriter` 只有通道入队，落库边由单 goroutine 承担（unified_writer.go:26-52、381）。
- **接口化服务器**：`lifecycle` 与具体服务器类型解耦，新增 QUIC 监听不引入新依赖边。

## 结论
本篇把系统画成六簇、约二十个真实节点、一条有向无环的依赖图。三处最容易画错的地方已在对照表中固定下来：阻断页在 `internal/waf/pages/block.go` 而非 `internal/waf/block.go`；传输池在 `internal/proxy/transport` 以包级函数暴露而非 `Proxy` 方法；站点解析是哈希查找而非树结构。节点的汇聚点是 `snapshot.Snapshot`——它同时被控制面写入路径与数据面读取路径指向，正因如此它必须不可变。
