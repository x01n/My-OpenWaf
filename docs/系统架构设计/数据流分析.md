## 简介
本文件面向 My-OpenWaf 的数据流分析，围绕「一个请求从进入数据面到写出响应」的完整路径，逐跳说明数据形态的转换、状态的迁移与错误处理落点。内容覆盖站点匹配、门禁检查、WAF 阶段链执行、动作决策、上游转发与响应回写，并指出关键决策点与潜在瓶颈。

**划界**：本文只描述**流**——每一步读什么、改什么、把什么交给下一步。组件之间的静态拓扑与依赖边归 [组件关系图](组件关系图.md)；阶段链在引擎内部的构建与缓存归 [WAF 引擎系统](../WAF 引擎系统/WAF 引擎系统.md)；快照的构建与发布语义归 [快照机制](快照机制.md)。

## 项目结构
数据流的所有分支都发生在 `internal/dataplane` 的单个 Hertz 中间件里，其余包只被它调用而不感知流程。

| 层 | 承载 | 在数据流中的角色 | 是否改写请求 |
|---|---|---|---|
| 接入层 | `dataplane.Handler` | 端点短路、快照读取、站点匹配 | 是（补 `X-Request-ID`、删 `Server`） |
| 门禁层 | `dataplane` 内联检查 | 挑战、防重放、访问控制、Basic Auth | 否 |
| 观测层 | `dataplane` 采样 | 走私嗅探、体采样、指纹提取 | 否 |
| 改写层 | `jsplugin` / `luaplugin` pre | 脚本可改 method/path/query/body/UA | 是 |
| 决策层 | `core/engine` + `pipeline` | 11 阶段链顺序执行 | 是（Lua pre 改写回写） |
| 落地层 | `waf/pages`、`waf/drop` | 拦截/维护/挑战/错误页与连接关闭 | 是（写响应） |
| 转发层 | `proxy` + `proxy/transport` | 协议分派、连接池复用、响应回写 | 是（出站头改写） |
| 记录层 | `observability.UnifiedWriter` | 异步批量落库 | 否 |

## 架构总览

数据面没有独立的「路由表」概念：监听器按 `bind` 建立，站点由 `Host` 在快照里查出来。因此一次请求的数据流可以概括为「一次哈希查找 + 一串按序执行的判定 + 一次协议分派」。

| 上下文要素 | 数据面视角 | 交互 | 失败语义 |
|---|---|---|---|
| 客户端 | 请求来源 | Hertz 中间件入参 | 头超限 431、无快照 503 |
| 快照 | 当前配置代 | `Holder.Load()` 一次 | nil 直接 503 `configuration_error` |
| 站点运行时 | 本请求的策略集 | `MatchSite(bind, host)` | 未命中写欢迎页 200 + `routing_error` |
| 引擎 | 判定机构 | `ProcessResolved` | 返回 `ProcessResult`，不 panic 到接入层 |
| 上游源站 | 放行目标 | 四路协议分派 | 502/504 友好错误页，`Mark` 记失败 |
| 响应缓存 | 边缘副本 | `Get`/`BeginFill`/`Set…IfGeneration` | generation 不符则退回收源 |
| 统一写入器 | 异步审计 | 四条通道入队 | 队列满计入 dropped 计数 |
| Redis | 挑战与限流状态 | 会话、nonce、计数器 | 不可用时降级而非站点不可用 |

### 阶段链执行与动作优先级
`pipeline.Run` 是顺序执行加两类特殊处理：非终止且需记录的命中被收进 `observeHits`；终止的**挑战类**动作不立即返回，而是暂存 `pendingChallenge` 继续跑完剩余阶段，最后取优先级最高者——比较用严格大于，因此同档挑战以先出现者为准。`drop` 例外，出现即短路。

| 动作 | 终止性 | 挑战类 | `TerminalPriority` | 短路行为 |
|---|---|---|---|---|
| `drop` | 是 | 否 | 90 | 立即返回 |
| `intercept` | 是 | 否 | 80 | 立即返回 |
| `rate_limit` | 是 | 否 | 70 | 立即返回 |
| `captcha_challenge` / `shield_challenge` / `chain_challenge` / `challenge` | 是 | 是 | 60（四者同档） | 暂存后继续 |
| `redirect` | 是 | 否 | 50 | 立即返回 |
| `observe` | 否 | 否 | 10 | 记入 observe 后继续 |
| `allow` / `tag` | 否 | 否 | 0 | 继续 |

优先级数值来自 `action.TerminalPriority`（action.go:88-119）。同档挑战之间不再排序，故链式与盾在同一请求里不会互相覆盖。

阶段链实测 11 项，顺序为 `ip_reputation → anti_replay → acl → lua_pre → owasp_default → cve → bot → browser_sign → rate_limit → signature → custom`，构建时按 11 预分配容量（engine.go:467）。其中 `signature` 与 `custom` 不参与按路径跳过装饰，其余阶段若配置了跳过路径会被包一层短路装饰器（engine.go:471-477、522-529）。

### 响应缓存与回写数据流
缓存路径的关键不是「命中与否」而是**代次**：`ResponseCache` 带 `generation` 计数，任何按站点的失效都会推进它。回写前先按当时的 generation 抓一次 stale 候选，回源失败时再用同一代重查，避免等待填充期间发生的失效被旧指针掩盖（handler.go:1152-1195）。

| 分支 | 触发条件 | 动作 | 记录值 |
|---|---|---|---|
| 不适用缓存 | 键为空或带条件/Range 头 | 直接 `ForwardHTTP` | `bypass` |
| 新鲜命中 | `Get` 返回未过期条目 | `WriteCachedResponseForSiteWithClientIP` | `hit` |
| 填充跟随 | `BeginFill` 返回非 leader | 只查同代新鲜条目 | `hit` |
| 回源 | leader 且未命中 | `FetchHTTPForCache` | `miss` |
| stale 回放 | 回源失败且同代有 stale 候选 | 回放旧条目 | `stale` |
| 写回 | 响应可缓存且 TTL>0 | `SetForSiteIfGeneration` | `miss` |

## 性能考虑
- **每请求一次哈希查找**：站点匹配是至多三次 map 探底的哈希查找，不存在树遍历；`NormalizeMatchHost` 对规范 Host 走零分配快路径（snapshot.go:409-421）。
- **拷贝与零拷贝并存**：主链路用 `MatchSite`（返回值拷贝，便于请求内改压缩字段），引擎内部用 `MatchSitePtr`（零拷贝）（snapshot.go:337、373）。
- **上下文池化**：`RequestCtx` 经 `sync.Pool` 复用，池对象超过头 map/slice 上限时在 Release 侧重建，防止峰值后 RSS 不回落（pool.go:11-28）。
- **派生值单次计算**：`DerivedHeaderOrder`、`DerivedALPN` 等在请求内至多算一次并缓存（pipeline.go:88-100）。
- **体采样上限 48KB**：`maxWAFBody = 48 * 1024`，与快照常量一致（handler.go:377、snapshot.go:493）。
- **连接池参数**：主 transport `MaxIdleConns 256 / PerHost 32 / IdleConnTimeout 30s`、`MaxConnsPerHost 256`、16KiB 缓冲（transport.go:157-164、172）。
- **缓存代次**：`ResponseCache` 用 generation 避免跨代回放，非安全方法按站点+路径精准清理，不做全分片扫描（handler.go:1218-1222）。
- **瓶颈点**：阶段链构建成本集中在未命中缓存的首个请求；上游连接耗尽表现为 504 而非 502；观测通道满会静默丢弃并计入 dropped 计数。

## 结论
My-OpenWaf 的数据流是一条**单函数、无倒钩**的线性链路：一次原子快照读取、一次哈希站点匹配、一串按序执行的判定、一次协议分派，最后统一收尾与异步记录。它有两个反直觉但重要的设计点——未命中站点返回欢迎页 200 而非 404（避免路由错误暴露站点存在性），以及挑战动作延迟裁决（让更严重的检测覆盖它）。性能来源集中在三处：不可变快照带来的无锁读、上下文与连接池复用、观测写入的批处理异步化。
