## 简介
My-OpenWaf 是一个基于 Go 语言开发的高性能 Web 应用防火墙系统，采用双服务器架构：控制平面（管理接口）与数据平面（流量处理）。它支持多站点防护、可视化管理界面、热重载配置、分布式同步等能力，适用于需要细粒度站点级防护与集中管理的企业与云环境。

- 项目目标：提供可扩展、可观测、易运维的 Web 防火墙解决方案，兼顾初学者易用性与高级用户的深度定制需求。
- 核心能力：多站点独立监听与热启停、基于 Next.js 的可视化管理面板、快照驱动的无损热重载、可选 Redis 分布式同步、覆盖 IP 名单/速率限制/OWASP/CVE/Bot/浏览器签名/自定义规则的完整防护链。
- 架构决策：后端 Go + Hertz，数据面按站点绑定独立监听器并支持 HTTP/3；前端 Next.js 静态导出后嵌入后端二进制，实现单体部署；PoW 质询由 Rust 编译为 WASM 加速。

## 核心组件
- 运行时（Runtime）
  - `NewRuntime` 先 `LoadConfigFromEnv`，校验引导配置后打开主库与日志库，可选建立 rueidis 客户端，并初始化内存缓存层与快照持有者 `Snapshot *snapshot.Holder`。
  - 来源 [internal/core/runtime.go:23-60](file://internal/core/runtime.go#L23-L60)。
- 快照（Snapshot）
  - 不可变快照持有站点映射、SNI 证书映射与全局保护配置；站点匹配用哈希键 `bind + 0x00 + host`（非 Trie），SNI/站点解析优先级为精确 → `*.` 单级父域 → catch-all `*`。
  - 来源 [internal/snapshot/snapshot.go:289-334](file://internal/snapshot/snapshot.go#L289-L334)。
- 引擎（Engine）
  - 将 `pipeline.RequestCtx` 送入多阶段流水线。阶段链按最大规模预分配容量 11，依实测顺序组装：IPReputation → AntiReplay → ACL → Lua 前置 → OWASP → CVE → Bot → BrowserSign → 请求限流 → Signature → Custom。
  - 来源 [internal/core/engine/engine.go:465-548](file://internal/core/engine/engine.go#L465-L548)。
- 流水线（Pipeline）
  - `RequestCtx` 携带已解码的请求数据（绑定地址、客户端 IP、方法、路径、查询、头部、请求体、TLS 指纹等）与派生缓存，供各阶段共享，避免重复解析。

## 架构总览
My-OpenWaf 采用“控制平面 + 数据平面”的双服务器架构：
- 控制平面：管理 API 服务器，提供认证、配置 CRUD、仪表盘与前端静态资源；`/healthz`、`/readyz`、`/status`、`/metrics` 在管理端口暴露。
- 数据平面：按站点维度创建独立监听器，每个监听器封装数据平面处理器，负责实时请求处理与防护。
- 配置与状态：配置变更通过数据库版本号递增触发快照重建与热重载；可选 Redis 用于分布式通知；内存缓存加速快照读取。
- 可观测性：事件经统一写入器异步批量落库；指标由数据面 `metrics` 子桥接到管理端暴露。

### WAF 引擎与请求处理流水线
- 请求上下文：`pipeline.RequestCtx` 含绑定地址、客户端 IP、方法、路径、查询、头部、请求体、TLS 指纹等，并对 JSON/query/头部做惰性解析缓存。
- 阶段顺序（实测 11 阶段，`engine.go:465-548`）：
  1) `ip_reputation`：白/黑名单决策。2) `anti_replay`：nonce 防重放。3) `acl`：站点访问控制规则。4) `lua_pre`：前置 Lua 策略（ACL 之后、OWASP 之前）。5) `owasp_default`：OWASP 规则族。6) `cve`：CVE 漏洞检测。7) `bot`：Bot 评分与指纹。8) `browser_sign`：浏览器签名校验。9) `rate_limit`：请求速率限制。10) `signature`：签名规则。11) `custom`：自定义规则。
- 终止语义：`signature`/`custom` 直连 append 不参与按 phase 跳过；非 Challenge 终端动作短路返回，Challenge 类动作可被后续更高优先级终端动作覆盖，观察命中用于日志记录。

### 速率限制与 IP 名单
- 速率限制：固定窗口计数，键 `(clientIP + host)`；`Reconfigure` 在持锁下原地改窗口/配额/开关；无效参数（`window<=0` 或 `max<=0`）按未启用处理。

## 性能考虑
- 快照与缓存：运行时持有不可变快照与内存缓存层，数据面读取走无锁快路径，避免每次重建快照。
- 阶段链短路：终端动作出现即返回，减少后续阶段开销；`signature`/`custom` 不参与按 phase 跳过装饰，热路径不引入额外分支。
- 解析缓存复用：`RequestCtx` 对 JSON body、query、头部与 OWASP/CVE 目标做惰性缓存，多阶段共享。
- 限流与封禁：清理协程定期回收过期窗口与封禁，防止内存膨胀。
- 监听器隔离与前端内嵌：按站点独立监听便于隔离与扩展；前端构建产物内嵌后端，减少静态资源访问延迟。

## 故障排查指南
| 症状 | 可能原因 | 排查 / 处理 |
|------|----------|-------------|
| 核心初始化或迁移失败、进程退出 | 驱动/DSN 错误、数据目录权限 | 看 `Run` 中 `os.Exit(1)` 前日志；核对 `MY_OPENWAF_DB_DRIVER`/`DSN` |
| 首次启动未见凭据 | 非首启（admin 账号已存在）或迁移未完成 | `SeedDefaults` 仅首启返回口令（seed.go）；确认主库已 `AutoMigrate` |
| 快照重建失败 | 站点/保护配置字段不完整 | 检查 `ReloadSnapshot` 失败日志与系统设置 |
| 限流不生效 | 窗口/配额非法按未启用 | `NewRateLimiter`/`Reconfigure` 对 `<=0` 置未启用；用管理端修正 |
| IP 名单/自动封禁异常 | 条目格式或阈值/窗口/时长配置 | 核对 CIDR/单 IP、过期时间与默认阈值 10/60/3600 |
| Redis 多节点不同步 | 地址/密码/DB 配置 | 检查 `rueidis` 连接与订阅回调 |
