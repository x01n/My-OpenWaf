## 简介

本篇讲两件事：**`POST /api/v1/rules/validate` 到底校验了什么**，以及 **`POST /api/v1/rules/test` 的「试运行」能证明什么、不能证明什么**。

三条必须先记住的实测结论：

1. **`valid:true` 不等于规则会生效**。保存期校验用 `internal/core/rules` 的 57 项 kind 白名单，快照编译期用 `internal/snapshot` 自己的 30 项前缀表，差集 **27 项**在 `compileRules` 被静默丢弃（build.go:923-926）。前端编辑器可达 **33 个字面量 kind**，其中 **21 项**落在这 27 项里——用图形表单造出来的规则有一大半是「存得下、跑不了」。
2. **试运行只填 6 个上下文字段**。`TestRule` 构造的 `MatchCtx` 覆盖 15 个字段中的 6 个（rule.go:251-258 与 phases.go:34-51），TLS 类、`header_order` 类、Host 类要么恒不命中，要么只能靠伪造 `x-owaf-*` 内部头才命中。
3. **试运行会写进真实的限流状态表**。`cc_rate` 的共享状态按「子条件 + 窗口 + 阈值 + 时长」的 MD5 取键（matcher.go:1858-1876），与规则参数一一对应；试运行会 LoadOrStore 同一对象，只是客户端计数键因 `bind`/`site_id` 为空而与线上不同（matcher.go:107-109）。**不会串改同一 IP 的线上配额，但会向生产状态表写入条目并参与 60 秒清扫**。

本篇只登记事实与给出可复现的自检命令，不改代码。

## 性能考虑

- **`validate` 每次都会构造一次语义校验**，其中正则类 kind 走 `cachedCompile`（RWMutex 保护的进程级 map），首次编译后复用；非法正则在保存期即拒，不会把成本推到运行期（matcher.go:1785-1808）。
- **`test` 每请求重新 `Compile`**，不做任何缓存：`rules.Compile` 会新建匹配器并排序，单条规则的开销可忽略，但该接口不能用于压测式批量验证。
- **`cc_rate` 的 dry-run 会写生产状态对象**：`ccRateStates` 是包级 `sync.Map`，按规则参数 MD5 取共享状态（matcher.go:45、1907-1919），试运行会 `LoadOrStore` 并递增窗口计数；客户端键含 `bind|siteID|host|ip`（phases.go:63-70），dry-run 的 `bind`/`siteID` 为空，因此与线上键不同源，但条目确实进入同一 map 并参与 60 秒清扫。
- **`query_param` 与 `block_body_json_path` 在 dry-run 下无缓存**：`reqCtx` 为 nil 时每次直接 `url.ParseQuery`/`json.Unmarshal`，功能正确但重复解析。
- **建议**：把 `validate` 当语法门、把 `test` 当「仅路径/查询/头/方法/IP/body 可用」的弱信号，真正的生效判定必须走一次真实请求或读快照。

## 结论

验证与测试这两个接口只做「表达式能不能被 core 层理解」，不做「快照会不会带上它」。由此形成三档判定强度：

| 手段 | 能证明 | 不能证明 |
|---|---|---|
| `POST /rules/validate` | 语法与语义合法（57 项） | 是否会被快照执行 |
| `POST /rules/test` | IP/方法/路径/查询/头/体六类匹配逻辑 | TLS、Host、派生头、站点归属、限流计数 |
| 真实请求 + 访问日志 | 端到端生效 | — |

- **成果**：本篇把三处白名单、27 项差集、21 项编辑器越界、6/15 的 dry-run 字段覆盖，以及契约脚本的真实覆盖面全部落到可复核的表格与 `comm` 命令。
- **原则落点**：KISS 要求判定口径只有一处，现实是三处各自维护——这是问题根源；DRY 的正解是让快照复用 `core/rules` 的 `ParsePattern`；SRP 上 `TestRule` 目前同时负责「合成上下文」和「执行匹配」，缺一个可注入的上下文构造边界。本篇按约定**只登记不改码**。
- **风险登记**：57↔30 无自动比对、`validateSimplePattern` 无 `default`、`TestRule` 的「编译为空」分支不可达、`cc_rate` 试运行会写入与线上同参数的共享状态对象、映射器头注释与实际数量不符。
