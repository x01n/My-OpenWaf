## 简介

本篇描述 My-OpenWaf 控制面的**身份认证与权限判定**实现：短期访问令牌（JWT HS256）、长期刷新令牌（HttpOnly Cookie + 服务端摘要存储）、管理端静态令牌（API Key）、活跃会话跟踪、暴力破解防护与三角色 RBAC。

本篇只覆盖鉴权与授权侧的行为与取值。端点条目见[API 端点参考](API 端点参考.md)，载荷字段格式见[请求响应格式规范](请求响应格式规范.md)，中间件在路由链中的位置见[路由设计规范](路由设计规范.md)。

安全前提：所有令牌、口令与密钥在本文档中一律以 `{占位}` 形式出现，不写真实值。

## 详细组件分析

### 访问令牌签发与校验

签发使用 HS256 与主密钥；校验先试主密钥，失败回退备用密钥，从而支持轮换过渡期。校验强制约束签名算法、issuer 与 audience，签名算法非 HMAC 时直接拒绝。

黑名单不可用时认证**保持 fail closed**：`ensureBlacklistReady` 以 1 秒退避重试加载，重试期间返回 `ErrTokenBlacklistUnavailable`，中间件据此返回 `503` 而不是放行。

| 环节 | 实现位置 | 判定 | 失败结果 |
|------|----------|------|----------|
| 算法约束 | `verifyWithKey` | 签名方法必须为 HMAC | `unexpected signing method` |
| issuer/audience | `jwt.WithIssuer`/`WithAudience` | 与常量一致 | 解析错误 |
| 密钥选择 | `VerifyAccessToken` | 主密钥失败再试备用密钥 | 签名无效 |
| 黑名单就绪 | `ensureBlacklistReady` | 已加载或 `db == nil` | `503` |
| 吊销检查 | `IsBlacklisted` | JTI 不在黑名单 | `token has been revoked` |

### 刷新令牌轮换与整链撤销

刷新令牌由 16 字节 JTI 与 32 字节原文组成，服务端只存原文的 SHA-256 摘要。每次刷新执行 `Rotate`：以 `jti = oldJTI AND revoked = false AND expires_at > now` 为条件把旧行置为已撤销并写入 `replaced_by`，同时创建新行；条件不满足即视为已被并发轮换，返回 `ErrRefreshTokenUnavailable`，handler 转为 `401`。

登出与强制下线不撤销单个 JTI，而是 `RevokeFamily` 撤销整条轮换链——浏览器发出登出请求前可能已完成一次刷新，只撤销请求携带的 JTI 会留下可用后继令牌。

### Cookie 属性与往返兼容

刷新 Cookie 名为 `my_openwaf_rt`，值为 `{jti}.{raw}`。分隔符选用点号而非冒号：Hertz 写 Cookie 走 `url.QueryEscape`，读回时不解码，冒号会被写成 `%3A` 而导致刷新恒定报 `malformed refresh token`。旧浏览器仍持有的 `%3A` 形态由兼容分支处理。

| 属性 | 取值 | 依据 |
|------|------|------|
| Name | `my_openwaf_rt` | `refreshCookieName` |
| 值格式 | `{jti}.{raw}` | `refreshCookieSeparator = '.'` |
| Path | `/` | 覆盖含 refresh 在内的全部请求 |
| Max-Age | 604800 秒（7 天） | `auth.RefreshTTL` |
| HttpOnly | 是 | 不暴露给脚本 |
| SameSite | `Lax` | 跨站重定向仍携带 |
| Secure | 由连接协议决定 | `https`/`h3` 为真，回环反代读 `X-Forwarded-Proto` |
| 清除方式 | 同名空值 + Max-Age `-1` | `clearRefreshCookie` |
| 旧格式兼容 | `%3A` 分隔符 | 兼容早于改动的登录会话 |

### 暴力破解防护

计数按两个维度同时记录：纯 IP（全局速率）与 `IP|用户名`（定向爆破）。锁定判定先查 IP 级，再查 IP+用户名级。

`isLockedKey` 必须保持只读：它只在 `RLock` 下执行，若在此处写 `map`，并发读者会触发 `concurrent map writes` 使进程崩溃。已过期锁定记录因此故意留在原地，由下次失败或清理协程回收。

| 参数 | 默认 | 可配置 | 语义 |
|------|:----:|:------:|------|
| `maxFailures` | 5 | 是（`Reconfigure`） | 达到即锁定，非法值回落 5 |
| `lockoutDur` | 15 分钟 | 是（`Reconfigure`） | 锁定时长，非法值回落 15 分钟 |
| 清理周期 | 5 分钟 | 否 | 遍历回收空闲记录 |
| 回收阈值 | `2 × lockoutDur` | 否 | 距最后一次失败超过即删除 |
| `remaining_attempts` 上报 | ≤ 3 时上报 | 否 | 避免精确枚举锁定阈值 |
| 成功登录 | 删除 IP+用户名 记录 | 否 | 不删除纯 IP 记录 |

### 管理端令牌（API Key）

API Key 是 32 字节随机数的十六进制明文，仅在创建响应中出现一次，落库为 bcrypt 哈希与前 8 字符索引前缀。校验走前缀快路径，无前缀的历史令牌回退全表比对；命中即更新 `last_used_at`。

令牌的**身份与权限一律取自所属 `AdminAccount`**，不再无条件赋予 admin 角色；归属账号被删除时该令牌立即失效并返回 `401 api key owner account no longer exists`。

### 前端认证集成

访问令牌存于 `localStorage`（键 `token` 与 `token_expires_at`），跨标签页通过 storage 事件同步；刷新使用 Web Locks 加 localStorage 兜底锁，避免多标签页并发消费一次性刷新令牌。

`apiRequest` 在 `401` 且路径非 `login/refresh/logout` 时进入恢复分支，按四种情形分别处理。

| 情形 | 判定 | 动作 |
|------|------|------|
| 其他标签页已轮换 | 本地令牌已变化 | 直接用新令牌重试，不消费刷新凭据 |
| 刷新成功且令牌一致 | `refresh.ok` | 用新令牌重试一次 |
| 刷新成功但已被替换 | 登出或重新登录发生 | 抛 `ApiError(401, "会话已变更，请重试")` |
| 刷新返回未授权 | `reason = unauthorized` | 清令牌、跳转 `/login`、抛 `ApiError(401)` |
| 刷新服务不可用 | 5xx 或网络失败 | 保留原 `401` 语义并附 `refresh_status: unavailable` |

## 性能考虑

认证热路径不访问数据库：黑名单用 `sync.Map`，会话用受 `RWMutex` 保护的 `map`。写库压力通过两处节流控制——会话活跃时间按 30 秒最小间隔落库，刷新令牌轮换采用就地替换而非追加行，避免每次刷新新增一条会话记录。

过期回收由三个独立周期承担：黑名单 10 分钟、会话 5 分钟、暴力破解记录 5 分钟（回收阈值两倍锁定时长）。`CleanExpired(64)` 在登录与刷新成功后顺带执行，批量上限固定为 64。

首次启动时 `SeedDefaults` 为 `admin` 账号生成 16 字节随机口令并仅在本次输出，不落日志；系统不预置任何 API Key。

## 故障排查指南

| 症状 | 原因 | 排查动作 | 处置 |

## 结论

控制面认证采用"短期 JWT + 一次性轮换刷新令牌 + 归属账号化的 API Key"三轨结构，服务端只保存摘要与哈希，凭据原文除一次性展示外不落任何输出。吊销语义以整链撤销为准，覆盖登出、强退、改密与删号四条路径，避免旧浏览器凭后继刷新令牌恢复会话。

优势：认证热路径无数据库往返；密钥轮换有备用密钥过渡；黑名单不可用时 fail closed，不会静默放过已吊销令牌。

已知边界：会话视图以内存为主、数据库为辅，多实例部署时各实例视图不互通；角色只到分组粒度。二者是当前规模的合理取舍，本篇不做扩展设计。
