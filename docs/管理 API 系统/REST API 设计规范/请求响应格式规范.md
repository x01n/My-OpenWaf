## 简介

本篇定义控制面 REST API 的**载荷契约**：请求参数如何传递与解析、响应如何包装、字段命名与类型约定、分页与排序机制、以及请求体字段的校验规则与失败语义。

## 详细组件分析

### 请求参数传递方式

三类位置各有固定解析入口，解析失败一律返回 `400` 并携带 `error`。

| 位置 | 解析方式 | 失败语义 | 典型端点 |
|------|----------|----------|----------|
| 路径 `:id` | `shared.ParseUintParam` → `strconv.ParseUint(.., 10, 64)` | `400 invalid id` | `/sites/:id` |
| 路径 `:key` | `c.Param("key")` 直接取字符串 | 未命中即 `500`/空值 | `/settings/:key` |
| 路径 `:ip` | 参数值传入升级链状态查询 | 非法 IP 查不到记录 | `/escalation/status/:ip` |
| 查询 `page` | `strconv.Atoi`，缺省按 0 处理再由 `Paginate` 兜底 | 无错误，钳制 | 全部列表端点 |
| 查询 `page_size` | 同上，钳到 `1..200` | 无错误，钳制 | 全部列表端点 |
| 查询过滤项 | `c.Query(name)`，空串视为不过滤 | 无错误，忽略 | `/security-events` |
| 查询时间 | `time.Parse(time.RFC3339, ..)` | 解析失败即忽略该条件 | `since`/`until` |
| 查询枚举 | `securityEventAggregateHours` 严格校验 | `400 hours must be between 1 and 720` | `*/stats`、`*/timeline` |
| 请求体 | `c.BindJSON(&body)` | `400 请求体格式无效` 或 `400 <绑定错误>` | 全部写端点 |
| 请求头 | `c.GetHeader("Authorization")` | `401` | 全部受控端点 |
| Cookie | `c.Cookie("my_openwaf_rt")` | `401 missing refresh token` | `/auth/refresh` |

> [!NOTE]
> 布尔型查询参数以字符串比较实现：`c.Query("all") == "true"`。传 `1` 或 `TRUE` 均不生效。

### 分页机制与排序规则

`Paginate` 只做下界回落与上界钳制，同时防止极大 `page` 造成 `offset` 溢出为负数。

```mermaid
flowchart TD
A["输入 page, page_size"] --> B{"page < 1 ?"}
B --> |是| C["page = 1"]
B --> |否| D["保持原值"]
C --> E{"page_size < 1 ?"}
D --> E
E --> |是| F["page_size = 20"]
E --> |否| G{"page_size > 200 ?"}
G --> |是| H["page_size = 200"]
G --> |否| I["保持原值"]
F --> J{"page-1 > (MaxInt-page_size)/page_size ?"}
H --> J
I --> J
J --> |是| K["page 钳到上界"]
J --> |否| L["保持原值"]
K --> M["offset=(page-1)*page_size, limit=page_size"]
L --> M
```

**分页参数表**

|------|:----:|------|:----:|------|------|------|------|
| `page` | query | int | 否 | `< 1` 回落 1；上界按页长留余量 | `1` | `2` | 页码 |
| `page_size` | query | int | 否 | `1..200`；`< 1` 回落 20 | `20` | `50` | 页长 |

排序约定：仓库层列表以 `id ASC` 为主键序返回；内存切片分页保持上游给定顺序，不做二次排序。

### 字段命名与类型约定

控制面 JSON 键**一律为 snake_case**，由模型 `json` 标签决定，不是驼峰。前端类型定义与标签逐字对齐。

| 类型 | Go 形态 | JSON 形态 | 空值表达 | 实例 |
|------|---------|-----------|----------|------|
| 字符串 | `string` | 字符串 | `""` | `host` |
| 可选字符串 | `*string` | 字符串或省略 | `null` 或字段缺失 | `challenge_action` |
| 布尔 | `bool` | `true`/`false` | 恒有值 | `tls_enabled` |
| 整型 | `int`/`uint` | 数字 | `0` | `priority` |
| 无符号指针 | `*uint` | 数字或 `null` | `null` | `policy_id` |
| 时间（模型） | `time.Time` | RFC3339 字符串 | `"0001-01-01T00:00:00Z"` | `created_at` |
| 时间指针 | `*time.Time` | RFC3339 或省略 | `null` | `last_used_at` |
| 过期时间（令牌） | `time.Time` | **Unix 秒整数** | 恒有值 | 登录响应 `expires_at` |
| JSON blob | `string` | 提交对象/数组，落库为文本 | `""` | `cc_rules` |
| 哈希口令 | `string` | 不出现（`json:"-"`） | — | `password_hash` |

### 三态与继承语义

站点级 nullable 字段遵循同一套语义：不传即保留原值，`null` 即取消覆盖回到继承全局。

| 字段 | Go 形态 | 缺省（不传） | `null` | 空串 | 有效值 |
|------|---------|:------------:|:------:|:----:|:------:|
| `challenge_action` | `*string` | 保留原值 | 置 `nil`（继承） | 视为非法 | 4 个质询动作 |
| `captcha_type` | `*string` | 保留原值 | 置 `nil`（继承） | 视为非法 | 4 个验证码类型 |
| `anti_replay_cookie_mode` | `*string` | 保留原值 | 置 `nil`（继承） | 置 `nil`（继承） | `standard`/`dual` |
| `skip_path_by_phase` | `*string` | 保留原值 | 置 `nil` | 校验失败 | 阶段→路径数组 |

前端必须把这类字段表达为"继承全局 / 覆盖启用 / 覆盖关闭"三态，不得把空值误存为 `false` 或空对象。

## 性能考虑

分页上限 200 与调用侧最多聚合 10 页共同限制单次响应体量；事件与访问日志过滤条件直接下推到 SQL，靠 `id` 主键序返回避免排序开销。统计与时间线端点的聚合窗口被限制在 720 小时内，防止全表扫描。绑定层对 JSON blob 采用"先摘取再解析"，避免结构体绑定失败带来的重试成本。

## 故障排查指南

| 症状 | 原因 | 处置 |
|------|------|------|
| `400 请求体格式无效` | JSON 语法错误或字段类型不符 | 逐字段对照模型标签类型 |
| `400 invalid id` | 路径参数非数字 | 使用 `:id` 的数字主键 |
| `400 invalid pattern` | 模式缺少已知前缀冒号结构 | 按 `kind:arg` 或复合 JSON 书写 |
| `400 hours must be between 1 and 720` | 统计窗口越界或非法 | 落在 `1..720` |
| `400 skip_path_by_phase must be a JSON object` | 提交了数组或字符串 | 改为阶段到路径数组的对象 |
| `400 invalid cc rules` | 含未知字段或多值 JSON | 删除未知字段，仅保留一个数组 |
| `TLS-enabled site requires cert_id` | 开启 TLS 未选证书 | 补 `cert_id` |
| `invalid anti_replay_cookie_mode` | 取值不在 `standard`/`dual` | 改为合法值或 `null` |
| 列表页为空但 `total > 0` | `page` 超界被钳制或切片越界 | 回到第 1 页核对页长 |
| 站点保存后 blob 字段丢失 | 未走 `BindSiteFromRequestBody` | 使用站点专用绑定入口 |
| 覆盖字段被意外清空 | 把"不传"当成"传 null" | 保持不传，取消覆盖才传 `null` |

## 结论

控制面载荷契约的三个特征是：**无信封**（成功形态随资源语义变化，错误固定单层 `error`）、**snake_case 逐字对齐**（模型标签即前端类型，不做大小写转换）、**三态明确**（不传、`null`、有值分别对应保留、继承、覆盖）。校验集中在 `shared` 层完成，使处理器的绑定分支只需报告失败而不重复定义规则。

改进方向：`items`/`total`/`page` 三者目前由各处理器手工拼装，存在返回字段不一致的情况，收敛到一个共享响应结构是低风险的局部改动；本篇不做全库改造。
