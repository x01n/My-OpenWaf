## 核心组件

路由层由四个部分组成：装配入口、中间件链、命名与动作约定、静态回退。

```mermaid
classDiagram
class RegisterRoutes {
+h.Use(SecurityHeaders)
+h.Use(AccessLog)
+注册 8 个根路由
+创建 api / readGroup / opsGroup / adminGroup
+mountStaticHandler(h, StaticFS)
}
class SecurityHeaders {
+固定四头
+/api/v1 前缀加 Cache-Control no-store
+快照驱动 XSS/HSTS/HPKP 头
}
class AccessLog {
+生成 X-Request-ID
+记录 method/path/status/latency/auth
}
class AuthMiddleware {
+白名单放行
+JWT 优先、API Key 回退
+写入 auth_role / auth_jti
}
class RequireRole {
+角色白名单集合判定
+不满足 403 并 Abort
}
class NoRoute {
+/api/ 前缀返回 404 JSON
+其余交给 serveStaticFile
}
RegisterRoutes --> SecurityHeaders
RegisterRoutes --> AccessLog
RegisterRoutes --> AuthMiddleware
RegisterRoutes --> RequireRole
RegisterRoutes --> NoRoute
```

### 资源命名约定与路径设计原则

| 模式 | 语义 | 实例 |
|------|------|------|

### HTTP 方法使用规范

| 方法 | 用途 | 状态码 | 实测条目 |
|:----:|------|:------:|:--------:|
| GET | 列表、详情、统计、时间线、状态、导出 | 200 | 100 |
| POST | 新建 | 201 | 见各资源表 |
| POST | 更新（`/update`）、删除（`/delete`） | 200 / 204 | 见各资源表 |
| POST | 状态动作与运维动作 | 200 | 见各资源表 |
| PUT | 未使用 | — | 0 |
| DELETE | 未使用 | — | 0 |

不注册 PUT/DELETE 的直接后果：任何按 REST 惯例发起的 `PUT`/`DELETE` 请求都会走到 `NoRoute`，`/api/` 前缀下返回 `404` 而不是 `405`。调用侧必须按 POST 动作后缀书写。

```json
{
  "error": "endpoint not found"
}
```

### 路由注册机制

注册顺序遵循"全局中间件 → 公开端点 → 认证端点 → 分组 → 分组内公开端点 → 静态回退"。

1. `h.Use(SecurityHeaders)`、`h.Use(AccessLog)`：全局生效，先于任何路由匹配。
2. `h.GET("/api/v1/health", ...)`：在鉴权分组创建之前注册，因此不受 `AuthMiddleware` 影响。
3. 三个认证写端点同样注册在实例根上，配合中间件白名单实现免鉴权。
4. `api := h.Group("/api/v1")` + `api.Use(AuthMiddleware(...))`：此后所有子分组自动继承鉴权。
5. 三个权限子组用空前缀创建，只追加各自的角色中间件。
6. `adminGroup` 内仍可注册 GET（`backup/export`、`certificates/acme/status`），分组语义是"角色要求"而非"写操作"。
7. 实例根还承载 `realtime/ws` 与两个 `__owaf` 资产端点，均在鉴权分组之外。
8. 最后调用 `mountStaticHandler` 注册 `NoRoute`。

### 静态文件处理与 SPA 回退

`mountStaticHandler` 先解析资源来源：`StaticFS` 非空则读磁盘目录，否则使用内嵌产物树；解析失败时**直接返回**，即不注册 `NoRoute`，此时所有未命中路由由 Hertz 默认行为处理。

`routeCandidates` 的候选生成顺序决定回退质量：

| 步 | 候选形态 | 适用场景 |
|:--:|----------|----------|
| 1 | 原始路径本身 | 精确静态资源 |
| 2 | Next.js RSC 变体（`__next.*.txt` 还原） | 客户端导航数据 |
| 3 | 动态路由段替换为 `_` | 导出期占位段 |
| 4 | 以 `/` 结尾时补 `xxx/index.html` | 目录式路由 |
| 5 | 无扩展名时补 `xxx/index.html` 与 `xxx.html` | 页面路由 |
| 6 | 全无扩展名兜底 `index.html` | SPA 深链 |

命中后由 `ContentType` 按扩展名映射响应类型；未命中返回纯文本 `not found` 与 `404`。

| 情形 | 状态码 | `Content-Type` | 响应体 |
|------|:------:|----------------|--------|
| `/api/` 前缀未命中 | 404 | `application/json` | `{"error":"endpoint not found"}` |
| 静态资源命中 | 200 | 按扩展名映射 | 文件字节 |
| `.html` | 200 | `text/html; charset=utf-8` | 页面 |
| `.js` | 200 | `application/javascript` | 脚本 |
| `.css` / `.json` / `.svg` / `.png` / `.ico` / `.woff2` | 200 | 各自类型 | 资源 |
| 未知扩展名 | 200 | `application/octet-stream` | 原样字节 |
| 全部候选未命中 | 404 | 无（纯文本） | `not found` |

### 路由安全约束

安全头由全局中间件统一注入，路由层不再逐端点设置；`/api/v1/` 前缀的响应无论成功失败都禁缓存，避免策略、日志与账号元数据被浏览器或中间代理复用。

| 约束 | 实现 | 覆盖范围 |
|------|------|----------|
| `X-Content-Type-Options: nosniff` | `SecurityHeaders` | 全部响应 |
| `X-Frame-Options: DENY` | `SecurityHeaders` | 全部响应 |
| `Referrer-Policy: strict-origin-when-cross-origin` | `SecurityHeaders` | 全部响应 |
| `Content-Security-Policy`（含 `unsafe-inline`） | `SecurityHeaders` | 全部响应 |
| `Cache-Control: no-store` | 路径前缀判定 + 认证 handler 各自写入 | `/api/v1/` |
| `X-Request-ID` | `AccessLog` 生成 UUID | 全部响应 |
| `Strict-Transport-Security` | 快照开关 + 协议为 `https`/`h3` | 条件注入 |
| `X-XSS-Protection`、HPKP 两态 | 快照开关 | 条件注入 |
| 鉴权白名单 | 四个路径精确匹配 | `health` 与三个 `auth` 写端点 |

## 性能考虑

路由为纯静态注册，无运行时构建开销；分组共享中间件实例，避免逐端点重复构造角色集合。`RequireRole` 在构造期把角色变长参数预转成 `map[string]bool`，判定为常数时间。

`NoRoute` 回退对每个未命中请求做多次 `fs.ReadFile` 尝试，候选数量随路径段数增长；把明确属于 API 的未命中提前短路（`/api/` 前缀判定）可避免无谓的文件系统探测。

## 结论

控制面路由的可预测性来自三条硬规则：**所有端点集中注册**、**权限只由分组决定**、**只用 GET/POST 两种方法**。由此带来的收益是新增端点无需考虑中间件装配与 CORS 方法预检；代价是更新与删除必须以后缀形式表达，且调用方容易因套用 REST 惯例而拿到 `404` 而非 `405`。

静态段与参数段的优先级冲突由注释与命名测试锁定，属于必须持续维护的约定：任何新增 `stats`/`requests`/`default` 类端点都应与同层 `:id` 端点一起核对。
